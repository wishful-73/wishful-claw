# S-154 终端「常驻」会话结束后自动关闭对应选项卡

- **登记日期**：2026-09-28
- **登记来源**：老大 2026-09-28 13:53「我们不是有终端常驻的工具了么，目前关掉的时候没有顺便关掉选项卡，导致用户看到的是一堆已经无效的选项卡，这个需要**顺便把选项卡一起关掉**」
- **分支**：`dev/v2-iter-36`
- **状态**：📝 已登记，待实施

---

## 一、现象

Agent 通过 Terminal 工具起的终端，进程结束后：**底部终端停靠栏里的选项卡还在**，只是状态点变成「已退出 / 出错」。跑得多了，用户看到的是一排点了没反应的死选项卡。

---

## 二、机制实证（代码事实，2026-09-28 复勘）

### 2.1 生命周期链路

| 环节 | 位置 | 行为 |
|---|---|---|
| agent 起终端 | `src/main/ipc/terminal-handlers.ts:420-500` | 建 PTY（`term-<uuid>`），命令**打进 shell 的提示符**（不是启动行），带 `sessionId` / `projectId` |
| PTY 退出 | 同上 `:450-462` | `pty.onExit` → `createWindowEvent(..., 'terminal:exit', { id, exitCode, signal })` |
| 渲染端收退出 | `src/renderer/src/stores/terminal-store.ts:281-296` | `_onExit` **只改 `status`**（`exited` / `error`）—— **tab 不删** ← **就是这条** |
| 渲染端建 tab | 同上 `:214-260` | `TERMINAL_CREATED` 事件 → `kind: 'local-agent'`；若正是当前会话且停靠栏没开，顺带把停靠栏打开并选中它 |
| 用户手动关 tab | 同上 `:155-176` | `closeTab()` → 发 `terminal:kill` → 从 `tabs` 移除 + 重挑 `activeTabId` |

### 2.2 关键事实

1. **tab 有三种来源**（`TerminalTabKind`，`:11`）：`local`（用户自己开的）、`local-agent`（agent 起的）、`ssh-agent`（SSH 会话观察窗）。**只有 `local-agent` 是「用完即弃」的** —— 用户自己开的和 SSH 观察窗都可能是他要留着看输出的。
2. **没有「常驻终端」以外的长生逻辑** —— 老大的「终端常驻」指的就是 Terminal 工具的 PTY 跨多次调用复用；PTY 一死，那个 tab 就没有存在意义了。
3. **`closeTab()` 是唯一会发 `terminal:kill` 的入口**（S-134 已裁定：切会话 / 结束会话都不杀 PTY）。本条**不碰**这条规矩 —— 退出事件是**结果**，不是我们主动去杀。
4. **陷阱：空停靠栏会自动新建终端** —— `BottomTerminalDock.tsx:118-133`：`dockOpen && sessionTabs.length === 0` 时 `handleAutoCreateTerminal()` 会**自动创建一个本地终端**。⇒ 若只删 tab 不收停靠栏，用户会看到「死 tab 消失 → 冒出一个全新空白终端」，反而更糟。**所以删最后一个 tab 时要把该会话的停靠栏一并收起。**

---

## 三、改法

### 3.1 行为定稿

| 场景 | 行为 |
|---|---|
| `local-agent` tab 收到 `terminal:exit` | **直接移除 tab** |
| 移除后该 `sessionId` 已无任何 tab，且停靠栏开着 | **收起该会话的停靠栏**（挡 2.2 第 4 条那个自动新建） |
| `local` tab 退出 | 维持现状（留 tab、状态转 `exited` / `error`） |
| `ssh-agent` tab | 不参与 —— 它不接 `terminal:exit`（`closeTab` 也跳过 kill） |

**为什么不做延迟关闭**：老大要的是「顺便一起关掉」。延迟窗（比如留 3 秒让用户看一眼尾巴输出）会引入一个新的状态与计时器，而 agent 终端的输出在工具结果里本来也有；**不做**。

### 3.2 落点

抽一个**零依赖纯函数模块** `src/renderer/src/stores/terminal-tab-lifecycle.ts`（沿用 `scroll-collapse-gate` 的做法：renderer 与回归套件跑同一份代码）：

- `AUTO_CLOSE_ON_EXIT_KINDS: ReadonlySet<TerminalTabKind>` = `{ 'local-agent' }`
- `shouldCloseTabOnExit(kind)` —— 判据单独成函数，将来要放开关只改这里
- `removeTabAndPickActive(tabs, id, activeTabId)` —— 抽自 `closeTab` 现有那段（`tabs.filter` + 末尾兜底），让「删 tab 后选谁」只有一份实现；`closeTab` 改调它
- `countTabsForSession(tabs, sessionId)` —— 判「该会话是否已无 tab」

`terminal-store.ts` 的改点：
1. `closeTab` 内联的 filter/重挑 → 改调 `removeTabAndPickActive`
2. `_onExit` 内：目标 tab 是 `local-agent` ⇒ 走删除路径 + 按需收起停靠栏；否则维持现有「只改状态」
3. `TerminalTabKind` 类型移至新模块并由 store 再导出（对外导入路径不变）

## 四、边界（如实说）

- **输出会立刻消失**：agent 终端被 stop 的瞬间 tab 就没了，用户若正盯着那屏输出，会看到它直接消失。这是「一起关掉」的固有代价；工具结果里仍有完整输出，故不额外做「保留 N 秒」。
- **只治 `local-agent`**：用户自己开的 tab 仍是「退出后留着一排 `exited` 状态」的现状。若老大之后也想收，改 `AUTO_CLOSE_ON_EXIT_KINDS` 一处即可。
- **不碰 S-134 的裁定**：切会话 / 结束会话依然不杀 PTY；本条只在**进程真的退出之后**清理 UI。

---

## 五、遗留观察

- 若 agent 终端因**自然原因**退出（例如 agent 打了 `exit`），同样会关 tab —— 符合「死了就没意义」的口径。
- 停靠栏「收起」用 `ui-store` 现成的 `setBottomTerminalDockOpen(sessionId, false)`（`ui-store.ts:323-324`）。
