# S-134 · 常驻终端：agent 可起、可读、可停的可见进程（落在底部终端面板）

- 2026-09-22：**老大提出**（缘起本迭代「shell 命令执行 / 常驻终端」讨论），同日拍定三条口径。

**动机（这是缺口，不是锦上添花）**：现有 `Bash`（`ShellExecuteTool`）是「一次性跑完 → 拿 stdout/stderr/exitCode → 收回显示」。agent 要跑 `npm run dev` / 文件 watch / 长任务时只剩三条烂路：超时被掐（默认 10 min）、输出挤在工具结果里看不见、进程起在无人知晓的地方收不回来。

**口径（老大 2026-09-22 拍板）**：

| # | 事项 | 裁定 |
|:--:|---|---|
| 1 | 进程生命周期 | **关 tab = kill；退出应用 = kill；切会话 / 会话结束但 tab 还开着 = 不动**（用户是唯一收尾人） |
| 2 | 能力面 | **读 + 停都要**（原话「最好能读也能停」） |
| 3 | SSH 项目 | **保持原样** —— 不动现有 SSH 链路，本工具不提供远程执行 |

**结论先行：这是「接线」不是「造轮子」** —— 五件现成件把主体工作兜住了（每条都已读码核实）：

| 现成件 | 位置 | 作用 |
|---|---|---|
| 真 node-pty 会话 | `src/main/ipc/terminal-handlers.ts:299` `createTerminalSession` | 已含 64 KB 环形 buffer、`waitForInitialOutput`（120 ms）、`MAX_ACTIVE_SESSIONS = 32`、shell 候选链、cwd 兜底 |
| 事件广播 | `terminal-handlers.ts:379` `terminal:created` | **通道已存在，渲染端目前无人监听** ⇒ 加监听即可建 tab |

| 反向请求链路 | C# `AgentRuntimeSshToolExecutor` → `src/main/ipc/reverse-handlers/index.ts`（`ssh:exec`） | 现成模板 |
| 会话级 tab 归属 | `BottomTerminalDock.tsx:80` 按 `sessionId` 过滤；`terminal-store.ts:167` `ensureSshAgentTab` | tab 必须带 `sessionId`，「每会话一个 agent tab」的先例 |

**设计（我的推荐，老大可在规划确认时否掉）**：

- 工具名 **`Terminal`**，单工具三动作 `action: start | read | stop`（一个工具管一个资源，省 schema 且语义集中）。
- 参数：`action`（必填 enum）、`command`（start 必填）、`terminalId`（read/stop 必填）、`cwd` / `shell` / `env` / `title`（可选）。
- 返回：start ⇒ `{ terminalId, status, tail }`（**起完等首次输出**，让 agent 知道起没起来）；read ⇒ 尾部纯文本；stop ⇒ `{ status: 'stopped' }`。
- 可见性：`visibleScopes: HumanAttended` + `excludedScopes: NoHumanToAnswer`（**照 `WidgetToolProvider.cs:38-39` 的先例**）⇒ 聊天 / 协作可见，**子代理 / 后台自动化 / 频道会话不可见** —— 底部终端是「有人看着的共享面板」，没人看时起了也没人收。
- 审批：**必须进 `ShellApprovalTools`**（`ToolCallProcessor.Approval.cs:35`）。不接审批就是绕过审批的后门，这条不算「后续优化」。
- SSH 绑定项目：**不做远程**（口径 3）。工具描述写明「始终本地」，`ShouldRouteToSsh` 的任何分支都不动。
- 与 `Bash` 的分工写进工具描述：**一次性、要输出、要 exitCode ⇒ `Bash`；常驻、要看、要停 ⇒ `Terminal`**。

**已知的坑（必须在计划里处理，不留到实施时才发现）**：

1. **会话归属要传下去** —— `CreateTerminalSessionArgs` / `TerminalSession` / `TerminalSessionListEntry` 都没有 `sessionId` / `projectId`；C# 反向请求必须把 `state.Parameters.sessionId` 带上、`toSessionRecord` 透传，否则渲染端建出的 tab 会被 `tab.sessionId === sessionId` 的过滤条件挡掉，**起了但看不见**。
2. **读输出必须剥 ANSI** —— main 的 buffer 存的是裸 PTY 字节流（含转义序列与 `\r`）。直接回给模型会污染上下文，得在 main 侧转纯文本再截尾。
3. **执行环境是两套语义** —— `Bash` 在 C# 里跑（自己注入 `PYTHONUTF8` / `LANG`、走自己的 shell 候选链），`Terminal` 在 main 里跑（`process.env` + 设置页的终端 shell）。同一命令两边环境可能不同 ⇒ 工具描述要讲清楚，别让模型以为等价。
4. **关 tab 的清理路径** —— `closeTab` 只对 `kind !== 'ssh-agent'` 发 `TERMINAL_KILL`（`terminal-store.ts:145`）。新 tab kind 必须落在这个「真终端」一侧；若被误实现成 ssh-agent 那种只读观察 tab，就会出现**关掉 tab 进程还在**。

**独立性**：不依赖本迭代其它需求，可独立实施、独立成刀。

## 验收修正（2026-09-22，**未提交**，归收尾刀）

老大真机跑通常驻终端后报两条：**没有 `PS D:\claw\wishful-claw>` 那样的第一行**、**Ctrl+C 的观感跟常规终端不一样**。查出同一根因，顺带把读停链路上两个隐患一并修掉。

**根因**：`terminal-handlers.ts` 的 `getLaunchArgs` 在带 `command` 时走 `powershell -NoLogo -NoProfile -Command <cmd>`。`-Command` 下 PowerShell 是**非交互**的 ⇒ 不打印提示符、不回显命令、跳过 profile，且 **Ctrl+C 终止整个 shell**（而不是取消当前行回到提示符）。用户自己开的 tab 不带 command ⇒ `['-NoLogo']` 交互式 —— 两者自然不像。

**改法（四条）**：

1. **命令改为注入交互式 shell** —— `getLaunchArgs` 去掉 command 分支，一律启交互式 shell；`createTerminalSession` 在首输出之后延时 `COMMAND_SUBMIT_DELAY_MS = 250`（等 PSReadLine 到提示符，否则首字符会被吞）再 `pty.write(command + '\r')`，再等 `COMMAND_ECHO_WAIT_MS = 150` 让回显进 buffer。agent 的 tab 从此与用户手开的 tab 是**同一个东西**：提示符、命令回显、profile、历史、Ctrl+C 取消当前行。
2. **`read` 改增量** —— `TerminalSession` 加 `lastReadSeq` 游标；新增 `readTerminalOutput()` 只回 `seq > 游标` 的新文本并推进游标，`start` 的 `tail` 也走它（`createTerminalSession` 不再自己推进）⇒ **第一次 read 不重放启动输出**。无新输出时回 `note: 'No new output since the previous read.'`，不让空串被读成坏掉。
3. **Ctrl+C 标记修 start 去重** —— `writeTerminalSession` 检测 `\x03` 置 `session.interrupted`（任何其它按键清除），`TerminalSessionListEntry` 透出。`handleTerminalStart` 的去重分两支：**未被中断** ⇒ 照旧 attach；**被中断** ⇒ `submitTerminalCommand()` 把命令重新敲进同一个 shell（同 tab、新一次运行），`note` 说明原因。**不引入 `idle` 之类的新 status 值** —— 命令是否在跑由增量文本自证（`^C` + 新提示符），另造一个状态源只能是猜。

4. **起终端即打开该会话的底部终端面板** —— 原口径是「建 tab 但不动屏幕」，老大真机反馈「启动终端没有默认打开底部终端面板」⇒ 反转为：`_onCreated` 加完 tab 之后，若终端属于**当前活跃会话**且该会话面板**尚未打开**，则打开面板并把新 tab 设为激活。两条克制规则保留：非当前会话不动（后台 run 的终端不该改用户视野）、面板已打开时不改选中 tab（用户正看自己选的终端，新 tab 在 tab 栏上以翠绿图标可见）。`BottomTerminalDock` 的 auto-create effect 不受影响 —— tab 先入 store，`sessionTabs.length` 已为 1，不会再自动建一个普通终端。

**代价（老大已点头）**：交互式 shell 下命令跑完 shell 仍在，**短命令不再回 `exitCode`**。这正是工具契约本意（描述早已写明「要 exitCode 用 Bash」），`Terminal` 只管常驻进程。

**C# 侧**：`AgentRuntimeTerminalExecutor` 的 `note` 改为透传 main 的文案（「attach 到在跑的」与「中断后重新敲入」是两种 reused，文案归 main 所有）；`TerminalToolProvider` 描述补两段（命令敲进交互式 shell / read 返回自上次以来新增）。

**测试**：`TerminalTool` 断言 26 → **27**（加一条「描述声明 read 只回新增」——JSON 形状看不出增量与全量的区别，描述是模型唯一的信息来源）。门禁：`typecheck` EXIT=0；`npm test` **47/47**；两 sln 0 错 0 警。

**覆盖不到的部分**：增量游标 / 中断标记 / 命令注入全部长在 `terminal-handlers.ts`（Electron + node-pty 依赖），现有 TS 套件跑不了这个模块 ⇒ 这三条没有自动化测试，只能真机验。
