## 四、门禁零污染（2026-09-21 已核证）

放根级 `website/` 后，现有链路**一条都不用改**：

| 链路 | 现状 | 是否扫到 `website/` |
|---|---|---|

### 本地开发的端口（2026-09-22 改定）

官网**用固定端口**，写在 `website/vite.config.ts` 里并开 `strictPort`：

| 命令（在 `website/` 下） | 端口 | 用途 |
|---|---|---|
| `npm run dev` | **5280** | 开发服务器（HMR） |
| `npm run preview` | **5281** | 预览 `dist` 产物 |

**为什么偏离 Vite 默认的 5173 / 4173**：主项目 electron-vite 的 renderer dev / preview 正占着这两个默认值。同机同开时 Vite 会**静默 +1**（官网挪到 5174），结果是「打开 5280 测官网」实际看的是主项目 —— 端口没错、命令没错，测错了对象。`strictPort` 让端口被占时**直接报错退出**，不偷偷换端口（要求 preview 端口时同理，不用再手敲 `--port`）。

> 历史文档里的 `localhost:5173`（S-121 验证）、`localhost:5298`（S-127 实测）是**当时**的地址，属实施记录，保留不改。

### 干净路由（`/guide` 而不是 `/guide.html`）

2026-09-21 老大裁定：地址栏不想看到 `.html`，锚点走 `/guide#models` 这种形式。

- **产物文件名不变**（仍是 `dist/guide.html`），改的是访问形态：`vite.config.ts` 里一个 `clean-urls` 中间件把 `/guide` 重写到 `/guide.html`，dev 与 preview 都挂；内部链接全部改成相对无后缀（`./guide`、`./download`、`./`、`./#faq`）。
- **只支持无斜杠**：`base: './'` 下产物 HTML 的资源是相对路径，浏览器停在 `/guide/` 时会把 `./assets/...` 解析成 `/guide/assets/...` 直接 404。所以 `/guide/` 与未知路径一律 404（`appType: 'mpa'`，默认 `'spa'` 会把首页塞给任何错路径，打错 `/guid` 看着像 200）。
- **上线时 Nginx 必须补一行**，否则线上 `/guide` 会 404（本地 dev/preview 的重写只活在 Vite 里）：
  `try_files $uri $uri.html $uri/ =404;`
  换托管商同理：Netlify 自动 clean URLs；GitHub Pages 的 Jekyll 构建也吃 `/guide`。选纯静态对象存储（COS 静态站）时**不支持**这种映射，届时要改成 `guide/index.html` 的目录形态或加回 `.html` —— 属阶段 4 的决策点。

## 附录：下载源设计结论（推迟实施，备查）

**问题**：GitHub Releases 国内不稳 —— 这**同时**是官网下载页的病（官网方案 L270）**和** app 内更新链路的病（S-111：巡检失败只落日志、打包时 electron-builder 拉二进制超时）。

**结论**：**一个源，两个消费方**。

```
腾讯云 COS（免备案，约 0.5 元/GB 外网下行）
├── wishful-claw-0.2.N-setup.exe     ← 官网下载页点这里
├── latest.yml                       ← app 内更新（electron-updater）读这里
└── latest.json                      ← 官网下载页读这里（由 latest.yml 派生）
```

- `latest.yml` 由 electron-builder **已经产出**，字段（`version` / `path` / `sha512` / `size` / `files[].url`）正好是官网下载页需要的全部信息 ⇒ 发版脚本**顺手转换**即可，不用新写数据源。
- 官网页面**运行时读 `latest.json`**（而非构建时注入）⇒ 发版**零官网构建**，正合官网方案「下载页独立、便于只改一处」的初衷。
- 发布流程插入点：`docs/release-workflow.md` 4.3「上传资产」之后加一节「同步下载源」，**现有步骤一个不动**。
- 遗留决策（届时拍）：COS 上线后 GitHub Release 那段**是否保留**（海外兜底 or 只留 COS）。

**启动条件**：老大 2026-09-21 指定 —— **等官网备案过后再调整**。
