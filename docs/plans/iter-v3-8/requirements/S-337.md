### 5.1 落地形状

| 方法 | 顶替的调用点 | 备注 |
|---|---|---|
| `CountByProject(db, projectId)` | `ProjectExecutor.cs:85` | N+1 不动 |
| `CountActiveByProject(db, projectId, cutoffMs)` | `ProjectExecutor.cs:89` | 时间窗口由调用方算 |
| `ListRecentByProject(db, projectId, limit = 20)` | `ProjectExecutor.cs:133` | `LIMIT` 用绑定参数 |

### 5.2 关键：`sessions` 有**两份 INSERT，列集不同，绝不能合并**

| | `DbSessionTools.Create`（端点） | `InsertProjectSession`（本单） |
|---|---|---|
| 列数 | **24 列全量** | **12 列子集** |
| `collaboration_mode` / `permission_mode` | 从入参写入 | **留 NULL**，由 `rowToSession` 回填（S-189） |
| `message_count` / `pinned` | `message_count` 绑参、`pinned` 绑参 | **字面量 0** |
| 谁在用 | 渲染端建会话 | 项目执行器旁路直插（agent 内部） |

把 12 列合并进 24 列，会顺手把 `collab` / `permission` 从 NULL 变成某个具体值 —— 那正是 S-189 要避免的：worker 读不到渲染端的用户设置，写死等于用错的值覆盖正确值。

**反过来合并（24 → 12）更糟**：端点建会话会丢掉 `icon` / `context_cap_*` / `threshold` / `provider` / `model` / `persona`。

所以 Store 里这个方法名字叫 `InsertProjectSession`（点明「给项目执行器用」），注释里写死「和 `DbSessionTools.Create` 不是同一件事，别合并」。

### 5.3 S-115 / S-189 两段注释整段搬进 Store

`:233-236` 原文两段（`model_selection_mode` NOT NULL 无默认值会撞约束 / `collab`+`permission` 留 NULL 由 `rowToSession` 回填）**整段搬进了 `InsertProjectSession` 的 XML 注释**，调用点只留一行：

```csharp
// S-115 / S-189 两条约束的说明随 SQL 搬进了 DbSessionStore.InsertProjectSession。
DbSessionStore.InsertProjectSession(db, entity);
```

§二 那条要求是硬的：漏了这段，下一个人两个月后会再踩一次 NOT NULL 约束。留在调用点则成了「注释指着不存在的东西」，所以跟着 SQL 走。

### 5.4 `ListRecentByProject` 用 `SELECT *` —— 与本族其他 Store 相反，理由在列数

`DbPlanStore` / `DbTaskStore` / `DbProjectStore` 都写显式列，这里没写：

| | 列数 | 写法 | 理由 |
|---|---:|---|---|
| `plans` | 9 | 显式列 | 可控，加列时「漏改」本身是信号 |
| `tasks` | 14 | 显式列 | 同上 |
| `projects` | 8 | 显式列 | 同上 |
| **`sessions`** | **29** | **`SELECT *`** | `EntityMappers.MapSession` **按列名**读（`GetOrdinal`），`SELECT *` 不存在错位风险；写 29 个列名，实体每加一个字段要同步一处，漏了才是真炸 |

§二 原本要求「显式列全字段，理由同 S-333」。**照做反而制造同步负担** —— 这条按实测改了，不是偷懒。差别写进了方法注释，避免下一个人以为「这里漏了」。

### 5.5 两个「顺手」都被按住了

| 看着该改 | 实际没改 | 原因 |
|---|---|---|
| `message_count = 0` / `pinned = 0` 改成绑定参数 | 保留字面量 | 那是语义变更（S-328 §四） |
| `@cutoff` 的 `now - 3600000` 挪进 Db 层 | 留在调用点算，方法只收 `cutoffMs` | 把「活跃」的定义埋进基础设施层，改口径就得改 Db 层 |

另有一处**不算顺手、是必须**的：`LIMIT 20` 改成了 `LIMIT @limit` 绑定参数。SQLite 支持在 `LIMIT` 上用参数，这样 `limit = 20` 这个默认值只存在于方法签名一处，不再散在 SQL 与调用点。
