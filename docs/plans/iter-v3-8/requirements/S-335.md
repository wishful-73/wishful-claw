## 二、为什么它排第一

1. **一屏看完** —— 121 行、主键只有一个 `tool_use_id`（不是自增 `id`）、没有事务、没有 join。
2. **样板必须在一个地方定死** —— 后面 S-328 / S-333 / S-334 / S-337 / S-338 五个编号都照它写。反过来先做大的，样板会在五份代码里长出五样，最后统一回去比现在做还贵。
3. **语义最单纯** —— `data` 是一整块 JSON 文本（子 agent 报告快照），读进来解析、写回去原样字符串，没有字段级映射。

## 三、风险

| 风险 | 处置 |
|---|---|
| 主键是 `tool_use_id`，不是 `id` | 强类型方法名要写明（`ReadByToolUseId` / `UpsertByToolUseId`）。叫 `Get(string id)` 会让下一个人以为是 `id` 列 |

## 六、实施记录（2026-11-06 09:2x，commit `0938f296`）

### 6.1 命名与形状：照 `DbCompactionSnapshotStore`

开工时先找先例，`Infrastructure/Db/` 下已经有一个**纯表访问**类 —— `DbCompactionSnapshotStore`(277 行)。约定定了，后面五刀照抄：

```
public static class Db<主体>Store          // 不带 Tools 后缀 —— Tools 是端点
    public static XxxEntity? Get...(DbService db, ...)   // 首参 DbService，进出强类型
    public static void Insert(DbService db, XxxEntity e)
    public static int  Update...(DbService db, ...)      // 返回受影响行数
```

不碰 `JsonElement`、不碰 `WorkerResponse`、不 try/catch（异常由调用方按各自策略处理）。

### 6.2 又一个「零件在、没接线」

`DbSubAgentTools.InsertSubAgentRun(DbService, SubAgentRunEntity)` **早就是强类型形状了**，只是 `internal` 且被埋在端点类里。这直接印证 S-328 §二 的结论：缺的从来不是能力，是那层封装。

处置：实现搬到 `DbSubAgentRunStore.Insert`，`InsertSubAgentRun` 保留为一行转调 —— 端点内部还有其他调用点，直接删会扩大半径；但**同一份 INSERT SQL 只能留一处**，所以它里面不许再有 SQL。

### 6.3 最关键的一处：`null` 到底表示什么

原代码：

```csharp
var existingData = db.QueryScalar<string?>(
    "SELECT data FROM sub_agent_runs WHERE tool_use_id = @id", …);
if (existingData is null) { /* INSERT */ } else { /* UPDATE data */ }
```

改成返回实体后，这个判断必须**逐个对齐**：

| DDL 事实（`DbClient.Schema:99-107`） | 含义 |
|---|---|
| `data TEXT NOT NULL DEFAULT ''` | 行存在 ⇒ data 一定非 NULL，最少是 `''` |
| `tool_use_id TEXT PRIMARY KEY NOT NULL` | 查不到就只有一种可能：行不存在 |

⇒ `existing is null` 严格等价于原来的 `existingData is null`，两种实现在「行在但 data 是空串」时都走 UPDATE（正确）。

**如果按直觉写成 `existing?.Data is null`**，行在但 data 是 `''` 时也会走 INSERT → 主键冲突 → 抛异常 → 被 catch 记日志 → **报告写丢且不报错**。这就是为什么 `null` 的语义必须在 Store 的类型注释里写死。

同理 `UpdateData` 返回受影响行数并注释「0 表示行不存在」：调用方若拿它当「更新成功」，同样是静默丢数据。

### 6.4 业务默认值留在调用点

`session_id ?? "_unknown"`、`StartedAt = completedAt`（报告落库时没有真实开始时间，拿完成时间顶上）、`success ? 1 : 0` —— 这些都是**业务约定**，不进 Store。Store 只负责「把实体写进表」，不做默认值填充。

`MergeFinalOutput`（读-改-写合并 JSON）也整个留在 Agent 层：它是业务逻辑，不是表访问。
