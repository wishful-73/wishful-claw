## 一、现象

对外描述**四平八稳、像产品说明书**，缺吸引力：读完知道「它能做什么」，但不产生「我想装一个试试」的冲动。

**具体表现**（现文案，逐处摘录）：

| 位置 | 现文案 | 问题 |
|---|---|---|
| 官网 Hero 主标题 | `你说一句，它去把活干完` | 准确、但平；无反差、无情绪 |
| 官网 Hero 副标题 | `跑在你自己电脑上的智能助手：读写文件、执行命令、操作浏览器和桌面软件。不花钱就能开始……` | **功能罗列式**，一句话塞四个动词 |
| README 首屏 `<strong>` | `桌面 AI Agent 工作台 — 有记忆、有人格、能动手` | 规格化描述，无记忆点 |
| 官网「为什么是它」quote | `不是聊天玩具，是真能干活的 Agent。` / `订阅购买，点一下就到了。` / `不用解释，看一眼就知道。` | 前两条偏辩解，第三条偏空 |
| 官网 features `desc` | `在你电脑上读写文件、跑命令、改代码，不是只会在对话框里聊天` | 以「不是什么」立论，弱 |
| README 结尾 | `自用项目，慢慢打磨。` | 与「邀请人用」的意图相反 |

## 二、目标

**把「说明书口吻」改成「有钩子的口吻」** —— 在**红线不破**（见 §四 裁定 2）且**不越合规边界**（裁定 3）的前提下，重写叙述方式，让首屏读起来有吸引力。**改的是「怎么讲」，不是「讲什么」**：事实、能力清单、受众定位一律不动。

具体要达到：

1. **首屏一句话能被记住** —— 官网 Hero 与 README 首屏是唯二的「第一印象面」，必须重写。
2. **卖点前移、形容词后退** —— 少罗列功能动词，多讲「你会因此少干什么」。
3. **口径一致** —— 官网与 README 描述同一件事时用同一套说法，不各说各的。

## 三、范围

| 导出 | 字段 | 说明 |

| `advantages` | 各组 `items[].name` / `quote` / `body` | 「为什么是它」 |
| `valueLadder` | `title` / `note` / `tiers[].name` / `detail` | 「不花钱也能用起来」 |

**顺带一处硬约束**：`BRAND` 改动会牵动 4 行静态投影（`index.html` / `download.html` 的 `title` 与 `description`，见 `site.ts:3-5` 注释）。**本需求不动 `BRAND`**（品牌名与备案全称是合规面，见 §六）。

### 3.2 README（仓库根 `README.md`）

需同步的段落：

- 首屏 `<strong>` 定位句（`:4`）
- 首屏简介行（`:5`）
- 各节标题与开场句（`🚀 快速上手` / `✨ 它能为你做什么` 各子节 / `💾 数据与隐私` / `❓ 常见问题` / 结尾 `自用项目，慢慢打磨。`）

## 四、裁定结果（老大 2026-10-15 09:53）

> 老大原话：**「红线不破，只是需要改我们的叙述，变得更有诱惑力一点」**

| # | 决策点 | 裁定 | 落点 |
|---|---|---|---|
| 1 | **标题党的「度」** | **「变得更有诱惑力一点」** —— 介于 A 与 B 之间：**换叙述方式、加钩子**，但**不上 C 档**（不搞悬念式标题、不夸张失真） | 重写句式与立意，不堆形容词 |
| 2 | **是否突破既有红线** | **不破。** `site.ts:46-48` 的两条原样有效 —— ①**「不写成程序员工具」**（目标人群是被配置门槛挡住的人）；②**不碰瓷大厂** | 叙述要勾人，但**受众定位不变**、**不与大厂对比叫板** |
| 3 | **合规边界** | **硬约束，不需另行裁定** —— 官网已过 ICP（`蜀ICP备2026057067号`）与公安联网备案（`川公网安备51080202020186号`），文案**不得构成虚假宣传**（「永久免费」「全自动无人值守」这类与实况不符的承诺一律不写） | 逐条自检 |
| 4 | **官网与 README 是否同一套措辞** | **同源**（README 可略详）—— 已按此默认执行，如无异议照此推进 | 同一卖点两处用同一套说法 |
| 5 | **英文面是否同步** | **不同步**（本条只改中文）—— 已按此默认执行，如无异议照此推进 | 不动英文资源 |

**由此得到的写作准则**（本条的执行口径）：

1. **改的是「怎么讲」，不是「讲什么」** —— 事实、能力清单、受众定位一律不动。
2. **卖点前移、形容词后退** —— 少罗列功能动词，多讲「你会因此少干什么 / 少操什么心」。
3. **允许修辞与反差** —— 但每句都要能在软件里找到对应事实。
4. **不碰瓷、不设假想敌** —— 不出现「比 XX 强」「不像 XX 那样」这类对比式叫板。
5. **允许口语与网络词**（如「白嫖」）—— 判据是「**人爱听**」，**不是「正式」**；**说人话、"能不能被记住"优先于端庄**（老大 2026-10-16 09:05：「总要说些现在的人爱听的，而不是我们之前纯介绍」）。**红线只有上面两条 + 合规面（不虚假宣传），不自行扩大。**

### 7.8 评审

> - **这版建议的首屏**：**「你只负责提需求」/「原地升级当老板」** —— 卖的是 **PM 角色/身份**。
>
> 这是**换卖点**，不是改措辞。两条路各有代价：
> - **换**：差异化更强（“能开项目、派活、收回执的总管”确实少见），但**理解门槛更高** —— 普通人得先知道“全局会话”“派活”是什么。（**“项目”这个词本身不撞红线①** —— 它就是个容器，见 §7.9。）
> - **不换**：首屏保持零门槛，全局 PM 退到 `features`（现 `site.ts:167` 已有「全局助理派活」一条）里强化。
>
> **我的倾向**：**首屏不换** —— 通用能力是最大公约数，全局 PM 是"第二眼惊喜"，放 `features` 里重写（把「全局助理派活」那条从一行扩成有画面感的一段）。但**这属于产品定位，得你拍。**

### 7.9 「项目」= 工作空间，不是开发项目（老大 2026-10-16 09:19 口径）

> 老大原话：「**项目不一定非要是开发项目啊，有些地方叫工作空间 不叫项目**」

- **软件事实**：`project` 这个实体在 UI 里叫「项目」（`chat.json:27/94/102/106…`），但**软件自己的帮助文案就点破了** —— `chat.json:341`：「**项目相当于工作空间**，可保存项目名、工作目录、SSH 连接和默认模型」；另有「工作区」（`:1015/:1018`）、「工作空间」（`:1213`）在别处混用。
- ⇒ **它是容器，不绑开发**：一个文件夹 + 一个 SSH + 一个默认模型，干哪行的活都行。
- **纠正 §7.8 的一处过度担心（已撤回）**：我先前把「项目 / 派活 / 建任务」当成"项目管理词、易撞红线①"。**这条不成立** —— 红线① 管的是**整体定位**（别把软件写成程序员工具），不是**禁用某个词**；「项目」不是程序员专属词。
- **官网用词建议**：主词**跟软件 UI 对齐，用「项目」**（否则官网说一套、进软件全叫"项目"，用户懵）+ **首次出现白话点破一次**：「项目就是一个工作空间 —— 一个文件夹、一个 SSH、一个默认模型，什么活都能放」。官网现仅 `site.ts:167` 一处用到「项目」，**改动面很小**。

### 7.10 落点方案（老大 2026-10-16 09:24 拍板：**首屏不换**）

> 老大原话：「**首屏不换，不过得找到地方描述刚刚这个**」

- **裁定**：`hero.title` 保持「你说一句，它去把活干完」**不动**（§7.8 的方向问题收口）。
- **要求**：§7.6 那套**全局 PM 故事**（提需求 → 建任务 → 开项目 → 派活 → 收结果 → 叫停 → 清队列）**要在官网找个地方描述**。

**★ 落点推荐：`advantages` 新增第三组。**

| 判据 | 说明 |
|---|---|
| **零组件改动** | `sections/advantages.tsx` 是**通用渲染** —— `advantages.groups.map` 出「分类胶囊 + 卡片（1 条单列 / 多条两列）」，**新增一组只加数据、不动 JSX** |
| **文案属性对** | advantages 标题 =「**为什么是它**」= 说服 / 差异化区；全局 PM（"你只负责提需求，剩下它管"）**正是差异化卖点** |
| **容量够** | 每卡有 `name` / `quote`（勾子）/ `body`（故事），装得下这套链路；`features` 一条只有一段 `desc`，装不下 |

- **组名 / 卡片措辞**（"省心" / "当老板" / "不用你管" 之类）：**开工时定**，不上呈。
- **写作硬约束**（§7.8 + §四-3）：①不说"项目自己长出来"（是能力非保证）②不说"不用你配"（父目录要配一次）③有落点约束 ④「回执」→「干完自动告诉你」。

**配套两处**：

1. **`features` 那条「全局助理派活」`desc` 同步加厚**（一行 → 点出关键动作），与 advantages 新组呼应。**截图已有**（`assetNo 5`），无需新素材。
2. **§7.9 的白话点破落在这里** —— `site.ts:167` 是全站**唯一**出现「项目」的地方，把「项目就是一个工作空间」放在这一组里最自然。

**备选（改动更小、容量有限）**：只扩 `features` 那条 `desc`，不动 advantages。**我倾向加 advantages 一组** —— 一行 desc 装不下这套故事，且会破坏选项卡版式。
