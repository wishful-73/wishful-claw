### 5.2 两个维护为豁免而非拆分的理由

- **`clipboard-enhancer.ts`**：九个模块级可变绑定（`history` / `config` / `lastClipboardText` / `lastClipboardImageHash` / `lastImagePollAt` / `previousForegroundWindow` / `previousFocusWindow` / `openedWithAlt` / `clipboardWindow`）被持久化、捕获、IPC、窗口四块代码交叉读写。`history` 有 8 处整体赋值 + 2 处原地 `unshift`，拆开只能二选一：跨模块 `export let` + 全改 setter（必改逻辑，违反第 9 条），或造 state 容器 + 访问器层（新增中间层，每次读写多一跳）。文件头已写明实质证据与行号。
- **`updater.ts`**：11 个可变绑定（`updater` / `initializePromise` / `checkPromise` / `periodicRecheckTimer` / `checkIsPeriodic` / `downloadGate` / `installGate` / `options` / `coordinator` / `activeOperationId` / `lastProgressLogAt`）构成同一个更新器状态机，写入点横跨初始化、检查、下载、安装、周期重查五个阶段，没有一个阶段能只拿一半；按阶段拆文件会互相 import 对方 state ⇒ 循环依赖。
