## 三、筛选集合（**已定：3 项** —— 老大 2026-10-12 12:34）

### F1 模型

按 `provider · model` **组合**多选。

⚠️ **必须带 provider**：同一个 `model_id`（如 `claude-sonnet-4-5`）会在多个服务商下同时出现，只按 `model_id` 筛会把几家的量混在一起。

- **选项来源**：**复用当前窗口 `db/usage-by-model` 的返回**（`UsagePanel.tsx:173-176` 已在拉），其行键天然就是 `(providerId, modelId)` 组合 ⇒ **零额外查询、与图表口径天然一致**。
- **形态**：搜索式多选（组合数可能几十个），选中项显示为 `服务商 · 模型`。

### F2 状态

成功 / 失败 二选（可多选）。附一个「**只看失败**」快捷入口 —— 这是本条最常用的动作。

### F3 HTTP 状态码

按 `http_status_code` **精确**匹配，支持逗号分隔多值（如 `429,503`）。
**形态（助手拍定的实施细节）**：文本输入框，不做下拉 —— 状态码全集没有现成的聚合来源，为它单独加一个查询或端点不划算。

### 被砍掉的候选（**老大 2026-10-12 12:34 裁定**）

| 候选 | 结论 |
|---|---|
| 来源筛选（`runtime_role` / `scope` / `collaboration_mode`） | **砍**（「条件不用那么多」） |
| 关键字搜索（`error_message` / `session_id` 模糊匹配） | **砍**（同上）—— 注意：**这意味着「按报错内容搜」这个诉求本次不做** |
| 只看重试行（`attempt_index > 1`） | **砍**（同上），但**状态筛选 + 模型 + 状态码已覆盖主要排查路径** |
| 成本 / token / 耗时的**数值区间**筛选 | **不做** —— 面板定位是「宏观趋势 + 异常定位」，区间筛选频率低。 |
| `session_id` **精确筛选** | **不做** —— 原定由关键字搜索覆盖，该条已砍 ⇒ 明确不做。 |
| 表格**排序**（按耗时 / 成本 / 时间） | **不做** —— 属**另一件事**（表头排序交互 + 服务端 `ORDER BY` 白名单），要就单开一条。 |

## 四、作用范围（**已定：只作用于明细表** —— 老大 2026-10-12 13:42）

**结论**：筛选条件**只作用于「请求明细」表**；**上方概览数字 / 折线柱状图 / 按模型汇总一律保持「全局条件」**（只受时间窗口 `range` 影响，**不受明细筛选影响**）。

老大原话：

> 「筛选只作用于明细表，上方概览的是全局条件」

**为什么这样对**：

1. 上方是「**这段时间整体在烧什么**」的宏观视图，下方是「**挑具体请求看**」的显微镜 —— 两者口径本就不同，**过滤明细不该动总量**（否则数字缩水会误导判断）。
2. **改动面收到 1 个端点**：只动 `db/usage-logs`；上方 4 个端点（`usage-overview` / `usage-buckets` / `usage-model-buckets` / `usage-by-model`）**一律不动**。
3. 「按模型看整体走势」**已由折线图的按模型拆线覆盖**（`usage-model-buckets`），不缺这个能力。

**已否决 —— 方案 B**（筛选同时作用于上方 5 个端点）：宏观数字会随明细筛选一起缩水，**违背「上方是全局条件」的口径**，且改动面 ×4。
