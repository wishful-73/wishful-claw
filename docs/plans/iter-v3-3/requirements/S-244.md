# S-244：插件基座（5/5）· 安装确认与卸载清理

> 本号是 **R-4 插件基座**拆分出的第 5 条（共 5 条：S-240 ~ S-244）。依赖 S-240。收尾刀。

## 1. 原话 / 来源

> 2026-10-27 14:03 老大：

性质：**体验 + 工程完整性**。渲染端 + 主进程，无 C# 改动。

归属：**v3-iter-3（产品 1.0.3）**。

编号：S-244。

## 2. 目标

1. **安装时让用户知道自己在装什么** —— 一行说明 + 勾选确认（不是风险墙，不是拦截）
2. **卸载时不留垃圾** —— 插件目录 / session 分区 / 私有 KV 三处一起清

## 3. 现状（2026-10-27 实读源码）

### 3.1 安装链路已有，确认缺失

`src/main/ipc/extension-handlers.ts`：

- `extension:install-from-folder`（`:71-72`）
- `extension:update`（`:83-84`）
- `extension:remove`（`:105-106`）
- `extension:open-folder`（`:114-115`）
- `extension:storage-get` / `set` / `delete`（`:139-155`）

⇒ **安装动作本身通了，但没有任何确认步骤** —— 选中文件夹即装。

### 3.2 卸载只删目录，另两处不清

`extension:remove` 只管插件目录。**不清理**：

- `partition: persist:plugin-<id>` 的 session 数据（S-241 新增，现在还不存在）
- `extension:storage-*` 私有 KV（若存在主程序侧存储）

⇒ 依赖 S-241 落地后才能验证「分区清了没有」。

## 4. 落点

### 4.1 安装确认（一次性、不重复骚扰）

选中文件夹 → 解析 manifest → 弹确认：

```
即将安装插件「<name>」 v<version>
由 <id> 提供 · 第三方

此插件可访问你的文件、程序与数据，并可在你电脑上运行程序。
需额外下载运行文件约 489 MB（安装后再点下载，不会自动下）。
请确认来源可信。

☐ 我已了解，仍要安装
                         [取消]  [安装]
```

- **不勾不能装**（唯一强制项）
- **勾选状态按插件 id 记住**（同一个插件更新时不再问）—— 记录在安装历史里，不进 manifest
- **「需额外下载约 XX MB」是必须项**（老大 14:17「知道有这个功能」的落点之二）：体积取自主程序内置资产表（[S-242](S-242.md) §4.1），不取插件自报。插件无资产则**整行不显示**，不留空行
- **不同文案按级别分**：只声明 `tools` 的插件说明可简化；声明 `views` 的必须带「运行程序」那句

### 4.2 卸载清理（**改口径**：不碰共享资产）

| 清理目标 | 做法 | 备注 |
|---|---|---|
| 插件目录 | 现有逻辑保留（`extension:remove`） | |
| session 分区 | `session.fromPartition('persist:plugin-<id>')` → `clearStorageData()` 后删目录 | |
| 私有 KV | 删 `extension:storage-*` 对应数据 | |
| **已下载资产** | **不删** | ⚠️ 改口径见下 |
| 运行态 | 先关窗口（S-241）、再按 pid 树收子进程（S-241） | |

**为什么资产不跟着删**：资产落在**主程序共享区** `%APPDATA%/WishfulClaw/plugin-assets/`（[S-242](S-242.md) §4.2），不属插件目录。理由是 ①插件更新不重下 ②多插件可共用同一模型 ③卸载时**无法判断还有没有别的插件在用**。

⇒ **清理改为独立入口**：设置页「存储」内列「已下载的插件资产」+ 每项体积 + 单独删除 + 「全部清理」。谁下的、多大、还占不使用中，一眼看清。

**顺序**：停用 → 关窗口 → 收子进程 → 清分区 → 清 KV → 删插件目录。任一步失败记录但不中断后续（尽量清干净）。

## 5. 验收

1. 选文件夹安装 → 弹出确认 → **不勾「安装」按钮禁用** → 勾上才能装
2. 取消 → 什么都没发生，插件列表无变化
3. 装完 → 卸载 → **目录、session 分区、私有 KV 三处都空**（逐个验证，不是「看起来没了」）
4. 同插件更新（版本号变）→ **不再弹确认**
5. 卸载某个已下载 489 MB 资产的插件 → **资产文件仍在**，设置页「已下载资产」列表里能看到并单独删掉
6. 卸载跑着的插件（窗口开着、子进程在跑）→ 先关窗口收进程，再清文件，**不出现文件占用删不掉**
7. 主程序重启后插件列表与卸载状态一致（不出现「列表还在、文件已删」）
8. 装一个声明了资产的插件 → 确认弹窗里出现「需额外下载约 XX MB」；装一个没资产的 → **该行不出现**

## 6. 风险

| # | 风险 | 处置 |
|---|---|---|
| 1 | 确认弹窗变「每次都烦」 | 按插件 id 记住，只在**首次安装**问 |
| 2 | 卸载时文件被占用删不掉 | 先关窗口收进程（S-241），再删；失败记录日志并提示「需重启后清理」 |
| 3 | `clearStorageData` 异步，删目录抢跑 | 串行 await，不并发 |
| 4 | 误删主程序自己的分区 / KV | 分区名前缀强校验必须为 `persist:plugin-`；KV 必须带插件 id 前缀 |
| 5 | **共享资产无人清理**（卸载不删 ⇒ 可能留 1 GB 垃圾） | 设置页「已下载资产」独立入口 + 每项体积 + 「全部清理」；本号必须一起交付，否则就是新造的垃圾堆 |

## 7. 不做什么

- **不做插件权限审核 / 白名单** —— 老大 14:03 定不设防
- **不做签名校验 / 来源验证** —— 本阶段只提示「请确认来源可信」
- **不做插件市场**
- **不做「已安装插件」的自动更新** —— 只支持手动 `update`
- **卸载不删共享资产** —— 见 §4.2，改由独立清理入口负责

## 8. 实施记录（2026-10-29，v3-iter-4 刀 5）

### 8.1 先纠一处旧结论（§3.2 写错了）

§3.2 当时写「`extension:remove` 只管插件目录，不清理私有 KV」。**实读 C# 后不成立**：
`ExtensionManifestStore.cs:140-186` 的 `Remove` 已经做了四件事 —— 删插件目录、从 state 文件里摘掉 id、
从 `extensions storage` 里摘掉该 id 的整个 KV 命名空间、删掉 manifest 里声明过的所有 secret 配置键。

⇒ 本号真正缺的只剩 **session 分区**（`persist:plugin-<id>`）—— 那是 S-241 才引入的东西，C# 侧根本不知道它存在。
另外 §4.3 预想的 `confirm` 参数走主进程也没采用（见 8.3）。

### 8.2 卸载清理（`extension:remove` 顺序钉死）

| 步骤 | 谁做 | 备注 |
|---|---|---|
| 1 停用 + 收子进程 | `unsyncExtensionResources` | 原有逻辑 |
| 2 关插件窗口 | `closePluginView(id)`（S-241） | 窗口还开着时会持续往同一个分区写 localStorage，清完立刻长回来 —— 所以必须排在清分区之前 |
| 3 清 session 分区 | 新增 `src/main/plugins/plugin-cleanup.ts` | `clearStorageData()` + `clearCache()` + 删 `{userData}/Partitions/plugin-<id>` |
| 4 删插件目录 / state / KV / secret | C# `extension/remove` | 已有，未改动 |

清理**不抛错**：任一步失败只往返回值里塞 `cleanupWarnings: string[]`，主流程照样算成功。
理由是一个锁住的 Cookie 文件不该让卸载停在那里，留下「列表里有、目录删一半」的脏状态。
渲染端拿到 warning 弹一条「部分缓存文件被占用，重启后自动清理」。

**id 判据抽成纯函数**（`src/main/plugins/plugin-cleanup-rules.ts`）：`isValidExtensionId` / `pluginPartitionName` /
`pluginPartitionDirName`，正则与 C# `ExtensionIdRegex` 一字不差（`^[a-z0-9][a-z0-9_-]{1,63}$`）。
`plugin-window.ts:197` 原来自己拼 `persist:plugin-${pluginId}` 字面量，现在改成调 `pluginPartitionName` ——
两处各写一遍，早晚会漂，而漂的那一次就是删错目录。

### 8.3 安装确认（渲染端，无后端改动）

§4.3 原本设想给 `extension:install-from-folder` 加 `confirm` 参数。**没这么做**：确认是「用户看没看懂」，
不是「后端允不允许」，拦在主进程只会让两处都要维护同一套文案。改成渲染端在调安装之前先读一遍目录：

| 步骤 | 实现 |
|---|---|
| 读摘要 | `extension-install-guard.ts` 用 `fs:read-file` 读 `<folder>/extension.json`，解析 id / name / version / tools / views / assets |
| 算体积 | 声明的资产 id 去 `plugin-asset:catalog` 匹配，**查不到的 id 不计入**（宁可少报，不能编数字） |
| 记住确认 | localStorage `wishful.extension.install-ack`，按插件 id 记；同一插件更新不再问（判据 4） |
| 弹窗 | `extension-install-dialog.tsx`：标题带名称与版本、一行提供方、按 `views` 有无分两套「它会碰什么」文案、资产行（无资产时整行不出现）、勾选框 + 取消/安装 |

**不勾，安装按钮禁用**是唯一强制项。选错目录（选成子目录 / 任意文件夹）给的是人话错误：
「这个目录里没有 extension.json，请选择插件根目录」，不是 `Unexpected token <`。

### 8.4 共享资产的清理入口（§4.2 + §6 风险 5）

新增 `plugin-assets-storage.tsx`，挂在「自定义扩展」页底部：只列 `state === 'ready'` 的资产（没下载的不占磁盘，
列出来只会让人误以为占了空间），显示名称 / id / 体积 / 总计，单项删除与「全部清理」都走 `confirm`。
下载完成由 `plugin-asset:progress` 推送触发重算，不轮询。
