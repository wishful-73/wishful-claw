# S-217：更新安装沿用历史安装范围与安装路径

## 1. 原话 / 来源

**2026-10-22 08:24**：

> 讨论一个需求，目前更新安装的时候 每次都要选择是给所有用户安装还是当前用户，以及安装路径有些用户是选过其它路径的。在安装的时候能拿到历史版本的路径和选择么

**2026-10-22 08:30**：

> 我的意思就是能默认值加载历史路径就行。现在是有这个还是不是这个，如果能做 那么就登记需求

**2026-10-22 08:33**：

> 之前就是有用户反映 他们已经安装过了，然后选了自定义路径的，结果更新安装的时候又是默认的推荐路径而不是之前的自定义安装路径，只是之前一直没有管，所以我也不知道这个问题是否真实存在

来源：用户反馈（历史遗留，未登记过），2026-10-22 由老大提出复议。

## 2. 现象

分三种子现象，**确定性不同**：

| # | 现象 | 确定性 |
|---|---|---|
| A | 更新安装时「为所有用户 / 仅当前用户」页每次出现，无法跳过 | **确定**（模板行为，见 §3） |
| B | A 页被人改选后，安装路径从历史自定义路径变成该范围的默认路径，旧安装残留 | **确定**（代码链路完整） |
| C | A 页未被改选，路径仍回落到默认推荐路径 | **未确认**，静态勘测未找到断裂点，需真机实测 |

用户原话对应的是 C，但 B 足以产生完全相同的用户感受 —— 用户分不清"我没改选"和"我点快了点成了另一个"。

### 2.1 安装目录与运行数据是分离的（2026-10-22 实查）

| 位置 | 路径 | 内容 | 决定方 |
|---|---|---|---|
| 安装目录 | `C:\Program Files\WishfulClaw`（per-machine）<br>`%LocalAppData%\Programs\Wishful Claw`（per-user） | exe / dll / resources | 安装器「范围页 + 目录页」，即本需求对象 |
| 运行数据 | `%USERPROFILE%\.wishful-claw` | `index.db` 589 MB<br>`data.db` 39 MB<br>`config.json` 976 KB<br>`settings.json` / `agents/` / `memory/` / `projects/` 等 | `WishfulClawDataDir.cs:15-17` 固定按 `UserProfile` |
| Electron userData | `%USERPROFILE%\.wishful-claw\electron-user-data` | Cache / Local Storage / Preferences | `src/main/index.ts:236` `app.setPath('userData', ...)` |

数据目录可用环境变量覆盖：`WISHFULCLAW_DATA_DIR`（`WishfulClawPaths.cs:6`）。

模板注释印证同一口径：`installer.nsh:77`、`:89` `# electron always uses per user app data`。

**@ 双安装会并发打开同一份 `index.db`** —— 589 MB 单文件 SQLite、WAL 模式，两个进程同时写会撞锁、版本错乱，存在写坏数据的风险。现象 B 的真实危害不是多占磁盘，是**数据可能损坏**。这条把 §5 方案 A 的必要性从「体验优化」提到「数据安全」。

另：`%APPDATA%\WishfulClaw` 是旧版未改 `userData` 路径时的残留目录，当前链路已不读写（待清理确认）。

实测样本（本机，per-machine 安装）：

```
HKLM\Software\cfc79f30-8748-54f5-ad78-ed9ba15bc986
  InstallLocation = C:\Program Files\WishfulClaw
卸载项: HKLM\...\Uninstall\cfc79f30-8748-54f5-ad78-ed9ba15bc986
  UninstallString = "C:\Program Files\WishfulClaw\Uninstall WishfulClaw.exe" /allusers
```

写入侧正常，`InstallLocation` 有值。

## 3. 代码链路

模板路径 `node_modules/app-builder-lib/templates/nsis/`（electron-builder **26.15.3**，自首次引入起未升级）。

### 3.1 当前打包配置

`electron-builder.yml`：

```yaml
nsis:
  oneClick: false
  allowToChangeInstallationDirectory: true
```

`perMachine` **未设** ⇒ `NsisTarget.js:445` `!oneClick || perMachine === true` 成立 ⇒ 定义 `INSTALL_MODE_PER_ALL_USERS_REQUIRED` ⇒ 安装范围可选（`assistedInstaller.nsh:18-20` 插入 `PAGE_INSTALL_MODE`）。

### 3.2 历史值的写与读

**写**：`include/installer.nsh:104` `registryAddInstallInfo` 无条件写：

```nsis
WriteRegStr SHELL_CONTEXT "${INSTALL_REGISTRY_KEY}" InstallLocation "$INSTDIR"
```

`INSTALL_REGISTRY_KEY = "Software\${APP_GUID}"`（`multiUser.nsh:8`），`APP_GUID` = `cfc79f30-8748-54f5-ad78-ed9ba15bc986`。per-user 落 `HKCU`，per-machine 落 `HKLM`（`SHELL_CONTEXT`，`installer.nsh:79-96`）。

**读**：`installer.nsi:77` `.onInit` 内调 `initMultiUser`，早于所有页面：

```nsis
; assistedInstaller.nsh:112-120
ReadRegStr $perMachineInstallationFolder HKLM "${INSTALL_REGISTRY_KEY}" InstallLocation
ReadRegStr $perUserInstallationFolder    HKCU "${INSTALL_REGISTRY_KEY}" InstallLocation
```

`assistedInstaller.nsh:135-152` 三分支：

- 只有 per-user ⇒ `setInstallModePerUser`
- 只有 per-machine ⇒ `setInstallModePerAllUsers`
- 都没有 / 两处都有 ⇒ 默认 `setInstallModePerUser`

两个 setter 里直接覆盖 `$INSTDIR`：

```nsis
; multiUser.nsh:26-28（per-user）
ReadRegStr $perUserInstallationFolder HKCU "${INSTALL_REGISTRY_KEY}" InstallLocation
${if} $perUserInstallationFolder != ""
  StrCpy $INSTDIR $perUserInstallationFolder

; multiUser.nsh:75-90（per-machine）
ReadRegStr $perMachineInstallationFolder HKLM "${INSTALL_REGISTRY_KEY}" InstallLocation
${if} $perMachineInstallationFolder != ""
  StrCpy $INSTDIR $perMachineInstallationFolder
${else}
  StrCpy $INSTDIR "$PROGRAMFILES64\${APP_FILENAME}"
```

### 3.3 现象 A：范围页跳不过

`assistedInstaller.nsh:18-20` 无条件插入 `PAGE_INSTALL_MODE`；`multiUserUi.nsh:31-92` 的 PRE 函数只处理三种跳过（UAC 内层进程 / `$isForceMachineInstall` / `$isForceCurrentInstall`），**没有 `isUpdated` 判断**。

对比目录页：`assistedInstaller.nsh:25-26` 有 `!insertmacro skipPageIfUpdated`。

`isUpdated` 判据 = 命令行是否带 `--updated`：

```js
// nsisScriptGenerator.js:32-36
!macro _isUpdated _a _b _t _f
  ${StdUtils.TestParameter} $R9 "updated"
```

| 场景 | 范围页 | 目录页 |
|---|---|---|
| app 内自动更新（`updater.ts:104` → `quitAndInstall(false, true)`） | 出现 | 跳过 |
| 手动双击安装包 | 出现 | 出现（`$INSTDIR` 已预填历史值） |

### 3.4 现象 B：范围改选 ⇒ 路径换家 + 双安装

`multiUserUi.nsh:41-43` 给自定义钩子留了口子：

```nsis
!ifmacrodef customInstallmode
  !insertmacro customInstallMode
!endif
```

当前项目**没有** `nsis.include`，`build/`、`resources/`、`scripts/` 下无 `.nsh`，该钩子为空。

于是 PRE 直接落到 `:45-65` 之外的建对话框分支，用户可自由改选。改成「所有用户」时 `setInstallModePerAllUsers` 读 HKLM —— 从没 per-machine 装过的机器读空 ⇒ `$INSTDIR` 变 `C:\Program Files\WishfulClaw`，旧 per-user 那套不删（`installSection.nsh:52-58` 只卸载 `SHELL_CONTEXT` 与 `HKCU`，反向组合不处理）。

### 3.5 现象 C：静态未找到断裂点

已逐项排除：

- `electron-builder` 版本从未升级（`package.json` 恒为 `^26.15.3`）
- `appId` / `productName` / `executableName` / `oneClick` / `allowToChangeInstallationDirectory` 在 git 历史中从未变更
- `APP_FILENAME = WishfulClaw`（`NsisTarget.js:166` → `targetUtil.js` `getWindowsInstallationDirName`，取 `productFilename` 且匹配 `^[-_+0-9a-zA-Z .]+$`）
- `SetRegView 64` 在 `installer.nsi:67` 执行，**早于** `initMultiUser`（`:77`），读写视图一致
- `installSection.nsh` 全程不改 `$INSTDIR`（`:60` 仅 `SetOutPath`）

## 4. 根因

**现象 A / B**：`PAGE_INSTALL_MODE` 缺 `skipPageIfUpdated` 且项目未挂 `customInstallMode` 钩子 —— 更新流程把「安装范围」当自由选项重新暴露，一旦改选就触发 `$INSTDIR` 重算，历史路径随之丢弃。

**现象 C**：**未确认**。静态勘测指向"读得到"，需真机实测定性。已知唯一确定会导致读不到的条件是**换 Windows 用户账户**（per-user 的 `InstallLocation` 在 `HKCU`，另一个账户天然读不到，属 per-user 语义固有，非缺陷）。

## 5. 修复方向

| 方案 | 做法 | 优点 | 风险 / 缺点 |
|---|---|---|---|
| **A** | `nsis.include` 加 `customInstallMode`：`.onInit` 已填好的 `$hasPerMachineInstallation` / `$hasPerUserInstallation` 只有一处为 1 时，设 `$isForceMachineInstall` / `$isForceCurrentInstall` = 1，PRE 直接 `Abort` | 范围页彻底跳过；路径自然沿用；堵掉双安装；首次安装不受影响 | 两处都装过时仍需人工选（正确行为） |
| B | 同 A，但额外在 `customInit` 里把 `$INSTDIR` 兜底写死为注册表值 | 更硬 | 若用户确有换路径意图就改不了；与 A 收益重叠 |
| C | 改 `oneClick: true` 走静默安装 | 彻底无页面 | 丢自定义路径能力，与用户诉求相反；需要改整个安装体验 |
| D | 不改，只在文档写明"更新时范围页要选对" | 零成本 | 用户不会看文档；双安装问题留着 |

**我的倾向：A。** 收益最大、改动最小、风险可控 —— 只改"更新"路径，首次安装两页照旧。且由 §2.1 可知，A 不只是体验优化：**它堵的是两份程序并发写同一份 `index.db` 的数据损坏风险**，优先级高于"少点两次下一步"。

CENTRAL 待定：目录页在手动双击场景仍会出现（`MUI_PAGE_DIRECTORY` 的跳过条件绑死在 `isUpdated`，可挂钩子的 `customPageAfterChangeDir` 是页面之后，撤不掉页面）。但 `$INSTDIR` 已是历史值，点「下一步」即沿用，是否也要一并处理 **待老大裁定**。

## 6. 代价与取舍

**（规划态，实施后回填）** 预期代价：

- 用户在更新时**失去**改安装范围的自由。想从 per-user 迁到 per-machine 必须卸载重装。
- 副作用依赖 `multiUserUi.nsh:45-65` 的既有分支，其中 `$isForceMachineInstall = 1` 会触发 `UAC_RunElevated` —— per-machine 用户每次更新要过一次 UAC。这是沿用历史模式的必然结果，不是新增负担（per-machine 安装本来就要提权）。

## 7. 刻意不做

**（规划态，实施后回填）**

- 不做 `$INSTDIR` 兜底写死（方案 B）：与 A 收益重叠，且损害"确实想换路径"的场景。
- 不改 `oneClick`（方案 C）：与产品定位冲突。
- 不处理跨 Windows 账户读不到 `HKCU` 的情形：per-user 语义固有，要解决只能强制 per-machine。

## 8. 验收

**前提**：需真机安装，安置临时路径，测完卸载。

| 场景 | 步骤 | 期望 |
|---|---|---|
| 基线复现 | 当前 1.0.0 包，per-user 自定义 `D:\tmp\WCTest` 装一次 → 再双击同一安装包 → 看范围页与目录页 | 记录实际默认值，据此判定 §2 现象 C 真伪 |
| A 修复验证 | 同上环境，范围页应**不出现**，目录页默认 `D:\tmp\WCTest` | 通过 |
| 反向 | per-machine 自定义路径装 → 再跑安装包 | 范围页不出现，目录页默认历史 per-machine 路径 |
| 首次安装 | 干净机器（或清空两条注册表键） | 两页照常出现，行为不变 |

| 数据安全 | per-user 自定义路径装 → 改选「所有用户」复现双装 → 两个 exe 同时启 | 修复前：记录是否出现 `index.db` 锁错误 / 数据异常（作为 B 危害的实证）；修复后：不可能双装 |
