# S-254：耗时读数补「天」并让秒常驻；亚秒（毫秒）只留给工具调用

> 小需求。一个纯函数 + 状态栏一处判据 + 一套断言。无新功能，只调耗时读数的单位阶梯。

## 1. 原话 / 来源

> 2026-10-28 12:23 老大：

> 「我们之前处理了时间格式 再进行一点优化 目前执行过程中到1小时以后 出现的是时分 没有看到秒，
> 然后网络中断了，所以我不确定情况，我希望是天时分秒 这是有值就显示。毫秒只在工具调用上有，
> 输入框左上角状态栏不需要毫秒」

性质：**读数规范**，接 S-245（秒档去小数）同一根轴。

归属：**v3-iter-3（产品 1.0.3）**。编号：**S-254**。

## 2. 目标

1. 单位阶梯从 `ms / s / m / h` 扩到 **`ms / s / m / h / d`**（天）。
2. **小时档必须带秒**。现状 `1h2m` 之后就只剩时与分，秒被整段丢掉 —— 老大跑到 1 小时以上时
   无法从读数判断「还在走还是断了」。
3. **有值就显示**：某单位数值为 0 就跳过（沿用既有口径 `1h` 不写 `1h0m`、`1m` 不写 `1m0s`）。
4. **毫秒只留给工具调用**。输入框左上角状态栏（`composer-status-indicator`）不出 `42ms`
   这类亚秒读数 —— 挂载瞬间的第一帧就会闪一下，没有信息量。

## 3. 现状（2026-10-28 实读）

`src/renderer/src/lib/format-duration.ts:20-34`：

```ts
const totalMinutes = Math.floor(totalSeconds / 60)
const seconds = totalSeconds - totalMinutes * 60
if (totalMinutes >= 60) {
  const hours = Math.floor(totalMinutes / 60)
  const minutes = totalMinutes - hours * 60
  return minutes === 0 ? `${hours}h` : `${hours}h${minutes}m`   // ← 秒在这里整段消失
}
```

- 无天档：`25h` 会继续写 `25h`，不折成 `1d1h`。
- 状态栏 `resolveRunningElapsedLabel`（同文件 `:54-64`）直接复用 `formatDurationMs`，
  所以挂载首帧 `now − startedAt ≈ 30ms` 时状态栏会显示 `30ms`，下一 tick 才变 `1s`。

## 4. 要求

### 4.1 阶梯口径

| 区间 | 读数 | 说明 |
|---|---|---|
| `< 1s` | `340ms` | 只给工具调用 / 请求明细用 |
| `1s ~ 59s` | `7s` | 秒档取整（S-245 已定） |
| `1m ~ 59m` | `1m5s` / `1m`（秒为 0 时省） | |
| `1h ~ 23h` | `1h2m2s` / `1h2m`（秒为 0 时省） | **本需求核心：秒回来了** |
| `≥ 1d` | `1d1h1m1s` / `1d`（整点省） | 新增天档 |

「有值就显示」= 零值单位跳过，不做补位（不出 `1h0m0s`）。

### 4.2 谁能看到毫秒

保留：工具卡（`ToolCallCard` / `FileChangeCard` / `CodeGraphToolCard` / `SubAgentCard` /
`ImageGeneratingLoader`）、设置页请求明细、重试延迟（`formatRetryDelay`）。

去掉：**输入框左上角状态栏**。`< 1s` 时**返回 `null`（不出数）**，而不是报 `0s` ——
与该函数既有态度「宁可没有，不可报 0 或负数」一致。

有意不动：`formatPreciseDurationMs`（TTFT 首字延迟）与 `formatRuntimeTtft`（状态栏吞吐旁的
TTFT 读数）—— 那是**性能指标**，`1.2s` 与 `1.8s` 的差别对排查有意义，见 S-245 §4.3。

## 5. 验收

1. 跑一轮超过 1 小时的会话 ⇒ 状态栏读数是 `1h2m2s` 这种，秒在跳。
2. 跑满 24 小时以上 ⇒ 出现 `1d…`。
3. 刚开始跑的第一秒内 ⇒ 状态栏不显示耗时，不闪 `42ms`。
4. 工具卡右侧仍是 `14ms` 这类亚秒读数，没被一起吞掉。
5. `1m` / `1h` 这类整点读法保留（零值不补位）。

## 6. 不在范围

- 不改聊天窗时刻格式（S-222 / `chat-time`）。
- 不动 TTFT 两个读数的精度口径。
- 不动主进程与 C# 侧任何耗时统计。

## 7. 实施记录

2026-10-28 实施完成，源码 1 个文件 + 测试 2 个文件。

### 7.1 源码

`src/renderer/src/lib/format-duration.ts`：

- `formatDurationMs`：整段重写单位链。`total = Math.round(ms)` → `totalSeconds = Math.round(total / 1000)`
  → 按 `d / h / m / s` 整除拆位 → 零值单位跳过拼接。
  **取整只发生一次**，这是关键：旧实现在分钟档对秒二次四舍五入，会吐 `1m60s`。
- `resolveRunningElapsedLabel`：`elapsed < 1000` 直接 `return null`。

### 7.2 测试

| 文件 | 改动 |
|---|---|
| `tests/composer-status-elapsed/program.ts` | 「与操作栏同口径」拆成两段：亚秒段（1/340/999ms）断言状态栏 `null`，1s 以上仍逐字对齐 `formatDurationMs`。单位阶梯补 `1h2m5s` / `1h` / `1d1h1m1s` / `2d`，并钉住「取整只做一次」（3 599 600ms ⇒ `1h`，不出 `1h59m60s`） |
| `tests/message-timestamp/program.ts` | `119 600ms` 由 `1m60s` 改 `2m`；`86 400 000ms` 由 `24h` 改 `1d`，另补天档与小时带秒四条 |

断言随之改成 `2m` —— 是修好，不是放宽。
