## 三、Everything 官方核查（2026-09-28 抓 voidtools 官网，非记忆）

抓取页：`command_line_options`（200）、`multiple_instances`（200）。以下均为官方页原文口径。

### 3.1 命令行参数（本需求只用 `-search`）

| 参数 | 官方说明 | 采用 |
|---|---|---|
| `-search <text>` | *Set the search to the specified text*；**1.4 起**，无 1.5 标注；官方示例 `Everything.exe -s "invoice"` | ✅ **本需求唯一用到的参数** |
| `-s <text>` | 同上，短名 | ❌ **不用** —— `es.exe` 里 `-s` 是「按路径排序」，将来读码易串，统一写长名 |
| `-search*` / `-search-text` 等 | 页上标注 **Requires Everything 1.5** | ❌ 只为兼容 1.4 用户 |
| 其余分组 | 结果（`-sort` / `-columns` / `-thumbnails`）、窗口（`-maximize` / `-on-top` / `-toggle-window`）、数据库（`-reindex` 等）、文件列表、ETP、安装类（`-install-*`） | ❌ 一概不加 |

**关键否定事实**：官方这份参数表**没有任何一项能打开 `Tools → Options`**（即无法用命令行替用户开 HTTP server）。

### 3.2 多实例语义（这条决定了我们什么都不用写）

`multiple_instances` 页原文：

> *If an existing instance is found the command line options are sent and processed by the existing instance.*

⇒ **实例复用由 Everything 自己做**。我们**不加** `-new-window`、**不加** `-config`、**不加** `-instance`、不维护自己的实例名。

### 3.3 不自动探测第三方私有副本（2026-09-28 新结论）

本机存在两份第三方内置的 Everything 副本，**一律不碰**：

| 来源 | 路径 | 版本 | 要害 |
|---|---|---|---|
| uTools | `%APPDATA%\uTools\plugins\4aec480ea79b66b2e15cca81f523571e.asar.unpacked\preload\everything\` | 1.4.1.1009 | 自带 `Everything.db` 97 MB；ini：`run_as_admin=1`、`ipc=1`、`allow_multiple_instances=0`、`http_server_enabled=0`、`etp_server_enabled=0` |
| WPS | `%LOCALAPPDATA%\Kingsoft\WPS Office\12.1.0.29161\office6\addons\everythingsearch\everythingbinary`（含 `12.1.0.28043` 另一份） | 1.4.1.1032 | ini 里 **`exclude_files=...*.exe`、`exclude_folders=...%appdata%...`** ⇒ 接上去用户搜 exe 一个都搜不出 |

理由：① 它们是**宿主的私有副本**，`-search` 投过去等于借别人的进程用，行为不可控（`allow_multiple_instances=0` 时甚至可能另起新进程）；② WPS 那份**索引是裁剪过的**，会给出「明明有文件却搜不到」的假故障；③ 老大的口径是「不存在就**引导用户去下载**」，指的是**用户自己的 Everything**。

## 四、落地形态（Windows 接管式）

### 4.1 总策略

**只做两件事**：① 探测**用户自装**的 Everything exe 路径；② 把关键词经 `-search` 交给它并启动。

探测不到 ⇒ 文件模式**不可用**（置灰 + 引导入口），**不兜底遍历**、**不内置二进制**、**不改用户 `Everything.ini`**、**不代拉起常驻进程**。

### 4.2 探测 exe 路径（只探路径，不接管运行时）

八档，按**代价**分三批跑，便宜的先跑、命中就早返回（挂载面板的常见路径不该为「扫盘」白等一秒）。
表里「优先级」是 `pickEverythingExePath` 的排序；分批只是把便宜的探测并发出去。

| 优先级 | 档位 | 探点 | 说明 |
|---|---|---|---|
| 1 | `manual` | 用户在设置页指定的路径（含「本机检测」自动绑定的） | 最高 —— 便携版（免安装）注册表里探不到，这是主流场景 |
| 2 | `registry` | 卸载项 `DisplayIcon`（剥尾部 `,0` / 引号）/ `InstallLocation` | 覆盖标准安装版 |
| 3 | `service` | 服务 `BINARY_PATH_NAME`（剥引号与 `-svc`） | 装了服务模式会留痕 |
| 4 | `process` | 正在运行的进程映像路径 | 「用户此刻在用的那份」，比猜的强 |
| 5 | `shortcut` | 开始菜单 / 桌面 `.lnk` 的目标（`shell.readShortcutLink`） | 便携版常见落点；要过版本检测 |
| 6 | `program-files` | 常见安装位：`%ProgramFiles%\Everything`、`\Everything 1.5a`、`(x86)`，以及 **scoop / chocolatey / winget** 的落点 | 兜底（包管理器装的都不写官方卸载键，必须显式列） |
| 7 | `path` | `where Everything.exe` | 兜底 |
| 8 | `scan` | 固定盘根往下 3 层（根记 0），跳过 `Windows` / `AppData` / 回收站 / `node_modules` 等，找到即停，**全局 2s 硬超时** | **只有重探（「本机检测」）才跑** —— 它是唯一的猜测档 |

分批：① 手动指定单独看；② `registry` + `program-files` + `path` 一批；③ `service` + `process` 一批；
④ `shortcut` 单独（要过版本检测）；⑤ `scan` 只在重探时跑。移动盘（`DriveType=2`）不扫。

**两道过滤器**（跑在候选上，不是跑在选中结果上）：

1. **第三方私有副本剔除** —— 路径里带 uTools / WPS 私有目录的一律丢（§3.3）。
2. **PE 版本信息校验** —— 候选要读 `ProductName` / `FileDescription` 含 Everything 才认；
   **读不到就放行（fail-open）** —— 老版本或精简 exe 不带这两个字段，拦掉等于误杀真安装。

多个候选命中时**按优先级取一个绑上**，不弹列表让用户挑（老大口径：「检测到直接给他绑定上」）。

**本机实测（干净样本）**：注册表三处 Uninstall 项无 Everything、`HKCU\Software\voidtools` 不存在、上述常见路径全 False、`where` 空、无进程 ⇒ **本机未装**（uTools / WPS 那两份按 §3.3 不计入）。
耗时（本机未装，即最坏路径）：服务查询无、进程查询 413ms（含拉起 powershell）、快捷方式全空、常见落点全无、
扫盘根+1 层 0.01–0.03s/盘、根+2 层 C: 0.84s / D: 0.09s。

### 4.3 调用方式

```
<Everything.exe> -search "<关键词>"
```

- 用 `spawn(exePath, ['-search', keyword], { detached: true, stdio: 'ignore' })` —— **不接管它的输出**，`unref()` 后我们即完成。
- 已有实例在跑 ⇒ 关键词被投递给已有实例、其窗口前置；没在跑 ⇒ `-search` 会顺带把 Everything 拉起（官方语义：set the search to the specified text）。
- **我们不留任何结果状态**：面板不写结果列表、不做高亮、不做图标。

### 4.4 未探到时的引导（两个选项，不能只给下载页）

1. **下载并安装 Everything**（安装版）：`https://www.voidtools.com/downloads/`
2. **本机检测** → 重探一遍（含扫盘），命中就**直接绑上**，不弹列表让用户挑。

（老大 09-28 15:38 口径：「如果用户本机没有，那么我们提供两个选项 1.去安装 2.本机检测，如果检测到直接给他绑定上，
**而不是引导用户去绑定**」。据此「手动指定路径」从主选项**降级为小字兜底** —— 不是让用户去找路径，
是让用户点一下、我们自己扫。）

（原第 3 轮里面「HTTP server 安全建议」「端口占用」两条**随之作废** —— 我们不接 HTTP。）

## 六、性能与交互约束（写死，验收用）

1. 文件模式**不得**接入 [`fs:search-files`](../../../../src/main/ipc/fs-handlers.ts) 那条实时递归链 —— 它就是「很卡」本身。
2. 探测**只读、且不常驻轮询**，分两级：**轻探**（挂载面板 / 切模式 / 开设置页，30s 缓存）只跑前七档；
   **重探**（只有「本机检测」按钮会触发）多跑一档扫盘，命中即绑。不做常驻轮询。
   「重新检测」是轻探重跑（含缓存失效），不是重探 —— 它是「刚才那份结论可能过期了」的意思。
3. `spawn` 必须 `detached` + `unref`，**不能让 launcher 等它退出**。
4. 关键词非空才允许回车；空关键词不启动 Everything。
5. 引导文案里的下载页 URL 是**唯一**外链，落点固定，不随版本变。

## 七、待裁定 / 待办

1. **mac / Linux 是否另立需求** —— 本轮只做 Windows。老大 09-28 13:53「先只做 Windows 就行」。mac（`mdfind`）有**系统自带**的对等物，但「带参数启动」在 mac 无对等 GUI 结果窗口，`mdfind` 只能在终端吐结果 ⇒ 与「接管式」形态不兼容，**建议另立需求再谈**。
2. **未装时文件模式的呈现** —— **裁定：能切进去，进去就是引导页**（2026-09-28 实施时定）。
   原建议是「置灰不可切入 + 旁挂引导入口」，放弃的理由：launcher 面板里**没有**那个旁挂入口会落地的位置，置灰等于把引导藏进设置页 —— 用户既不知道有文件搜索这回事，也不知道缺什么。老大的口径是「**如果不存在引导用户去下载**」，所以引导必须出现在用户切过去的那一眼里。代价是文件模式多一个「未就绪」状态，已在 `FileSearchPanel` 里按 `supported / ready / 未探到` 三档分开渲染。
3. **设置页落点** —— **裁定：launcher 窗口内的「快速搜索设置」页**（2026-09-28 实施时定）。
   原建议是主设置页的「快捷启动」节，放弃的理由：**自定义启动项已经只活在 launcher 窗口的设置页里**（主设置页那个 launcher 节只有开关 + 快捷键 + 说明），文件搜索与「自定义启动项」同属 launcher 自己的配置，放主设置页会把同类配置拆成两处；而文件模式的引导页离这里只有一步，用户看到「未检测到」就能直接跳过来指定路径。
4. **UIPI 风险（未实测）** —— Everything 常以**管理员**运行（uTools 那份 ini 就是 `run_as_admin=1`）。我们从非提权进程 `spawn -search` 投给管理员实例，Windows UIPI 可能拦掉。官方只说「发给现有实例」，未说跨权限级。失败表现（静默无反应 / 另起非提权实例）决定引导文案的第三档要不要写。**实测需先得到老大许可**（副作用：会弹 Everything 窗口、首次可能触发 UAC）。

### 8.2 二轮：探测档位 4→8，命中即绑定（「本机检测」）

**起因**（老大 2026-09-28 15:38）：「便携版 / 绿色版装在了别处？到『设置 → 快速搜索设置 → 文件搜索』手动指定
Everything.exe 的路径」这个不太对 —— 用户真的装了，应该**让我们自己搜、然后检测**。

**落地的文件**

| 文件 | 内容 |
|---|---|
| `src/main/lib/everything-search.ts` | 档位枚举 4→8（加 `service` / `process` / `shortcut` / `scan`）；新增 `EVERYTHING_SOURCE_PRIORITY`、`parseExecutablePathLines`、`getKnownInstallCandidates`、`parseEverythingServiceImagePath`、`isEverythingVersionInfoHit`、`isThirdPartyPrivateEverythingPath`、`sanitizeEverythingCandidates`、`shouldScanIntoDirectory`、`EVERYTHING_SCAN_MAX_DEPTH`（=3） |

| `tests/ipc-msgpack-routing/program.ts` | `launcher:detect-everything` 归入 `PRELOAD_BINARY_ONLY` |

**实施时才定下来的细节**

- **探测分两级的理由**：轻探（档 1–7，亚秒）够覆盖「装在本机标准位置」这一主流；扫盘（档 8）是**唯一的猜测档**，
  只在用户主动点「本机检测」时跑 —— 不能让它拖慢每次切模式。
- **命中即绑定**：`launcher:detect-everything` 探到就写 `everythingExePath` 落盘并标 `everythingExePathAuto = true`，
  设置页据此显示「本机检测」而不是「手动指定」。**用户已经手选过路径时不动它** —— 那是用户自己的判断，优先级更高。
- **绑定后不重探**：直接把结果改写成 `source: 'manual' / detected: true` 并回填探测缓存 —— 重探要再扫一次盘 + 四个子进程，纯浪费。
- **`shell.readShortcutLink()` 解 `.lnk`**：比自己去解 Shell Link 二进制靠谱（Electron 原生）。
- **扫盘要设硬超时**：全局 2s，扫到即停；移动盘（`DriveType=2`）不扫。
- **版本检测 fail-open**：`ProductName` / `FileDescription` 读不到就放行，有值但不含 Everything 才拦。

**顺带修掉的一处漂移**：二轮改写面板时，渲染端的 `refreshEverythingStatus` 被接到了 `launcher:get-everything-status`
（吃 30s 探测缓存），于是「重新检测」按钮点下去拿到的是点之前的结果 —— 而对面那条 `launcher:refresh-everything-status`
（会失效缓存再轻探）从此无人调用，被 `test:ipc-msgpack-routing` 的「白名单通道必须真有人调」断言逮住。
已改回走 `launcher:refresh-everything-status`：**「重新检测」= 轻探重跑，「本机检测」= 重探 + 绑定**，两者不是一回事。
