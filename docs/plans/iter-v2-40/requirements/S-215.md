# S-215：中断执行后收起过程块，操作栏缺耗时统计

> 状态：**已实施并验证通过**（2026-10-21 09:32 登记，提交 `3371aacc`；老大 10-21 14:13 真机测试通过）。
> 类型：**bug**（已有显示位没数据）。
> 归属：**iter-v2-40**。
> 轨道：**软件侧**（纯渲染端；Worker 零改动）。

---

## 一、现象（老大 2026-10-20 08:42 原话）

> 测试发现几个问题 …… 2. 中断执行后，收起了执行过程，但是缺少耗时统计

用户点了停止，执行过程折叠成一块，**底部操作栏该有的耗时没有**。正常跑完的那轮有。

## 二、根因

`components/chat/AssistantMessage/action-bar.tsx:62-65`：

```ts
const finishedAt = updatedAt ?? createdAt
// 耗时只在两个戳都齐、且结束晚于开始时才算（老消息没有 updatedAt）。
const elapsedMs =
  updatedAt != null && createdAt != null && updatedAt > createdAt ? updatedAt - createdAt : null
```

`finishedAt` 已经做了 `?? createdAt` 兜底，但 **`elapsedMs` 硬性要求 `updatedAt != null`**。

中断的那一轮，消息没有 `updatedAt`（没走到正常收尾的写入路径），于是耗时恒为 `null` —— 位子在、数字没有。

数据其实是有的：S-210 已经把 `loop_end` 落成 `meta.runEnd.at`（收尾时刻，渲染端时钟）。同一条消息里，`createdAt` + `runEnd.at` 就能算出这轮跑了多久。

## 三、目标（口径 A：不区分中断与正常结束）

**所有跑完的一轮都要有耗时**，不管怎么结束的：

| 场景 | 耗时来源 |
| --- | --- |
| 正常跑完（有 `updatedAt`） | `updatedAt − createdAt`（现状不变） |
| 中断 / 报错（无 `updatedAt`） | `runEnd.at − createdAt` |
| 老消息（两者都没有） | 不显示，不编 |

**显示位置不动** —— 就是底部操作栏那个已有位置（`action-bar.tsx:150-155`，`10:31 · 12s`）。

## 四、非目标 / 纠偏

- **不在折叠块摘要里新开耗时位**。首版把耗时拼进 `buildProcessSummary` 的摘要尾（`过程 3 个命令 · 12s`），老大 2026-10-21 09:34 原话：「现在是折叠块的标题头最后面加上了耗时。这个显示位置是错误的。本身我们就有耗时的显示位置，为什么要新加一个位置？？」⇒ **撤掉**，耗时只留在操作栏一处。
- 不改结束原因的显示（那是 S-210）。
- 不动时间戳的落库口径（`updatedAt` 该有还是没有，是既有行为）。

## 五、修法

1. `ActionBarProps` 加 `runEnd?: MessageRunEndMeta | null`（`AssistantMessage/index.tsx` 已有 `meta?.runEnd`，直接传）；
2. 耗时口径改为：

   ```ts
   const endAt = updatedAt ?? runEnd?.at ?? null
   const elapsedMs =
     endAt != null && createdAt != null && endAt > createdAt ? endAt - createdAt : null
   ```

3. `finishedAt` 显示时刻同样用 `endAt ?? createdAt` —— 中断那轮也能亮出结束时间；
4. **撤掉** `buildProcessSummary` 的第 4 个参数 `elapsedMs` 与末尾 ` · 时长` 拼接，`ContentRenderer` / `AssistantMessage` / `MessageItem` 上那条透传连同 `index.tsx` 的本地计算一起删掉。

## 六、改动面

| 文件 | 改动 |
| --- | --- |
| `components/chat/AssistantMessage/action-bar.tsx` | 加 `runEnd` prop；耗时与结束时刻用 `runEnd.at` 兜底 |
| `components/chat/AssistantMessage/index.tsx` | 传 `runEnd` 给 ActionBar；删本地 `elapsedMs` 计算 |
| `components/chat/AssistantMessage/content-renderer.tsx` | 删 `elapsedMs` prop 与传参 |
| `components/chat/AssistantMessage/process-summary.ts` | `buildProcessSummary` 回退到 4 参（去掉耗时拼接） |
| `components/chat/AssistantMessage/types.ts`、`MessageItem.tsx` | 删 `elapsedMs` 透传 |
| `tests/run-end-display/program.ts` | 删耗时拼接用例，改钉「摘要不含耗时」 |

**Worker 侧零改动。**

## 七、风险

- `runEnd.at` 是渲染端时钟、`createdAt` 来自落库，两者同源（都由渲染端 `Date.now()` 落），不会出现时钟偏移导致的负数；仍保留 `endAt > createdAt` 守卫。
- 压缩分片的 `fragment.totalElapsedMs`（整轮总耗时）是另一个字段，落在末段操作栏，与本节 `elapsedMs`（本段）并存，互不覆盖。
