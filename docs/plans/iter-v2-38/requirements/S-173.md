## 六、代价与取舍

**实施后回填（2026-10-08）：**

- 实际代价与预期一致：`ProviderCompletionSettings` 扩容要同步 C# 侧四处（record + `Read` / `Write` 两个键 + `ProviderCompletionSettingsService.IsPair` 校验 + `AgentRuntimeImageGenerateExecutor.BuildPayload` 取直）。**未新增任何通道** —— 第四档复用现役三档的 `provider/completion-config-read` / `-write`，与三档同文件、同一次保存。
- 预期取舍确认：显式指定位**优先于** S-166 的「跟随当前对话 provider」。
- 一处**新增**取舍（登记时没写）：指定位的**存在性校验放在主进程**，不在 Worker。Worker 只做「读配置 + 透传两个 id」，`provider` 是否存在、模型是否还在该 provider、`apiKey` 是否为空三关全由 `resolveExplicitImageEndpoint` 判 —— 因为主进程才是拿着 provider store 真正发请求的那一侧，校验与使用同一份数据，不会出现「Worker 说存在、主进程发不出去」。

## 七、刻意不做

- **不动 `ModelManagementPanel`** —— 它在 AI 服务商页（`ProviderPanel.tsx:379`），是本需求的排除项；除非裁定走 C。
- **不删 S-166 的三级回落** —— 它是「没指定时」的兜底，删掉会让未配置用户直接失去生图能力。
- **不删 `ModelFormDialog` 的「使用方式 = 图像」** —— 它是 S-166 的声明路径，也是本档模型下拉的数据来源；本需求只是**新增**一个显式指定位，不是替换声明方式。
- **主进程不读 `config.json`** —— 指定位由 Worker 读出、随 `image:generate` 反向请求送达（裁定 ②甲）。主进程因此只认「请求里带了什么」，不需要知道 Worker 的配置文件在哪，也不会与 Worker 各自解析一遍配置。
- **不做「指定位悬空时回落」** —— 见 §九 裁定。

## 九、实施记录（2026-10-08）

**接线与悬空口径（老大 16:28 / 16:32）：** 甲（Worker 送达）+ 指定位**悬空即报错、不回落** —— 已按此落地。

### 数据链（四档一源）

| 环节 | 位置 | 落点 |
|---|---|---|
| 存储 | `Infrastructure/Storage/ProviderCompletionSettings.cs` | record 尾部加 `ImageProviderId` / `ImageModelId`（默认 `null` ⇒ 既有 `new ProviderCompletionSettings()` 调用不破）；`Read` / `Write` 各增 `imageProviderId` / `imageModelId` 两键 |
| 校验 | `Agent/ProviderCompletionSettingsService.cs` | `IsPair` 增第四对：provider / model 必须成对，否则写入失败 |
| 送达 | `Agent/AgentRuntimeImageGenerateExecutor.cs` `BuildPayload` | 读第四档，非空时写 `imageProviderId` / `imageModelId` 进 `image:generate` 反向请求；**只读不解析、不校验** |
| 面板 | `ProviderCompletionSettingsPanel.tsx` | 第四档 `image`，排在 `fallback` 之后（它是产出能力，不是辅助通道）；`acceptsModel(route, model)` 一处区分过滤规则：三档 `chat`/无 category，图片档 `category === 'image'` |
| 解析 | `main/lib/image-endpoint.ts` `resolveExplicitImageEndpoint` | 新增。provider 存在 + 有 `apiKey` + 模型在该 provider 的 `models` 里 ⇒ 命中；任一不满足 ⇒ 返回可操作错误 |
| 消费 | `main/ipc/reverse-handlers/image-reverse-handler.ts` | 两个 id 任一存在即走显式解析；`error` 非空直接 `{ success:false, error }`；两个都空才走 S-166 三级回落 |

**为什么显式解析另起函数而不是给 `resolveImageEndpoint` 加参数**：显式位的失败语义与回落链**相反**（报错 vs 继续找），塞进同一返回值会逼调用方从「命中了哪一级」反推意图。两个函数各自单一语义，反向处理器的分支就是一句 `if (explicitProviderId || explicitModelId)`。S-166 的既有断言因此**一条未改**。
