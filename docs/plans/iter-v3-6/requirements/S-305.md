## 一、现象

插件工具在聊天窗**从不显示插件卡片**，一律退化成普通工具卡片的文本输出。

不是样式问题，是**一张都渲染不出来**。

## 二、根因：两个断点，任一个都足以让卡片永不出现

### 断点 1 · 解析函数是空桩

`src/renderer/src/lib/extensions/extension-result.ts:4-6`

```ts
export function parseExtensionToolResult(_text: unknown): ExtensionToolResult | null {
  return null
}
```

无条件返回 `null`。连参数名都带了下划线前缀（未使用）——这本身就是「临时占位、还没实现」的标记。

### 断点 2 · 主进程不产出标记

`__wishfulClawExtensionResult` 全仓**只出现一次**：

| 位置 | 性质 |
|---|---|
| `src/shared/extension-types.ts:164` | 只是 `ExtensionToolResult` 接口定义里的一个字段 |

主进程侧**零产出** —— 没有任何代码路径把插件工具结果包装成这个形状。

### 调用链现状

```
ToolCallCard/index.tsx:143-146   parseExtensionToolResult(output)  →  null（永远）
ToolCallCard/index.tsx:509       <ExtensionToolResultCard output={output} />  →  渲染 null
```

`ExtensionToolResultCard.tsx:16-17` 拿到 `null` 直接 `return null`，整棵子树不渲染。

## 三、已完工的部分（不是全没做）

6 种 `kind` 分派**齐全且能跑**（`extension-tool-components.tsx:43-54`）：

| kind | 渲染器 | 读取字段 | 实现位置 |
|---|---|---|---|
| `card` | `CardRenderer` | `title` / `subtitle` / `body` / `items[]`（截 12 条） | `extension-tool-renderers.tsx:137` |
| `table` | `TableRenderer` | `rows[]` / `columns[]`，未给列名则从行中推断（≤8 列 / ≤30 行） | `:160` |
| `form` | `FormRenderer` | `fields[]`，渲染成**只读** input | `:223` |
| `chart` | `ChartRenderer` | `data[{label,value}]`，横向条形，纯 CSS 无图表库 | `:245` |
| `html` | `ExtensionHtmlRenderer` | `manifest.renderers[name].entry` | `:114` |
| `component` | `ExtensionComponentRenderer` | `manifest.components[name].entry` | `:7` |

两路 HTML 最终都落到 `ExtensionAssetHtmlRenderer`（`:10`），这套是有讲究的：

| 能力 | 实现 |
|---|---|
| 隔离 | `<iframe sandbox="allow-scripts" srcDoc={...}>`，**无 `allow-same-origin`** ⇒ 插件拿不到父窗 origin |
| 取内容 | IPC `EXTENSION_READ_ASSET`，按插件根相对路径读；读不到显示 `Renderer not found` |
| 握手 | iframe 发 `{source, type:'ready'}` → 父窗回 `{type:'props', props}`（插件只拿 props，拿不到完整 result） |
| 高度自适应 | 初始 96，插件发 `{type:'resize', height}` → `clamp(80, 1200)` |
| 兜底 | 加载中一版、错误一版，都不白屏 |

**结论：零件是好零件，就是总闸没合。**

## 四、修法（两处，缺一不可）

1. **主进程产出包装**：插件工具结果 → `ExtensionToolResult`（`__wishfulClawExtensionResult: true` + `extensionId` + `text` / `data` / `ui`）
2. **渲染端实现解析**：`parseExtensionToolResult` 反序列化，校验 `__wishfulClawExtensionResult === true` 后才认，否则 `null`

只做 1 不做 2 仍然全空；只做 2 不做 1 则永远解析不到东西。

## 五、为什么值得做

- 现在插件工具想展示结构化结果，只有两条烂路：吐 JSON 让用户看一坨，或者吐 markdown 骗自己
- 6 种渲染器 + iframe 沙箱 + 高度协商已经付过成本，**沉没在代码里一分钱没回收**
- 后续任何带 UI 的插件（含将来的 CodeGraph 图谱画布）都卡在这个总闸上
