## 范围与功能单元（交付 31 条 / 刀 0 ~ 刀 42 / 51 个提交）

### 两件减法 + 一件治本（刀 0 ~ 刀 8）

- **S-321 死代码清理（刀 0，`dd617f82`）** —— 从 OpenCowork 整目录搬来、只搬到 lib 层没搬 UI 与主进程层的那批：宠物 1,250 行 + 翻译 746 行 + 14 条通道白名单残留。**必须在 S-318 之前做**：S-318 刀 2 原本要为「宠物 / 翻译用着多账号轮转」留兼容逻辑，而这两者都是死代码 ⇒ 先删它们，刀 2 才能把 `lib/auth/` 整目录清掉。三道核验不可跳：动态 `import()` 扫描、持久化 nav 值回落、打包产物字符串扫描。
- **S-318 公开面合规清理（刀 1 ~ 刀 5）** —— 5 个 preset 做的是同一件事：用用户自己的账号订阅、**冒充官方客户端身份**去走厂商只对自家客户端开放的 OAuth 通道。额度是用户自己的，但绕开了「只允许官方客户端使用」的限制。个人违反服务协议最坏是封号，做成产品对外分发是另一个量级（老大原话「如果我去抖音推广大家使用，有这个功能的话，会被腾讯这些直接告」）。
  - 刀 1 A 段（`7fc9647a`）：WorkBuddy 一系 4 文件整删 + 设置页「授权 AI 服务商」整页删 + C# `ApplyOAuthAccount` 整对删。整页删的前提已验证：`ProviderAuthPanel.tsx:200` 用 `isServerPollProvider` 过滤，全仓只有 WorkBuddy 两个 preset 是 `server_poll` ⇒ 不影响 Kimi / Copilot / Codex 的登录入口。
  - 刀 2 B 段（`e5e3dfa3`）：`codex-oauth` / `copilot-oauth` / `moonshot-coding` 三家 + `lib/auth/` 整目录清（刀 0 删掉宠物与翻译后，多账号轮转已无消费者）。**保留 `moonshot`（API Key 版）**。
  - 刀 3（`b24517e6`）：僵尸服务商记录显式剔除 —— `REMOVED_BUILTIN_IDS` 命中即连 `extraBuiltinRecords` 一起丢，悬空引用靠 `ensureBuiltinPresets` 拨正 + `getActiveProvider` 运行时回落兜底。**这条开工前是待定项**（剔除 vs 隐藏），取决于回落路径验不验得通 —— 验通了，所以剔除。
  - 刀 4 构建期硬拦截（随刀 1 / 刀 2 两批进 `scripts/after-pack-remove-files.cjs`）：`afterPack` 扫 `resources/`（含 `app.asar` 二进制），命中任一冒充证据串就 `throw` 中止构建。**扫的是产物不是源码** —— 只扫源码拦不住「下次顺手带回来」。
  - 刀 5 零命中收口：全仓复扫，只剩两处**设计必需**的命中 —— `REMOVED_BUILTIN_IDS`（剔除痕迹）与 `FORBIDDEN_MARKERS`（拦截器关键字表）。判据写清楚：关键字取「冒充证据」本身（客户端标识头 + 厂商内部端点），不取厂商名裸词，否则清理痕迹自己就成了假阳性。
- **S-324 `StripDataUrlPrefix` span 化（刀 6，`ebfdad75`）** —— 一张 600 KB 图复制两遍只为看前 64 字符。加零分配 span 版，`DetectImageMediaTypeFromBase64` 与 `ImageFileProbe.HasCompleteContainerInBase64` 改用它，**判据不变**；string 版留给三处真正要产 string 的调用点。排最前是为了先建立「改动不改行为」的信心。
- **S-323 `request_debug` 结构化裁剪（刀 7，`48223ea5`）** —— 每轮推完整 body，渲染层上限只有 4 KB ⇒ 99.97% 生成即丢。新增 `RequestDebugBodyTrimmer`（超 8 KB 的字符串值换占位、非法 JSON 退回硬截断、短 body 走快速路径），三个 provider 全接入。**不能硬截断** —— 调试面板要 `JSON.parse`，截断变非法 JSON 等于用「看不见」换「不卡」。
- **S-322 会话闲置淘汰（刀 8，`11994318`）** —— 「只涨不降」的真正根因：`SessionConversationManager` 永不淘汰，发过消息的会话各留一份完整 wire 副本（含图片 base64）到进程退出。补两条闸：闲置 **2h** 淘汰 + 常驻上限 **8 条**（超额按最久未访问砍）。安全性靠 `AgentLoop` 的 `MessageCount == 0` 从 DB 懒恢复；唯一会丢的是 status bar 的 cache hit/miss 累积计数，是展示指标不是数据。

### 欠账普查四轮（刀 16 ~ 刀 42，S-328 ~ S-351）

四轮扫描角度依次是「多余的东西」→「该有却没有的东西」，每一轮都纠正了我自己的一处方法错误。

- **只读审查五条（刀 16 ~ 19）** —— S-331 文档路径 4 处失效（`<br>` 先做这一刀因为它清视线）；S-332 renderer 层 8 处 `console.log`（其中一处打 `sshConnectionId`，是信息暴露不只是噪声）；S-330 删 4 具遗骸 + 拔掉一个从没打开过的英文空壳；S-329 补 500 行标记。**S-329 登记报「12 个无标记」实为 6 个** —— 扫描只认中文写法，漏了英文 `500-line exemption`，把三个大文件误判成无标记。
- **S-328 Agent 层手写 SQL 全族（刀 23 ~ 29，拆为 S-333 ~ S-338 六条）** —— 登记报「7 张表 12 处」，实测 **9 张表 30 处 / 9 个文件**（第一次机器扫用了不区分大小写的 `-match`，把 `multi-select questions` 当命中）。根因不是偷懒：Entity / Mapper 都在 Db 层且 Agent 正在用，**缺的是把两者粘起来的「表访问」那层** ⇒ 正是 S-326 A2 裁定的未尽面。刀序不能换：S-335 先立样板 → S-328 复用 → S-334 处理连锁语义 → S-333 跨层 → S-337 写入 → S-338 大表 → S-336 收尾删重复 SQL。**S-336 必须最后**，它要删的是 Db 层原来那份，前面没搬完就删等于毁掉唯一实现。收口后 **Agent 层 SQL 字面量归零**，判据写进 `AGENTS.md` §6。
- **欠账普查六条（刀 30 ~ 35，S-339 ~ S-344）** —— 大小写重名文件（ext4 上会出事）、**26 文件 2,460 行死代码**（实测净减 2,346，登记高估）、`ProjectTerminalDock` 空壳（核实**不是功能缺失**，开关本来就硬编码 `false`）、两个方向相反的空壳、一份后半段 3,928 字节是 GBK 的报告、主进程 58 处裸 `console.log`。
- **二轮普查三条（刀 36 ~ 38，S-345 ~ S-347）** —— 这轮换了角度才扫出东西：加扫「有没有该有却没有的东西」，立刻查出 `isBrowserToolName` 恒假桩让**一套写完的卡片 + 6 图标 + 7 摘要一次没渲染过**、图片生成「重试」按钮点了没反应（后端从未产出过那个状态 ⇒ 全删，不是接上）。顺带发现上一轮的扫描脚本只取文件前 3 行找标记，而规范位置在第 7~9 行。
- **三轮 dev 审查三条（刀 39 ~ 41，S-348 ~ S-350）** —— 浏览器卡片兜底回显工具名。**根因比 dev 转述的更值得修**：不是「8 个分支缺 1 个」，是 `primary: summary || title` 那个兜底本身 —— S-270 修过同一个病的另一侧，当时没顺手把它收了。所以这一刀不是补一个 if，是把兜底改成空串 + 按 8 个常量逐个过的测试。
