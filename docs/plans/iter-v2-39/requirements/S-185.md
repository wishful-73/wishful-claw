## 三、为什么要精简（现状勘察）

### 1. 这些文件被**原样**注入系统提示词

- `PromptBuilder.cs:15` 注释：Persona `.md` **as ContextDocuments（raw Markdown, not parsed fields）** ⇒ 文件里每一个字都会进上下文，**没有解析 / 提取**。
- 注入位置：`PromptBuilder.Build` → `BuildContextDocuments`（`:85-88` / `:182-221`），包在 `<persona> … </persona>` 里，顺序固定 **IDENTITY → SOUL → ONTOLOGY → AGENTS**（`:411-414`）。
- 只在 `PromptProfile.Main` 下注入（`:86`）。

### 2. **不是**被截断的问题 —— 是纯长度问题

- 预算 `DefaultCharacterBudget = 20_000` 字符（`PromptBuilder.cs:25`），**无任何调用方传入自定义值**（全仓核实）⇒ 恒为 20,000。
- 当前最大人格 3,939 字符，**远未触及预算** ⇒ **不会触发截断**。
- ⇒ 老大的「注意力超标」指的是**提示词整体变长导致指令遵从下降**，属真实且无法靠调预算解决的问题。**只能靠把文本写短。**

### 3. 精简空间主要来自**跨文件重复**，不是信息量

同一特质在 3~4 个文件里各说一遍（以 `lao-zheng` 为例）：

| 特质 | 出现的文件 |
|---|---|
| 「说话直 / 不废话 / 不客套」 | IDENTITY（外在印象）、SOUL（§核心性格、§沟通风格）、ONTOLOGY（§价值观「诚实 > 圆滑」）、AGENTS（§技术讨论优先） |
| 「不确定就说不确定 / 不装懂」 | SOUL（§核心性格）、ONTOLOGY（§诚实性）、AGENTS（§错误处理） |
| 「排版 / 格式洁癖」 | SOUL（§核心性格）、AGENTS（§排版与格式标准） |
| 「我是谁」自述 | IDENTITY（§一句话）、SOUL（§老郑是谁）、ONTOLOGY（§自我总结）—— **三处** |

⇒ **压缩手段 = 去重 + 去修饰**，而非删信息。

## 四、约束与红线（**意思不变**）

**必须保留**：

1. **四文件结构与分工** —— `IDENTITY`（人设 / 外在印象）、`SOUL`（性格 / 沟通风格 / 互动）、`ONTOLOGY`（认知 / 能力边界 / 价值观 / 诚实性）、`AGENTS`（行为协议 / 记忆边界 / 工具原则 / 错误处理）。
2. **所有硬性行为条款** —— 「永远不会做的事」清单、底线、原则、具体格式规则（如「不用感叹号」「中英文之间加空格」「代码块标语言」）、记忆写入边界。
3. **人格取向** —— 语气、判断倾向、价值观排序，**一律不动**。

**不允许**：

- ❌ 引入原文没有的新意思；
- ❌ 改变人格取向或性格强度；
- ❌ 为省字数把「行为约束」压成含糊表述；
- ❌ 改动文件结构（标题层级、章节划分）导致可读性变差。

**允许**：

- ✅ 合并跨文件的重复表述（保留一处最完整的）；
- ✅ 删修饰性废话、重复举例、可有可无的展开；
- ✅ 长句改短句、长段改列表。

## 六、风险与注意事项

1. **无自动化护栏** —— 内容改动逃过全部测试；复核不严就会把人格改瘸。
2. **用户可见的产品内容** —— 内置 preset 是用户直接选用的人格，精简会改变观感（老大已认可）。
3. **已发布版本不受影响，但回不去** —— preset 是 embedded resource，改文件即改产品；`v0.2.38` 及更早的用户仍用旧文本。
4. **⚠️ 项目目录里的副本不会自动同步** —— 用户经设置页「从全局复制到项目」落盘的人格（如本仓 `.wishful-claw/personas/` 下那 6 份）是**静态拷贝**，精简后**仍是旧文本**。⇒ 若期望存量副本也更新，需**另想办法**（不在本需求范围，登记备查）。
5. **`default` 人格最小（1,464）** —— 本就写得紧凑，**可压缩空间小**；精简时**该文件单独判断**，不必与其他拉齐。
