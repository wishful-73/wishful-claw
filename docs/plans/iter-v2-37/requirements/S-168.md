## 二、现象

S-156 落地后的实际形态（老大看了不认可）：

1. 入口在 `PersonaPanel` **头部**（「AI 创建人格」按钮），**不在**「新增人格」页面里。
2. `PersonaGeneratorDialog` 是**一条龙**：输入描述 → 生成 → 四段 tab 预览编辑 → **弹窗内直接保存落库**。与「新增人格」页面那条 `draft → 编辑 → 保存` 的通道**完全不相干**。
3. 生成用的模型**硬编码取全局激活** provider + `activeModelId`，用户无从选择。

⇒ 老大要的：入口在新增人格页面、弹窗只负责生成、结果**回填**到页面表单、模型可当场选。

## 四、根因

**不是 bug，是形态与预期不符。** 三条：

1. **入口位置**：挂在面板头部，而不是「新增人格」页面内。
2. **结果不回流**：弹窗自带保存，与 `PersonaEditor` 的 draft 通道是两条平行线。
3. **模型不可选**：弹窗硬编码全局激活；且因为传 `providerRole: 'global'`，即便弹窗想指定模型，C# 侧 `TryResolveExplicit` 也会直接跳过 ⇒ **要支持「当场改」，必须先把 `providerRole` 从 `'global'` 上摘下来**。

## 五、修复方向

老大 10:31 已对三个待定点下裁定：

| # | 待定点 | 裁定 |
|---|---|---|
| 1 | 模型怎么选 | **A+B** —— 弹窗出 provider + model 双下拉，**默认带出已配的**（读 `provider/completion-config-read` 的 `personaProviderId` / `personaModelId`，未配则回落全局激活），允许当场改 |
| 2 | 头部按钮 | **撤掉** |
| 3 | 弹窗职责 | **生成成功即回填**到新增人格页面；弹窗内的「预览 + 保存」拆掉 |

**落点（草案）**：

- `PersonaPanel.tsx`：删头部按钮与 `PersonaGeneratorDialog` 挂载；把「AI 辅助创建」按钮放进 `PersonaEditor`（仅 `isNew` 时显示），回调把生成结果 `setDraft(...)` + `setDirty(true)`。
- `PersonaGeneratorDialog.tsx`：删预览 / 保存两段，只留「描述输入 + 模型选择 + 生成」；成功后 `onGenerated(draft)` 回调并关闭；删掉内部 `savePersona`。
- 模型下拉：默认值从 `provider/completion-config-read` 取（`persona*Id`），改动后作为 explicit 传参 ⇒ **需去掉 `providerRole: 'global'`**。
- i18n：新增 key（「AI 辅助创建」「选择模型」等）zh / en 双份。

## 六、代价与取舍

（实施后回填；以下是登记时的预期）

- 撤掉头部按钮 ⇒ 已习惯从面板头部点的用户少一个入口，改为「先点新建人格、再点 AI 辅助」。**可接受** —— 生成本来就是为「新建」服务的，两条路合并成一条更顺。
- 弹窗内保存拆掉 ⇒ 生成后必须回到页面手动点「保存」。**可接受** —— 这正是老大要的「用户可以手动调整」，多一步是有意的。

## 七、刻意不做

（实施后回填；以下是登记时的预期）

- **不改 C# 解析顺序** —— `explicit → configured → fallback → global` 四档语义是对的，只是渲染端此前没走 explicit 这条路。只动渲染端传参，不动解析器。
- **不给「编辑已有人格」加 AI 按钮** —— 老大说的是「新增人格页面」。改已有人格是另一件事，没提就不做。

## 八、验证要求（实施时）

1. `npm run typecheck` 0 错误；`npm test` 全绿。
2. 真机：设置页 → 人格 → 新建人格 → 「AI 辅助创建」→ 输入描述 → 生成 → **内容回填到页面表单**（名称 / 标语 / 描述 + 四段）→ 手动改一处 → 点页面「保存」→ 列表出现新人格。
3. 模型下拉默认带出「模型管理」里配的 AI 生成人格路由；未配时回落全局激活模型；当场改后生成用的是改后的模型。
4. 面板头部**不再有**「AI 创建人格」按钮。
