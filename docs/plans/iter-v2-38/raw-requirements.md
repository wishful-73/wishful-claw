### S-178（2026-10-09 11:06，随 S-176 真机验收一并给出）

> 「然后记录一个新的bug 就是我本身当前软件设置的是 并行执行2个子agent 实际上你同时运行过5个，状态都是显示工作中，没有等待中，但是只有两个能展开看具体情况，所以我有点错乱，设置并行到底是什么情况」

⇒ 拆解与根因（已实读定位，非推测）见 [`requirements/S-178.md`](requirements/S-178.md) §二 / §四：

- **设置真生效**（`maxConcurrentSubAgents` 一路传到 `SubAgentConcurrencyLimiter`，三个执行点都取闸门）；
- **但排队信息从不回传** —— C# 侧只 emit `sub_agent_start` / `sub_agent_end` 与内容类事件，**从不 emit `sub_agent_queued` / `sub_agent_dequeued`** ⇒ 渲染端那套「Queued」UI 是**死代码**；
- **且 `sub_agent_start` 在取闸门之前无条件下发**（`SubAgentExecutor.cs:74-81` 早于 `:138` 的 `AcquireAsync`）⇒ 卡片「点亮」≠「真在跑」。
- **⇒ 限制器把 3 个挡在队列里 → 界面 5 张卡全显示「工作中」，只有真跑的 2 个有内容可展开。** 与老大观察逐条吻合。

### S-179（2026-10-09 11:26，随 S-178 规划期一并给出）

> 「再登记一个优化项 跟178有点息息相关 子agent的渲染卡片 没有追着贴底，滚动条一直在顶部」

⇒ 拆解见 [`requirements/S-179.md`](requirements/S-179.md) §二 / §三：

- **现象两句**：① 子 Agent 卡片**不追着贴底**；② **滚动条一直在顶部**。
- **「哪个滚动条」未坐实** —— 三个候选：**A** 卡片内的 240px 步骤列表（`SubAgentCard.tsx:90`，**无任何自动滚动逻辑**）/ **B** 详情面板转录（`SubAgentExecutionDetail.tsx:379` 的 `autoScrollToBottom` 绑 `isRunning`，为假时完全不贴底）/ **C** 聊天窗主滚动（更像 **S-176 残留**，非新问题）。
- **与 S-178 同源**：都是子 Agent 卡片的呈现 —— S-178 治「状态文字」，本条治「滚动跟随」。**建议排在 S-178 之后动刀**（排队态一旦可见，排队期 `isRunning=false`，会与候选 B 直接叠加）。
- **⇒ 待老大确认五项**（哪个滚动条 / 停住还是弹回 / 上滚后是否被拉回 / 无条件贴底还是带用户意图门闩 / 是否纳入 38）。

### S-180（2026-10-09 13:52，随 S-179 真机验收后一并给出）

> 「38 迭代再登记一个小 bug 或者说叫优化吧，就是我们的子 agent 本身是可以后台执行 也可以主会话等待执行的。后台执行的结束后会主动唤起主会话并输出结果。但是在测试过程中主会话 agent 好像不知道这个规则，然后在自己死等通过命令让自己强制活着等待这些」

⇒ **只读勘测已完成**（子 agent，41 tool calls / 16 iters，零代码改动），根因与缺失点见 [`requirements/S-180.md`](requirements/S-180.md) §三：

- **规则真实存在**：`background=true` 的子 Agent 完成后走「缓冲通知 → 渲染端 `use-background-subagent-wakeup` 以新 user 消息**重开主 run**」（`SubAgentExecutor.Background.cs:100-130` → `sub_agent_end` → `hooks/use-background-subagent-wakeup.ts:103-123`）。
- **但提示词里没写**：`Task` 工具对模型可见的描述/Schema **只在 C#** `TaskTool.cs:50-120`，`background` 参数（`:111`）与 Usage notes（`:74-77`）**都没有**「不要等 / 完成会自动通知」；`:77` 反而教「用 `SubAgentStatus` 查进度」，**把模型推向轮询**。
- **「会通知你」唯一出处在调用之后**：`SubAgentExecutor.Background.cs:208-209`（工具返回值占位符）⇒ 治不了「调之前就死等」的根。
- **⇒ 主 run 活着期间自己 sleep/轮询 = 纯空转。** 修法候选四条（甲 `TaskTool.cs` / 乙 `PromptBuilder.cs` `<tool_calling>` / 丙 返回文本强化 / 丁 零代码改 persona 或 `userRules`），待老大定夺。
