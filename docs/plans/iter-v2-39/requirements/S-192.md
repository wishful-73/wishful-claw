# S-192：用户点「停止」后，队列应自动派发下一条

> 状态：**已登记**（2026-10-13）；**口径待齐**（「停完自动续」的最终方案待裁定，见 §五）；**未开工**。
> 类型：**体验优化**（对既有「停完先确认再放行」语义的行为修订）。
> 归属：**iter-v2-39**（迭代定位 = bug 修复 + 体验优化 / 能力补充）。

---

## 一、原话 / 来源

老大 2026-10-13：

> 「还有需要登记一个问题，就是用户点击停止的时候应该停止后自动发送队列中下一条，而不是让用户去队列点继续发送」

---

## 二、现象

会话正在跑一轮，用户又排了几条消息进队列。此时点「停止」按钮：

- 当前这一轮被取消；
- **队列被一并冻住**，不会自动派发下一条；
- 用户必须去输入框上方的队列区手动点「继续发送」，队列才恢复派发。

**期望**：停止 = 只停当前这一轮，**停完立即自动派发队列里的下一条**，不需要用户再点一次。

---

## 三、静态定位（读码，未实机）

### 3.1 停止链路

| 环节 | 位置 | 行为 |
|---|---|---|
| UI 停止按钮 | `hooks/use-chat-actions.ts:280` `stopStreaming()` | `pausePendingSessionDispatch(sessionId)` + `cancelStream()` |
| 取消流 | `stores/chat-store/index.ts:541` `cancelStream()` | `:556` **再次** `pausePendingSessionDispatch(sessionId)` |
| 冻结 | `hooks/use-chat-actions.ts:840` `pausePendingSessionDispatch` | 把会话加入 `_pausedPendingSessionDispatch` |

### 3.2 冻结没有出口（根因）

派发入口 `dispatchNextQueuedMessageForSession(sessionId, resumePaused = true)`（`:889`）本身默认会解冻，**但所有自动派发路径传的都是 `resumePaused = false`**：

- `stores/chat-store/index.ts:1750`（loop_end 分支）：`dispatchNextQueuedMessageForSession(targetSessionId, false)`；
- `hooks/use-chat-actions.ts:958`（尾递归）：`dispatchNextQueuedMessageForSession(sessionId, false)`。

⇒ 会话一旦被冻，**任何自动路径都不会解冻**，队列停死。

`use-chat-actions.ts:847-867` 的 `resumePendingSessionDispatch` 注释**自述了这一点**：

> 「这个冻结**没有出口**：所有自动派发路径传的都是 `resumePaused = false`……所以冻上之后队列永远不会自己动起来；此前只有 UI 的「继续」按钮能解。」

### 3.3 定性

「停止后不自动续」**不是遗漏，而是既有设计**（「停完先确认再放行」的保护）。该函数是 **S-188 第三刀**（`689e031c`）为**全局 PM** 补的显式解冻出口 —— PM 没有输入框、点不到「继续」按钮。

⇒ 本条需求 = **用户侧不再需要那道确认**，即对既有语义的**修订**。

---

## 四、影响

- 用户每停一轮都要手动点一次「继续」，多一步操作，且容易被误认为「队列卡死」。
- 与 S-188 第三刀形成不对称：**PM 侧有 `resumePendingSessionDispatch` 出口，用户侧反而只剩按钮**。

---

## 五、修复方向（**待老大裁定**）

| 候选 | 内容 | 评价 |
|---|---|---|
| **A** | 停止链路不再冻结队列（去掉 `stopStreaming` / `cancelStream` 里的 `pausePendingSessionDispatch`） | 最直接；但需确认其它冻结来源（「未受理」`handleSendMessage`、派发失败重试）是否需要保留 —— 那两类是**故障保护**，与「用户主动停」性质不同 |
| **B** | 保留冻结，**取消完成后**显式 `resumePendingSessionDispatch(sessionId)` + `dispatchNextQueuedMessageForSession(sessionId)` | 只改停止链路，语义收敛、改动面最小 |
| **C** | 自动派发路径改传 `resumePaused = true` | 改动面最大，且会让「未受理」等保护一起失效，**不建议** |

**倾向 B**（停止链路自己收尾，不动全局派发语义）。**最终待裁定。**

## 六、验证方式（待口径齐）

- **实机**：跑一轮 → 排队 2 条 → 点停止 ⇒ 队列应**立即自动派发第 1 条**（无需点「继续」），派发顺序与内容不变。
- 边界：停 + 队列为空（不应报错）；停 + 队列仅 1 条；连续停两次。
