## 二、现象

1. **找不到设置位。** 老大在设置页里翻不到「图片生成模型」的配置入口 —— 不是记错，是**本来就没有显式设置位**：37 第 9 刀 S-166（`cc26da7e`）是**纯后端**（`image-endpoint.ts` + handler + 测试），零 UI 改动。
2. **唯一可用入口深且绕。** 现在只能「AI 服务商 → 选中服务商 → 模型列表 → 编辑模型 → 模型的使用方式 → 图像」（`ModelFormDialog.tsx:262-275`），即**靠给某个模型打 `category = 'image'` 来间接声明**，没有「选一个模型专门做生图」的地方。
3. **「正常模型能生成图片」这条路走不通。** S-166 本意是让对话模型自己产图像块，老大实测判定不可行（对话模型不产图像块）⇒ 必须回到**显式指定一个生图模型**。
4. **位置诉求明确。** 老大点名要放在「模型管理」页，**排除「AI 服务商管理页」**。

## 四、根因

**未确认**（登记时）。倾向判断：生图模型缺一个**独立的用途位数据源**，只能靠「某个 provider 的某个模型声明 `category = 'image'`」间接表达；而这个声明入口又落在老大明确排除的 AI 服务商页深处。⇒ 不是解析器写错了，是**指定位从来没有过**。

## 五、修复方向

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（倾向）** | 在「模型管理」tab 的 `ProviderCompletionSettingsPanel` 加**第四档用途位「图片生成」**（服务商 + 模型），与既有三档同形；`ProviderCompletionSettings` 增 `imageProviderId` / `imageModelId`；生图解析优先读它，读不到再走 S-166 的三级回落。**该位的模型下拉放宽到 `category === 'image'`**（现役过滤只列 chat） | 动渲染端表单 + 共享类型 + C# 配置读写与解析器取值源；四级回落链多一层 |
| B | 不动用途位，只把「使用方式 = 图像」的声明入口从 AI 服务商页**搬到**模型管理页 | 改动小，但没解决「选一个模型专门生图」的诉求，仍靠逐模型打标 |
| C | 给 `managedModels` 加 `purpose` 字段，模型管理页按用途位分组 | 动全局模型库语义，影响 provider 副本继承逻辑，面最大 |

**老大裁定（2026-10-08 13:40）：走 A。** ⇒ 在「模型管理」tab 的 `ProviderCompletionSettingsPanel` 加**第四档用途位「图片生成」**（服务商 + 模型），与现役三档同形。

## 六、代价与取舍

（登记时的预期，实施后回填）

- 预期代价：`ProviderCompletionSettings` 结构扩容要同步 **C# 侧的读写与消费方**，两侧不一致时会出现「UI 选了、Worker 没读到」的静默失效 —— 验证时必须真机跑一次生图确认取值链打通。
- 预期取舍：显式指定位**优先于** S-166 的「跟随当前对话 provider」，即用户显式指定后不再自动跟随。
