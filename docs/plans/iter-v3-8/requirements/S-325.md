## 二、B1 · 章程描述了一个已被删掉的项目

`WishfulClaw.CodeGraph` 已在 **v3-iter-6（S-303）剥离为独立仓库 + 可选插件**，`src/runtime/` 下已无该项目。但文档三处仍当它存在：

| 位置 | 原文 | 实际 |
|---|---|---|
| `AGENTS.md:25` | 「另有 `src/runtime/WishfulClaw.CodeGraph` vendored 项目（不参与 7 层依赖链，仅被 Worker 引用）」 | 项目不存在 |
| `docs/project-structure.md:30-31` | 「`WishfulClaw.CodeGraph/` # 0. CodeGraph 引擎（vendored 自 github.com/AIDotNet/CodeGraph；不参与 7 层依赖链，仅被 Worker 引用）」 | 同上 |
| `docs/project-structure.md:56` | 「`Agent/Tools/Providers/` 是**工具提供者**（AskUser / Browser / Cron / **CodeGraph**…）」 | 该目录 25 个 Provider 里无 CodeGraph |

**为什么这条必须单独登记**：这两份文档是「东西在哪」的索引。照 `AGENTS.md:25` 去找 `src/runtime/WishfulClaw.CodeGraph` 的人，会白花时间确认它不存在，然后怀疑整份文档的可靠性。

**注意区分**：`src/` 里仍有大量 `CodeGraph` 字样（`src/main/lib/codegraph-assets.ts`、`src/main/ipc/codegraph-handlers.ts` 等），那是**插件资产下载器**（S-303 剥离后的正常形态：按需下载引擎与语言包），**不是残留，不要删**。

## 三、B2 · Agent 层的依赖清单漏了 Workspace（且走的是隐式传递引用）

章程 `AGENTS.md:81` 写 Agent 依赖「Contracts + Core + Infrastructure + Persona」，**没写 Workspace**。

实测 Agent 项目里 **10 个文件** `using WishfulClaw.Workspace`：

```
AgentLoop.MemoryRecall.cs          SystemPromptCache.cs
ToolModuleState.cs                 Tools/ToolModule.cs
Tools/MemoryTools/MemoryAppendTool.cs        Tools/MemoryTools/MemoryHotReadTool.cs
Tools/MemoryTools/MemoryHotWriteTool.cs      Tools/MemoryTools/MemorySearchTool.cs
Tools/MemoryTools/MemoryToolHelpers.cs       Tools/MemoryTools/MemoryUpdateTool.cs
```

> 登记时写的是 9 个，实施时实测 10 个 —— 漏掉的是 `MemoryUpdateTool.cs`。这份清单不写死数字更稳，但写死能一眼看出规模，故保留并标注实测值。

它能编译，是因为 `WishfulClaw.Agent.csproj` → `Persona` → `Workspace` 的 **ProjectReference 是传递的**。

**按依赖方向图判定，这条边合法**（`Contracts → Core → Infrastructure → Workspace → Persona → Agent`，Workspace 在 Persona 之下，不是逆向）。所以：

- **不是代码违规**，是**章程清单漏写**
- 但隐式传递有实害：**哪天 Persona 不再引用 Workspace，Agent 会莫名其妙编译不过**，而改动 Persona 的人不会想到会连坐 Agent

建议在 `AGENTS.md:81` 显式写上 Workspace，并在冒号后注明「经 Persona 传递，非直接 `ProjectReference`」，把这条隐式边变成公开事实。
