## 2. 现象

S-352 在 `plan.md` 里被标成「刀 0~3 已交付，代码收口」，`raw-requirements.md:14` 更进一步写「`supportedMediaKinds` 留空、**自动降级发文本**，这是正确结论，不是失败」。实读下来有四处**没有真正生效**：

| 子项 | 现象 |
|---|---|
| **D-1** | `channel-media.ts`（降级链路的唯一实现）**全仓零 import**。所有 handler 直连 `service.sendMedia(...)`，媒体不支持时走的是 `throw`，不是「退避发文字」 |
| **D-2** | `ChannelSendAudio` 在钉钉 / Discord / QQ / Telegram / 企业微信 / WhatsApp 六个渠道**可见可调**，但一调就报 `Unsupported channel plugin tool` |

## 3. 代码链路（2026-11-11 实读）

### 3.1 D-1：降级链路是孤儿文件

```
=== who imports channel-media ===
(empty = nobody imports it)
```

`sendMediaOrText()` / `supportsMediaKind()` 除自身内部互调外无调用方。

而调用点全是直连：

| 调用点 | 写法 |
|---|---|
| `channel-weixin-handlers.ts` 三处（send-image / send-file / send-audio） | `await service.sendMedia(...)` |
| `channel-feishu-handlers.ts` 三处 | `await service.sendMedia(...)` |
| `executeWeixinChannelTool` / `executeFeishuChannelTool` | 同上 |

媒体不支持时的实际终局：
- `weixin-outbound-media.ts:111` —— `throw new Error('Weixin does not support outbound media kind: ...')`
- `feishu-outbound-media.ts:80` —— 同构的 `throw`

**⇒ 老大 10:46 拍的「退避发文字」在代码里没有生效点。**

### 3.2 D-2：可见性不区分渠道类型，路由只认两家

| 位置 | 行为 |
|---|---|
| `ChannelPluginToolProvider.cs:35` | `ChannelSendAudio` 无条件注册，`visibleScopes: ChannelOnly` |
| `ToolVisibilityScopes.cs:17` | `ChannelOnly = ["*:channel@*"]` —— **所有渠道会话都可见** |
| `AgentRuntimeChannelPluginExecutor.cs:119-123` | `ResolveGenericRoute` 只认 weixin / feishu，其余返回 `null` |
| `AgentRuntimeChannelPluginExecutor.cs:54-55` | `null` ⇒ `Unsupported channel plugin tool: ChannelSendAudio` |

`ChannelSendImage` / `ChannelSendFile` 早有同样问题（v1.0.8 之前），本迭代把同一个坑复制到第三个工具上。

### 3.3 D-3：注释与代码各说各话

`feishu-outbound-media.ts:71-77`：

```ts
// 飞书只认 opus；文件名强制 .opus，否则 uploadFile 的 file_type 与扩展名不一致
const { buffer } = await readBinarySource(media.source, 'audio.opus')
const fileName = media.fileName ?? resolveSourceFileName(media.source, 'audio.opus')
const fileKey = await api.media.uploadFile(buffer, fileName, 'opus')
```

`audio.opus` 只是**推断不出名字时的兜底**。传 `/tmp/x.mp3` ⇒ `fileName = 'x.mp3'` ⇒ `uploadFile(buf, 'x.mp3', 'opus')`，正是注释说要避免的那种不一致。

### 3.4 D-5：零测试

```
=== tests covering new channel media ===
(empty)
```

`inferVoiceEncodeType`（`weixin-outbound-media.ts:28-48`）是纯函数、8 个分支、零 IO、零依赖 —— 最该补也最便宜。且 `opus → OGG_SPEEX` 映射本身是推断（`:25-26` 自认「若真机上 opus 播不出来，先来改这一行」）。

## 4. 根因

**四条是同一个根：S-352 的验收口径停在「代码写完了」，没有一条判据要求「行为被调用到」。**

- D-1：新模块写好了，但没有一个调用点被改过来 —— 而刀 1 的验收只看了 typecheck + 测试通过，测试也没覆盖它（D-5），于是全绿。
- D-2：注册期和路由期是两个文件，谁都没错，合起来错。
- D-3：注释写的是**意图**，代码写的是**实现**，中间没人对照。
- D-5：新增代码没有「必须带测试」的门槛，`npm test` 仍然 130/130 —— 因为**它统计的是已有用例，不是覆盖率**。

这与 v3-iter-7 的迭代标题「零件全在，线没接」是同一个病，第二次犯。

## 5. 修复方向

### 5.1 D-1 —— 二选一，不能都不做

1. **接线**：handler 改走 `sendMediaOrText(service, chatId, media, fallbackText)`；`fallbackText` 必须是**有意义的内容**（说明「对方渠道发不了这种媒体」），不能是占位符 —— 这是 `channel-media.ts:46-47` 自己的要求。
2. **改文档**：把 `plan.md:38`、`plan.md:37`、`raw-requirements.md:14` 三处的「已交付 / 自动降级」改成「接口已就绪，尚未接线，降级行为未生效」。

倾向 **1**，因为 10:46 的裁定是行为要求，不是接口要求。

### 5.2 D-2 —— 注册期收窄

`ChannelPluginToolProvider` 目前不感知渠道类型。两条路：

- **A（小）**：`ResolveGenericRoute` 保持现状，但在注册期按「当前渠道是否支持该媒体形态」决定是否注册 `ChannelSendImage/File/Audio`；
- **B（大）**：`ToolDispatchRouter` 对 unsupported route 做「不可见」而非「调用后报错」。

倾向 **A**：与 S-352 刀 4~8「其余六家不做」的结论一致，改动面小。

### 5.3 D-3 —— 二选一

1. 真做强制：`fileName = path.basename(fileName, path.extname(fileName)) + '.opus'`；
2. 注释改成实话：飞书侧会拒，不做兜底。

倾向 **2**：强制改名会让「发了一段 mp3 但飞书收到 opus 标签」的错误更难查。**错要错得清楚。**

### 5.4 D-5 —— 补测试

新增 `tests/channel-media/`：

- `inferVoiceEncodeType` 8 个后缀各一条 + 未知后缀回落 SILK；
- `sendMediaOrText` 两条分支：支持 ⇒ `sentAs` 为 kind 且不调 `sendMessage`；不支持 ⇒ `sentAs === 'text'` 且调了 `sendMessage`。

约 30 行，纯函数无 IO，跑得很快。

## 6. 代价与取舍

- **D-1 接线**会让「媒体发不出去」从「报错」变成「悄悄发一条文字」。需要确认 `fallbackText` 的内容形态：是「原消息正文」还是「说明发不了」。倾向**原消息正文 + 一句说明**，否则用户只看到一句没头没尾的话。
- **D-2 方案 A** 需要 `ChannelPluginToolProvider` 拿到当前渠道类型 —— 要确认注册期是否已经有这个上下文，没有就要新传一个参数。
- **D-3 选 2** 意味着接受「飞书拒 mp3」这个现状，用户体验上要给出可读的错误。

## 7. 刻意不做

- **不改 `ChannelSendImage` / `ChannelSendFile` 的既有行为** —— 它们的 D-2 同类问题不属本单，避免一单动三处。
- **不补飞书 / 微信以外六家的媒体实现** —— 无凭证，S-352 刀 4~8 已裁定不做。
- **不动 `plan.md` 刀序表** —— 等 D-1 选定「接线」还是「改文档」之后再改，否则等于把一个假结论换成另一个假结论。
