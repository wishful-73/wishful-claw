### 8.1 一个必须提前认清的机制

C# 的命名空间解析**只在父链上自动查找**。文件写在 `namespace WishfulClaw.Agent.Tools;` 里，向上找的是 `WishfulClaw.Agent` → `WishfulClaw` → 全局 —— **不会**找到 `WishfulClaw.Agent.Executors`。

⇒ 移进子目录并改 namespace 后，**每一个引用该类型的文件都要补一行 `using`**，包括原本就在 `WishfulClaw.Agent` 下的文件（它和新的 `Executors` 是兄弟而非父子）。

这就是为什么 198 而不是 61。

### 8.2 前端零影响（已核实，不用动）

全仓 TS/TSX 里 101 处 `AgentRuntime` 命中，全部是**同名但无关**的东西：

- `registerNativeAgentRuntimeHandlers` / `[NativeAgentRuntime]`（`src/main/ipc/native-agent-runtime.ts`）—— Electron 侧 native agent 运行时，与 C# 类名无关
- `const agentRuntime = useAgentStore(...)`（`composer-status-indicator.tsx` 等）—— 就是个局部变量名

⇒ **前端一行不改**。这条基线是为了防止「看到 101 处就以为要动前端」的误判。
