# S-181：JsonHelpers.GetBool 不认字符串化布尔 —— `background:"true"` 静默回落前台

> 状态：**已实施**（2026-10-09）。口径（老大 14:37）：「**JsonHelpers.GetBool 对 "true"/"false"（含首尾空白）做宽松解析 处理这个吧**」⇒ 采纳推荐方案**乙**。计划见 [`../plan-s181/plan.md`](../plan-s181/plan.md)。**随 S-180 在 2026-10-09 真机复验通过。**
> 类型：**缺陷**（工具参数解析宽容度不足 ⇒ 类型不符时**静默**走错分支，无任何告警）。
> 来源：2026-10-09 13:52「主 agent 死等后台子 agent」报障的排查结论 —— **S-180 无效复验的直接动因**。

## 一、原话 / 来源

> 「JsonHelpers.GetBool 对 "true"/"false"（含首尾空白）做宽松解析 处理这个吧」

## 二、现象

调用方把布尔参数序列化成**字符串**（`"true"` / `" false "`）传入时，`JsonHelpers.GetBool` **静默回落 `fallback`** —— 不报错、不告警，调用方拿到 `false`，走错分支。

落到 S-180 的现场：`Task` 工具的 `background` 写成字符串 `"true"`，`GetBool` 回落 `false` ⇒ 子 Agent 走**前台**执行 ⇒ 主 Agent 被阻塞 **49.2 s / 59.5 s**，而规划上它「本该」立即返回、结束后被自动唤醒。

## 三、根因（实读定位）

`src/runtime/WishfulClaw.Core/Protocol/JsonHelpers.cs:16-28`：

```csharp
public static bool GetBool(JsonElement element, string name, bool fallback)
{
    if (element.ValueKind != JsonValueKind.Object || !element.TryGetProperty(name, out var property))
    {
        return fallback;
    }
    return property.ValueKind switch
    {
        JsonValueKind.True => true,
        JsonValueKind.False => false,
        _ => fallback   // ← "true"（字符串）、1、"True"、null 全落这里
    };
}
```

只认 `JsonValueKind.True` / `JsonValueKind.False` 两种**原生布尔**；字符串一律 `fallback`，**静默**。

### 证据（dev 库，会话 `9JffXuOXIrsfqGLXRYy92`）

| 项 | 值 |
|---|---|
| tool call `call_e66df7601636410bb88eb30e` | `{"description":"后台连跑三十条回显","prompt":"…","subagent_type":"custom","background":"true"}` |
| tool call `call_efb0dbf6c45d4d92b4c4019e` | `{"background":"true","description":"后台慢速测试",…}` |
| `agent_timeline_events.run_id` | **无 `-bg-` 前缀**（前台 = `subagent-{id}`；后台 = `subagent-bg-{id}`） |
| 两跑耗时 | **49.2 s / 59.5 s**（前台阻塞，非占位返回） |

⇒ 模型把布尔写成了**字符串**；类型不符 → 回落 → 前台。透传链路（`UseCapabilityExecutor:291-336` → `ToolDispatchRouter:512` → `SubAgentExecutor.ExecuteAsync`）逐段核过，**是通的**，问题只在**值类型**。

## 四、影响面

`JsonHelpers.GetBool` 改动前全仓共 **42 处调用点**（`src/` 42、`tests/` 0，27 个文件；本条新增 1 处测试调用后为 43）。改动方向一致（原本落 `fallback` 的现在能正确识别），**全部受益，无一处会改坏**：

| 输入 | 改前 | 改后 |
|---|---|---|
| 原生 `true` / `false` | 正确 | **不变** |
| 字符串 `"true"` / `" false "` / `"TRUE"` | 回落 `fallback` | **正确解析** |
| 字符串 `"yes"` / `"1"` / 空串 | 回落 | **仍回落** |
| 数字 `1`、对象、数组、`null` | 回落 | **仍回落**（**不扩大到**数字/其他类型） |
| 属性缺失 / 非 object | 回落 | **不变** |

已见调用点示例：`MediaFileTools.cs:37`（`deleteWhenDone`）、`AgentChangeTools.cs:211`（`beforeExists`）、`PathBoundary.cs:49`。

## 五、方案（已采纳乙）

| 方案 | 做法 | 评价 |
|---|---|---|
| 甲 | `Task` 工具侧校验类型不符即报错 | 只覆盖一个工具，其余 40 处照旧静默回落；**不采纳** |
| **乙（采纳）** | `JsonHelpers.GetBool` 加 `JsonValueKind.String` 分支：`Trim()` 后**大小写不敏感**匹配 `true` / `false`，其余仍回落 `fallback` | 一处修复覆盖全部调用点；改动窄、无行为倒退 |
| 丙 | 只改 schema 描述、提醒模型别写字符串 | 治标，模型行为不可控；**不采纳** |

**边界（写死免得下轮走回去）**：只识别 `true` / `false` 两词（含首尾空白、任意大小写），**不做** `yes/no` / `1/0` / `on/off` 的等价扩展 —— 老大口径就是这两个词。
