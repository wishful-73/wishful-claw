# S-136 · agent 回复操作栏「分叉」按钮点击必报失败（功能整体缺失）

- 2026-09-22：**老大提出**（原话：「agent回复板块有个 分叉按钮 以及收起的里面有个语音朗读，这个好像漏了」）。经澄清，「漏了」指**登记漏了**，不是代码漏了 —— 老大原话：「漏了 指的是登记漏了，没看到你的需求登记项」。同句里的「语音朗读」已单独定性在候选池（⏸ 暂不处理）。

**现象**：agent 回复气泡的操作栏「分叉」按钮 + 收起菜单里的同名项都在，**点了必弹「分叉失败」**，无其它反应。

**现状勘测（2026-09-22，根因已定位）**：

- **UI 在**：`src/renderer/src/components/chat/AssistantMessage/action-bar.tsx`（`AssistantActionBar`，分叉按钮约 `:188-193`）。
- **文案在**：`src/renderer/src/locales/zh/chat.json` 的 `messageActions.fork` =「分叉」、`messageActions.forked`、`messageActions.forkFailed` =「分叉失败」。
- **唯一缺口**：`src/renderer/src/stores/chat-store/session-slice.ts:43` 只有**可选类型声明**：

  ```ts
  forkSessionFromMessage?: (sessionId: string, messageId: string) => Promise<string | null>
  ```

  **全仓无实现体** ⇒ `useChatStore` 取出恒 `undefined` ⇒ `?.()` 短路 ⇒ `?? null` ⇒ `!forkedSessionId` ⇒ **必然 `toast.error(t('messageActions.forkFailed'))`**。

**可复用件**：

- **本地**：`session-slice.ts:477-498` 的 `duplicateSession` —— 整会话复制（`{ ...session, id, title: '${title} (copy)', messages: 重 id }` + `dbCreateSession` + `setActiveSession`）。分叉 = 「复制**到某条消息为止**」的变体。
- **参考**：OpenCowork `src/renderer/src/stores/chat-store.ts:4280-4331` 的 `forkSessionFromMessage` —— `loadSessionMessages` → 定位 `messageIndex` → `cloneMessagesForNewSession(messages.slice(0, messageIndex + 1))` → 构造新 Session（继承 `title` / `icon` / `mode` / `projectId` / `workingFolder` / `sshConnectionId` / `providerId` / `modelId`）→ `set`（push + `activeSessionId` = newId）→ `dbCreateSession` + **逐条 `dbAddMessage`** → 清 task / plan store → `syncSessionScopedState(newId)` → 返回 newId。

**待裁定**：

1. **新会话标题**：沿用源标题（OpenCowork 做法）还是加后缀区分（如本地 `duplicateSession` 的 `(copy)`）？
2. **消息落库方式**：`duplicateSession` **只调 `dbCreateSession(copy)`、不逐条写消息** —— 需先核实 wishful-claw 的 DB 层是否会自动落消息。若不会，则 `duplicateSession` 本身就有「DB 里会话存在但消息为空」的隐患，分叉实现必须照 OpenCowork **逐条 `dbAddMessage`**。**实施前必须先核实这一条。**

**体量**：小（一个 store 函数 + 一处接线）。

**独立性**：纯前端 store 层，不依赖 S-135 / S-137，可独立实施。
