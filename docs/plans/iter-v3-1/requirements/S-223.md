# S-223：dev 实例的项目级数据目录与生产隔离

## 1. 原话 / 来源

> 2026-10-23 17:02 老大：

性质：**工程基建**（运行态隔离），对打包版零行为变化。

## 2. 目标

一句话：**dev 实例在项目里写的数据，落到 `{工作区}/.wishful-claw-dev/`，不再与生产实例共用 `{工作区}/.wishful-claw/`。**

动机：我在 dev 实例上跑任务调试，会往项目里写计划、目标、项目记忆、生成图、codegraph 索引。生产实例（打包版）跑同一个项目时读的是同一个目录 ⇒ 我的调试产物污染了项目的真实记忆。

### 3.3b 共用常量的陷阱

`project-archive-helpers.ts:42` 的 `WISHFUL_CLAW_DIR` 被 `ProjectArchivePage.tsx` **两种用途共用**：

- `:82` `joinFsPath(home, WISHFUL_CLAW_DIR, 'projects', id)` —— **全局**，不能跟着项目级走
- `:85` `joinFsPath(workingFolder, WISHFUL_CLAW_DIR)` —— 项目级，要改

⇒ 只换常量的值不够，`:82` 必须显式改回 `WISHFUL_CLAW_DATA_DIR_NAME`。

## 4. 方案

### 4.1 单一判定源：由 Electron 主进程算好，注入子进程

不重复推导 `app.isPackaged`（C# worker 看不到它）。主进程已有一个判断点，就把结果顺着已有的注入通道传下去：

- `native-worker.ts` 的 `workerEnv`（`:183-187`）**新增**
  `WISHFULCLAW_PROJECT_DIR = app.isPackaged ? '.wishful-claw' : '.wishful-claw-dev'`
- 渲染端拿不到 `app.isPackaged`，由 preload 暴露同一个值（或在 `shared` 里用 `import.meta.env.DEV` 判断，plan 阶段二选一，按现有 preload 常量惯例定）

### 4.2 C# 侧：常量改为可解析，回退保持原值

```csharp
// WishfulClawDataDir（Infrastructure）
public static string ProjectDirName =>
    Environment.GetEnvironmentVariable(WishfulClawPaths.ProjectDirEnvVar)?.Trim()
    is { Length: > 0 } configured ? configured : WishfulClawPaths.DataDirName;

public static string ProjectRoot(string workingFolder) =>
    Path.Combine(workingFolder, ProjectDirName);
```

`WishfulClawPaths.DataDirName` 常量**保留不动**（CodeGraph 全局路径与回退值都依赖它），新增 `ProjectDirEnvVar`。

### 4.3 三处边界写死

- **不做迁移** —— dev 已在项目里写的 `.wishful-claw/` 留在原地，不搬、不读、不删
- **不自动追加项目 `.gitignore`** —— 老大明确只要隔离，这个已有缺口另记
- **不改全局目录口径** —— `~/.wishful-claw` / `~/.wishful-claw-dev` 一切照旧

## 5. 范围外

- 迁移历史 dev 数据（老大 17:04 明确不要）
- 向用户项目 `.gitignore` 自动追加条目
- `out/` 构建产物隔离（讨论过，老大 17:02 明确不要）
- `docs/` 里 `~/.wishful-claw` 的既有表述（全局口径不变）

## 6. 风险

| # | 风险 | 处置 |
|---|---|---|
| 1 | 渲染端与 worker 判定口径不一致 ⇒ 一半写 A 一半写 B | 判定只在主进程算一次，其余全部拿注入值；阶段六实测两边落盘路径一致 |
| 2 | `ProjectDirName` 被误用于全局路径，导致 `~/.wishful-claw-dev-dev` | 全局两处（`WishfulClawDataDir.cs:17`、`CodeGraphDataDir.cs:56`）保持用 `DataDirName`，审查逐行核对 |
| 3 | 环境变量未注入时静默回退到 `.wishful-claw` ⇒ dev 又污染生产 | 回退是刻意的（打包版正常路径）；阶段六用 dev 实例实测目录名确认为 `-dev` |
| 4 | dev 数据目录不会被用户 `.gitignore` 挡住，出现在 `git status` | 已知缺口，不在本需求处理；本仓库 `.gitignore` 需补一行 |
| 5 | 提示词文案随目录名变化 | 预期变化，非缺陷；`task-board-store.ts:104` 走同一个常量 |
