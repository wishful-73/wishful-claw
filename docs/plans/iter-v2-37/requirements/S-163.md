### 6.1 落点与篇幅

### 6.2 结构（十一节）

定位与用法 → 配色（两层结构 / 32 个语义 token 逐个写角色与禁区 / 面板与工作区 token / SSH 调色板 / 终端主题）→ 字体 → 间距 → 圆角 → 尺寸 → 层次与景深 → 动效 → 无障碍与国际化 → **`Do`（10 条）** → **`Don't`（10 条）**。

### 6.3 写作口径（按 §四 裁定「只梳理现有」）

- 每条 token **标出处行号**（`main.css:50-53`、`studio.ts:27-96` …），§五.1「每条 token 必须能在代码里找到对应」按此满足。
- **未引入任何新设计** —— 所有值都是从代码读出来的现状；「这里应该改成 X」这类建议一律不写（那属于「调整」，不在本条范围）。
- 查证中确认并首次成文的**三条结构事实**：
  1. `--radius` 只定义在 `:root`、**不在预设 `cssVars` 里** ⇒ 圆角不随配色预设变；
  2. 面板 / 工作区 / composer 那批 token **没有 `--color-*` 映射** ⇒ 不能当 Tailwind utility 用，只能 `var()`；
  3. `html { font-size: var(--app-font-size) }` ⇒ **全站 rem 随用户字号缩放**，写死 px 的尺寸会卡住不跟随。
- `Do` / `Don't` 全部由上述事实推导，不写泛泛之谈 —— 例如 Don't 第 4 条（`@layer base` 外禁写通配符）直接来自 `main.css:285-288` 记录的 iter-30 踩坑。

### 6.4 刻意不做

- **不动任何样式代码**（§四 裁定「调整不着急」）。
- 未覆盖 **Markdown 字阶**与**组件级尺寸矩阵**（按钮 / 输入 / 对话框各自的 padding 与高度）—— 代码里还没有统一口径，硬写等于替产品拍板，留到「调整」阶段。

### 6.5 门禁

纯文档改动，无代码变更 ⇒ 不跑构建。排版按 §五.2 自查：表格对齐、代码块带语言标识、中英文间空格。
