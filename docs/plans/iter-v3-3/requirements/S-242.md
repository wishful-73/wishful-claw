## 2. 目标

主程序**内置一张资产目录**（id → 名称 / 用途 / 体积 / 哈希 / 下载源）。插件只报 id，用户点一下「启用并下载」，我们自己知道去哪拿。

**成品三件**：

1. **内置目录** —— 主程序侧的表，插件看不见 URL
2. **下载器** —— 续传 / 校验 / 进度 / 重试 / 多源回退
3. **用户看得见** —— 插件卡片上先报体积再让点

## 3. 现状（2026-10-27 实读源码）

### 3.1 「资产」这件事有先例，但明确没有下载

`src/main/lib/codegraph-assets.ts` 开头注释写死：

```
// CodeGraph grammar assets (bundled only — no online download).
```

它做的是「**本地目录探测 + 状态诊断**」（`CodeGraphAssetStatus` / `CodeGraphAssetDiagnostic` 七种状态），**没有任何网络下载代码**。

⇒ 状态机设计可参照，下载器要从零写。

### 3.2 `requiresDownload` 是死字段

`src/renderer/src/lib/app-plugin/types.ts:61` 声明了 `requiresDownload?: boolean`，**全仓唯一消费点** `AppPluginPanel.tsx:174`：

```ts
if (descriptor.requiresDownload && !isCodeGraphReady) return 'not_ready'
```

读的是 codegraph 自己的 `requiresDownload: false` ⇒ **该分支永不成立**。这是「资产未就绪」概念存在过的痕迹，但从未实现。

### 3.3 现有下载代码只有自动更新

`src/main/updater.ts` 走 electron-updater，与插件资产无关，不可复用。

## 4. 落点

### 4.1 内置资产目录（主程序侧，插件不可见）

新增 `src/main/plugins/plugin-asset-catalog.ts`：

```ts
export interface AssetCatalogEntry {
  id: string            // 全程序唯一键，带命名空间：'asr/qwen3-asr-0.6b'
  name: string          // 用户看到的名称
  desc: string          // 一句话用途（下载前要给用户看）
  kind: 'binary' | 'model' | 'data'
  size: number          // 字节。用户点之前必须看到这个数
  sha256: string
  urls: string[]        // 多源按序试，第一个通的就下
}
```

**内置，不搞远端热更** —— 老大 14:19：「路径过期那是以后的事情」。换源就改表发版。

> ⚠️ **表内容 TODO 实测**：本号**只落表的结构与查找逻辑**，第一批条目（QwenASR exe / 模型）的 `size` 与 `sha256` **必须等拿到真实文件后实测填写**。文档与代码里一律写 `TODO 实测`，**不许先填估算值** —— 假的哈希比没有哈希更危险（校验永远失败，用户看到「损坏」）。

### 4.2 资产落共享区，不落插件目录（**改口径**）

原方案 `dest: "bin/qwen-asr.exe"` 相对插件根 —— **作废**。理由：

| # | 问题 |
|---|---|
| 1 | 插件更新一版目录一换，500 MB 模型**白下**，用户会骂人 |
| 2 | 两个插件要同一个模型时**各存一份**，磁盘翻倍 |
| 3 | 卸载插件时**不敢删**（可能是别人还在用的）⇒ 又变成垃圾 |

改为**主程序共享资产区**，按资产 id 存：

```
%APPDATA%/WishfulClaw/plugin-assets/
  asr/
    qwen-asr.exe
    qwen3-asr-0.6b/
      ...
```

- 插件更新 → 资产不动，秒过
- 多插件共用同一资产 → 下一份
- 插件卸载 → **不删**（S-244 会改为独立清理入口，见该文 §4.2）
- `.part` 临时文件同目录，完成后改名

### 4.3 状态机

```
absent → queued → downloading(%) → verifying → ready
                        ↓                ↓
                     failed ←  retry  ← failed
```

`ready` 判据：**文件存在 ∧ 大小一致 ∧ sha256 一致**（三样缺一不算就绪）。

### 4.4 实现要点

| 项 | 做法 |
|---|---|
| 多源回退 | `urls[]` 按序试；一个源连不上 / 返回非 200 / 中途断且不可续 → 换下一个，**前一个的 `.part` 不清**（下次还能续） |
| 断点续传 | HTTP `Range` + `.part`；服务端不支持 Range 则整下重来（记该源不支持） |
| 校验 | 流式 sha256（边下边算，不整文件读内存），完成后比对目录表 |
| 进度 | 节流推事件（≥ 200 ms 或 ≥ 5% 才推），避免刷爆 IPC |
| 重试 | 单源内指数退避最多 3 次，再换源；全源失败报最后一条错 |
| 并发 | 同一资产单实例（加锁）；不同资产最多 2 并发 |
| 取消 | 用户可取消，保留 `.part` |
| 已就绪快查 | 每次 `status` 只做**存在性 + 大小**检查，不重算 sha256（否则每次开面板都要卡几秒） |

### 4.7 对插件的暴露

```ts

  list(): Promise<AssetStatus[]>        // 本插件声明的资产 + 就绪状态 + 体积

```

插件**不应该**自己写死路径或自己下 —— 但权限全开，拦不住，只做引导。

## 5. 验收

1. 假插件声明 1 个资产 id → 插件卡片出现「未就绪 · 需下载 XX MB」（**体积来自主程序表**）
2. 点「启用并下载」→ 进度条走 → 完成变「就绪」，文件落 `plugin-assets/<ns>/`，大小与表一致
3. **断点续传**：下到 50% 取消 → 再点 → 从 50% 继续（看 `.part` 大小）
4. **校验失败**：临时改表里的 `sha256` → 下载完报「校验失败」，重试后停 failed，**不标 ready**
5. **多源回退**：把 `urls[0]` 换成不通的地址 → 自动走 `urls[1]` 并下成功
6. **插件更新后资产不重下**：改插件版本号重装 → 资产仍就绪
7. **未知 id**：manifest 写一个表里没有的 id → 卡片明示「未知资产（主程序不支持）」，不崩不白屏
8. **并发**：两个资产同时下，进度互不干扰
9. **插件里 `wishful.assets.path(id)`** 返回绝对路径且文件真实存在

## 6. 风险

| # | 风险 | 处置 |
|---|---|---|
| 1 | **哈希 / 体积填错** | 一律 `TODO 实测`；填错会让校验永远失败，用户看到「损坏」而实际是表的错 |
| 2 | **自托管带宽扛不住**（1 GB × 1000 人 = 1 TB） | 大文件默认走第三方源（ModelScope），自托管只做兜底；小文件（<50 MB）才自托管 |
| 3 | 下载源被投毒 | sha256 强制；**校验不过绝不落 ready** |
| 4 | 进度事件刷爆 IPC | 节流（≥200 ms 或 ≥5%） |
| 5 | 用户删了文件但状态缓存说 ready | 每次 `status` 做轻量存在性 + 大小检查 |
| 6 | 插件报一个主程序不认识的 id | 明确「未知资产」并计入诊断，不静默 |

## 7. 不做什么

- **不做远端资产表热更** —— 老大 14:19 定：内置，过期了改表发版
- **不做 CDN / 镜像自动择优 / P2P**
- **不做压缩包解压的通用化** —— 本号只支持**单文件直下 + 目录型资产**（多文件逐个登记为多个 id 或一个 id 对应一个 tar 由插件自己解，实施时按第一个真实插件定，现在不预先绑死）
- **不做断点续传的跨进程恢复** —— 保留 `.part` 即可手动续
- **不做资产的版本升级检查** —— 换表就换 id
- **不做插件市场 / 签名**
