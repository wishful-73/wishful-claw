### S-232（**无限期搁置**，2026-10-27）发送给模型前对密钥类敏感信息做本地脱敏

**老大 2026-10-27 09:19：「这个无限期搁置」** —— 不排期、不进任何迭代、不再追问。编号保留不回收。

正文已落 [S-232](requirements/S-232.md)（阶段一探索完成，§10 记搁置裁定）。
勘察结论保留在文里，将来重启不必重查。

老大原话要点：正则匹配 `sk-` / `AKIA` / `password=` 等密钥格式，发送前替换成 `[REDACTED]`；
参考 `GemFilter` 的 pre-send hook。

**已实查**：全仓没有 pre-send 全局脱敏。出站是三条独立管线
（`OpenAIChatRequestBuilder.WriteMessages:91` / `OpenAIResponsesInputWriter` / `AnthropicMessagesInputWriter`），
四类文本会进 prompt（用户消息 / 助手消息 / 工具参数 / 工具结果）。
局部先例两处：`AgentRuntimeTools.SanitizeExceptionMessage:452-473`（只管异常消息，且 `sk-` 裸前缀不命中）、
`CodeGraphPathSafety.IsConfigLeafNode`（只管 codegraph 读配置）。

**核心矛盾**：脱敏做在「出站」要每次全扫历史（与 T-7 裁定冲突）+ 击穿 prefix cache；
做在「写入时」则真值永久丢失，模型再也干不了「改 .env」这类活（`Write` 会把 `[REDACTED]` 写进用户文件）。

**待裁定**：①落点（出站 / 写入时 / 来源侧）②是否可逆 ③对官方服务商是否也脱敏。
