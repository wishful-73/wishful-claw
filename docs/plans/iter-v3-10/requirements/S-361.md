## 2. 现象（实测，2026-11-13）

首屏主图是**全站唯一**挂了宽度上限的容器（`hero.tsx` `max-w-6xl`，内容宽 1152 − 2×56 = 1040）。另外 6 个 `Section`、价值带、文案区、下载页、指引页、顶栏、页脚全是 `w-full` 通栏。

| 视口 | 主图内容宽 | 其余区块 | 差 |
|---|---|---|---|
| 1024 | 944 | 944 | 0 |
| 1152 | 1040 | 1040 | 0（**分叉临界点**） |
| 1440 | 1040 | 1328 | 288 |
| 1920 | 1040 | 1808 | 768 |

⇒ 窄屏看不出问题（这解释了为什么此前一直没被发现），宽屏才暴露：图被夹在中间，上下区块比图宽出一大截，左边缘不在一条竖线上。

**页脚另有一层**：内容是 `w-full` 通栏 + `bg-paper-soft` 浅灰色块，整条横带的左右边界跟上面的正文对不上，视觉上像「内容缩在里面」。老大原话是「宽度看起来都别扭」。

## 3. 方案

### 3.1 首页：把上限加给所有容器，不动那张图

裁定方向是**图当标尺**——主图 1152（内容宽 1040）不变，把它已有的上限推给所有同级容器。

`components/ui.tsx` 新增两个导出常量：

```ts
export const container = 'mx-auto w-full max-w-6xl px-6 sm:px-10 lg:px-14'
export const shellPadding = 'px-6 sm:px-10 lg:px-14 xl:px-32 2xl:px-48 min-[1920px]:px-56'
```

| 常量 | 谁用 | 宽度行为 |
|---|---|---|
| `container` | 首页 6 个 `Section` + 价值带 + 首屏文案区 + 首屏主图 | 收 `max-w-6xl`（1152，内容宽 1040） |
| `shellPadding` | 顶栏 / 页脚 / 下载页 `main` / 指引页 `main` | **不收 `max-w`**，只把宽屏左右内边距加厚 |

**两套必须分开**：老大 15:00 说「顶部和页脚可以适当增加一点间距，但是不用跟这些一样」。导航比首页正文宽是刻意的（全站导航通栏是常规做法），不能为了「统一」把它也收进 1152。

`shellPadding` 的档位：

| 视口 | 左右内边距 |
|---|---|
| < 1280 | 56（`lg:px-14`，与原来一致） |
| ≥ 1280 | 128（`xl:px-32`） |
| ≥ 1536 | 192（`2xl:px-48`） |
| ≥ 1920 | 224（`min-[1920px]:px-56`） |

### 3.2 页脚：去掉背景色，只留分隔线

15:12 老大提议背景透明。做：`bg-paper-soft` 删掉，保留 `border-t border-ink-700`。

**分隔线通栏、内容留白** —— 这是常规做法。留着色块的话，就是一条比内容宽出 448px 的横带，怎么调都对不上。

## 5. 已知遗留 / 刻意不做

- **全站两套宽度是有意为之**：首页正文 1040（跟主图），下载页 / 指引页 / 顶栏 / 页脚 1472（1920 下，通栏 + 224 留白）。从首页点进下载页内容会明显变宽。这是老大两条指令叠加的必然结果，不是 bug。要改需老大先定方向（首页也放宽 / 子页也收 1040）。
- **下载页按钮尺寸未动**：曾实测按钮 `h-14`=56px、每格 248px，提议改 41px / 每格 184px（grid 加 `max-w-xl`）/ 图标 16px / 换源区 `w-11`。老大 11:52 说「那算了，不改了」⇒ **不做**。
- **不碰文案**：`content/site.ts` 本轮零改动。
- **不改 `index.css` 设计 token**：只调布局容器，不动色板与字体栈。
- **`site/website/dev.mjs` 两行失效路径未修**（`API_DIR` / `DATA_DIR` 还指向搬家前的位置，`npm run dev` / `preview` 会撞 `ENOENT`，目前靠 `npm run dev:web` 绕过）。老大此前口径「不改了」，**另开单处理**。
