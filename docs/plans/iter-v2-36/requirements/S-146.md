# S-146 下载类报错未包装：用户直接看到原始报错报文

- **登记日期**：2026-09-23
- **登记来源**：老大 16:00「增加一个小需求，下载之类的 网络波动导致报错，并没有处理包装，用户看到的是原始的报错报文，这个需要调整」
- **分支**：`dev/v2-iter-36`
- **状态**：✅ 已实施（app 内更新链）

---

## 一、现象

网络波动（连接被重置 / 超时 / 服务端 5xx）时下载失败，**界面上出现的是原始报错报文** ——
`HttpError: 500 Internal Server Error`、`net::ERR_CONNECTION_RESET`，甚至整段 HTML 错误页 /
带栈文本。用户看不懂，也拿不到任何可操作的信息。

---

## 二、定位（本轮勘测）

链路：`src/main/updater.ts` 的 `formatError()` → `setError()` → `update:error` 事件 →
渲染端 store 的 `state.error` → `UpdateDialog` 里 **直接 `<p>{state.error}</p>`** 摊开显示。

`formatError()` 原有三层判定：

| 层 | 判据 | 结果 |
|---|---|---|
| 1 | `latest.yml` + `404` | `missingMetadata`（已包装）✅ |
| 2 | `ETIMEDOUT｜ERR_TIMED_OUT｜ECONNRESET｜ECONNREFUSED｜ENOTFOUND｜EAI_AGAIN` | `network`（已包装）✅ |
| 3 | 其余一切 | **`return message` —— 原文裸奔** ❌ |

**第 3 层是病根，且第 2 层的码表还有个漏**：它只认 **Node 系**码，而 Electron 的 `net` 模块与
electron-updater 的下载走的是 **Chromium 网络栈** —— 报文里出现的是 `net::ERR_CONNECTION_RESET`
这种带 `net::` 前缀的形式，**一个都匹配不上**，于是全部落进裸吐分支。此外 HTTP **5xx / 408 / 429**
（服务端抖动，用户唯一能做的是稍后重试）也不在表内。

---

## 三、修法

**抽纯函数模块** `src/main/lib/updater-error-format.ts`（零 electron 依赖 ⇒ main 与回归套件
跑同一份代码，同 S-142 抽 `stream-segments` 的做法）：

- `classifyUpdaterError(message)` → `{ kind: 'missingMetadata' | 'network' | 'unknown' | 'fallback', code? }`
  - 判定顺序 = 优先级：清单缺失（发布侧问题，文案要指向「重新生成并上传」）→ 网络类 → 带短码 → 兜底。
- 网络类码表**扩到三套**：Node / undici 系、Chromium `net::ERR_*`、HTTP 408 / 429 / 5xx。
- `extractErrorCode()`：优先级 `net::ERR_*` → `ERR_UPDATER_*` → `HTTP nnn`，**只放行短码**上屏。
- **兜底不再回吐原文**；原始报文照旧进 `logError` 的 `extra`（排查不受影响）。

`updater.ts` 的 `formatError()` 改为按分类取文案；新增双语消息键 `unknownWithCode`
（`更新失败（{code}），请稍后重试。` / `Update failed ({code}). Please try again later.`）。

---

## 四、验收

1. 界面上**永不出现原始报文**（测试里用 HTML 错误页与神秘文本各钉一条，并断言分类结果里
   没有原文段）。
2. `net::ERR_*`、HTTP 5xx / 408 / 429 → 「无法连接更新服务器，请检查网络后重试。」
3. 认得出短码的（`ERR_UPDATER_*` / `HTTP nnn`）→ 「更新失败（码），请稍后重试。」
4. `latest.yml` + 404 → 原「清单缺失」文案不变；`latest.yml` + 5xx → 归网络类（不是清单缺失）。
5. 回归套件 `tests/updater-error-format`（**38 断言**，`npm run test:updater-error-format`）。

---

## 五、范围

本轮只覆盖 **app 内更新**这条链（`checkForUpdates` / 下载 / 安装的失败展示）。

其它下载场景（工具内下载、官网下载按钮）**不在本轮** —— 官网下载失败是浏览器行为，不归本应用
展示。老大若指的是别的界面，说一声，另行登记。
