# S-282 · `WISHFULCLAW_DATA_DIR` 指向全新目录时首次启动静默退出 —— userData 子目录没人建，Chromium 建不了单例锁

> 归属：**移交 v3-iter-5**（阻断级缺陷，但只在「换数据目录」场景触发，不影响现有用户）。
> 状态：**✅ 已修** —— v3-iter-5 刀 0（2026-10-30 21:0x），实施记录见 §八。
> 登记 2026-10-30 11:05。
> 来源：2026-10-30 做 preview 内存对照实验时**连续踩中两次**，非推测。

## 一、现象

指定一个全新的数据目录启动：

```powershell
$env:WISHFULCLAW_DATA_DIR = "C:\Users\xxx\.wishful-claw-dev-preview"
npx electron-vite preview --skipBuild
```

进程启动后**立刻退出**。没有窗口、没有对话框、没有日志文件（`{dataDir}/logs/` 根本没建出来），控制台只有一行：

```
[7816:1030/104127.155:ERROR:chrome\browser\process_singleton_win.cc:446] Lock file can not be created! Error code: 3
```

`Error code: 3` = `ERROR_PATH_NOT_FOUND`。

## 二、根因

`src/main/index.ts:257`：

```ts
app.setName(appDisplayName)
app.setPath('userData', resolveDataPath('electron-user-data'))   // ← 这一行
```

`resolveDataPath` 只是 `join(resolveDataDir(), ...)`，**纯路径拼接，不创建目录**。`resolveDataDir()` 在 `WISHFULCLAW_DATA_DIR` 被设置时直接返回那个值。

于是：新数据目录存在、但 `{dataDir}/electron-user-data` 不存在 ⇒ Chromium 在 `requestSingleInstanceLock()`（紧随其后）阶段要在这个路径下建 `SingletonLock` ⇒ 父目录不存在 ⇒ 建锁失败 ⇒ 进程直接退出，且因为退出发生在日志系统初始化之前，**一个字都没留下**。

## 三、为什么一直没暴露

dev 实例的数据目录 `~/.wishful-claw-dev/` 是历史积累的，`electron-user-data` 早在第一次启动时就由 Electron 自己建好了（那时用的是默认 userData 路径，Electron 会 createDirectory）。**只有「给一个从未用过的目录」这条路径才会撞上**。

而这条路径恰恰是 S-223（工作区隔离）要走的：项目级目录已经能用 `.wishful-claw-dev` 分离了，但**全局级目录一旦换新位置就起不来**。

## 四、影响面

| 场景 | 后果 |
|---|---|
| S-223 工作区隔离想换全局数据目录 | 起不来 |
| 多实例并行（dev + preview 同时开） | 起不来，且无提示 |
| 用户手工迁移数据目录 | 起不来 |
| 数据目录被误删后重建 | 起不来 |

**静默退出是最糟的部分**：用户看到的就是「双击了，没反应」。这类问题报上来基本无法归因。

## 五、修法

在 `setPath` 之前确保目录存在：

```ts
const userDataPath = resolveDataPath('electron-user-data')
mkdirSync(userDataPath, { recursive: true })
app.setPath('userData', userDataPath)
```

两处细节：

1. **`recursive: true`** —— 新数据目录本身也可能不存在（`resolveDataPath` 只拼不建），一次调用把两层都建了。
2. **必须在 `app.requestSingleInstanceLock()` 之前** —— 现在的顺序是对的，别改乱。

顺带建议：`resolveDataDir()` 的语义是「解析」，不该有副作用；所以建目录放在调用点，不要塞进 `resolveDataDir`（否则每次解析都碰盘）。

## 六、验收

1. 指向一个**完全不存在**的目录启动 → 能起来，且该目录下出现 `electron-user-data/`。
2. 指向一个存在但没有 `electron-user-data` 子目录的目录启动 → 能起来。
3. 正常目录（dev / 生产）启动行为无变化。
4. 建议补一条单测：`resolveDataDir` 在 env 存在 / 不存在两种输入下的返回值（纯函数，不碰盘）。

## 七、本条暴露的相邻问题

排查期间还确认了一件事：**`resolveDataDir()` 只认 `WISHFULCLAW_DATA_DIR`，但项目级目录用的是另一个变量 `WISHFULCLAW_PROJECT_DIR`**（`src/main/lib/data-dir.ts:11-19` 与 `:33-35`）。两者职责不同、变量不同名，做工作区隔离时容易漏配一个。S-223 落地时应当有明确文档说明「全局数据」和「项目记忆」是两套目录、两个开关。

## 八、实施记录（v3-iter-5 刀 0）

按 §五 落地，另做了一处**没写在原方案里的调整**：把「选哪个目录」从主进程抽成一个纯函数。

**为什么多这一步** —— §六 第 4 条要「补一条单测」，但 `resolveDataDir()` 住主进程模块、import 了 electron，node 下 `app` 是 undefined，直接测不了。要么不测，要么把它拆开。选了拆：决定归 `pickDataDir`（`src/shared/data-dir.ts`，纯函数），落盘路径归 `resolveDataDir`（主进程薄壳）。这与 `project-dir.ts` 的 `pickProjectDirName` 是同一个先例。

**`pickDataDir` 返回 `{ fromEnv, value }` 而不是一个字符串** —— 两种来源语义不同：env 给的是**完整路径**（相对路径要按 cwd 转绝对），默认值只是**目录名**（必须拼 home）。压成一个字符串，主进程就只能靠 `isAbsolute()` 猜来源，于是 `WISHFULCLAW_DATA_DIR=.\data` 会被拼到 home 下、`WISHFULCLAW_DATA_DIR=.wishful-claw` 会被误判成默认值。

改动文件：

| 文件 | 改什么 |
|---|---|
| `src/shared/data-dir.ts` | 新增 `dataDirName(isPackaged)` 与 `pickDataDir(envValue, isPackaged)`（纯函数，不引 `node:path`） |
| `src/main/lib/data-dir.ts` | `resolveDataDir()` 改为复用 `pickDataDir`，只负责转绝对路径 |
| `src/main/index.ts` | `setPath` 前 `mkdirSync(userDataPath, { recursive: true })`，注释写死「必须早于单实例锁」 |

**约束**：`src/shared/**` 同时进 `tsconfig.node.json` 与 `tsconfig.web.json` ⇒ shared 里不能引 `node:path`。故 shared 只返回决定，拼路径留给主进程。

### 新增门禁 `tests/data-dir`（17 断言）

进 `npm test` 的 tsTests（`package.json` 加 `test:data-dir`，`scripts/run-tests.mjs` 自动发现）。

覆盖三块：

1. **目录名**（2 条）—— 打包版 `.wishful-claw`、dev 版 `.wishful-claw-dev`。⚠️ 参数语义是 `isPackaged`，与 `project-dir` 的 `projectDataDirName(isDev)` **相反**；本套件第一次跑就因为照着那边抄而红过，已在注释里点名。
2. **来源与取值**（11 条）—— env 原样采信 / 去首尾空白 / 纯空白回退默认 / env 压过打包态判定 / 相对路径原样返回（绝不 join home）/ **env 值恰好等于默认目录名时仍须标 `fromEnv=true`**。最后这条是防「把来源压成字符串」退化的闸。
3. **顺序闸**（3 条）—— 扫 `src/main/index.ts` 源码，断言 `mkdirSync` < `app.setPath` < `app.requestSingleInstanceLock()` 的**行序**。整套修复的正确性全押在顺序上，有人把 mkdir 挪到 setPath 之后「看着更整齐」缺陷就悄悄回来了 —— 而那时真机只表现为「双击没反应」。判据取带 `app.` 前缀的调用，避免命中注释里的同名字样。

**反向验证（本迭代硬规矩）**，两次都做：

| 把实现改回错误版本 | 结果 |
|---|---|
| `pickDataDir` 里 `fromEnv: true` → `false`（模拟来源标记丢失） | 红：`env 有值时必须标记 fromEnv=true` |
| `dataDirName` 三元写反（打包版↔dev 互换） | 红：`打包版默认必须是 .wishful-claw` |

撤销后均复绿。
