## 2. 现象

S-353 把「读入参」统一到 `TryGetProp`（驼峰 / 蛇形双向归一），治好了 7 处静默丢参。但同一批代码里还有四处**一致性残留**没跟上：

| 子项 | 现象 |
|---|---|
| **D-4** | `FeishuSendImage` / `WeixinSendImage` 的 schema 从 `imagePath` 改名 `filePath`，但 `TryGetProp` 的回落只有 `file_path` ↔ `filePath` —— **旧名 `imagePath` 两个都不命中** ⇒ 读到空串 ⇒ 报「filePath 为空」，看着像模型没传参 |
| **D-8** | `FeishuMediaApi.downloadUrl`（`feishu-media-api.ts:293-320`）已**零外部调用**，只剩自递归 |
| **D-9** | `fileType` 参数 executor 仍在写（`AgentRuntimeChannelPluginExecutor.cs:74`），接收方标 `@deprecated` 并忽略 —— **写了不生效** |
| **D-10** | 渲染端 `COMMON_PLUGIN_TOOL_HANDLERS`（`plugin-tools.ts:414`）缺 `ChannelSendAudio`，与 descriptor / C# 两处不一致 |

## 3. 代码链路（2026-11-11 实读）

### 3.1 D-4：改名没留别名

`TryGetProp`（`AgentRuntimeChannelPluginExecutor.cs:159-169`）：

```csharp
if (input.TryGetProperty(name, out value)) return true;
var alternate = name.Contains('_', StringComparison.Ordinal) ? ToCamelCase(name) : ToSnakeCase(name);
if (input.TryGetProperty(alternate, out value)) return true;
```

调用方传的是 `"file_path"` ⇒ `alternate = "filePath"`。**`imagePath` 不在这一对里。**

S-353 §3.3 已经把 `FeishuSendImage` 的 schema 从 `imagePath` 改成 `filePath`（`ChannelPluginToolProvider.cs:53-58`、`:142-147`），于是：

- 模型照**新** schema 传 `filePath` ⇒ ✅
- 模型照**旧** schema 或从别处学到 `imagePath` 传 ⇒ ❌ 空串 ⇒ 报「路径为空」

**这是 S-353 要治的那类病（「报错还像是模型没传」），修完又用另一种方式复现了一次。**

### 3.2 D-8：死代码

`feishu-media-api.ts:293` 的 `downloadUrl` 是手写 `http`/`https` + 手动跟随 302。唯一外部调用点（飞书 send-image handler）在 S-352 刀 1 改成了 `readBinarySource`，现在只剩 `:304` 的自递归。

**顺带的口径问题**：`downloadUrl`（Node `http` 模块）与 `readBinarySource`（`fetch`）**两套下载实现并存**。死的那份不删，下次谁改超时逻辑会改错文件。

### 3.3 D-9：写了被丢弃

```
AgentRuntimeChannelPluginExecutor.cs:74   WOpt(w, call, "file_type", "file_type")   ← 仍在写
channel-feishu-handlers.ts:35-44          @deprecated 从未有调用方传过 …（忽略）    ← 不读
```

「传了不生效」与 S-353 的「传了读不到」是同一种病，只是方向反过来。

### 3.4 D-10：三处声明不同步

| 文件 | 含 `ChannelSendAudio` |
|---|---|
| `channel-descriptors.ts:22`（`COMMON_PLUGIN_TOOLS`） | ✅ |
| `ChannelPluginToolProvider.cs:35`（C#，**模型真正看到的那套**） | ✅ |
| `plugin-tools.ts:414`（渲染端 handler 表） | ❌ |

连带 `PLUGIN_TOOL_DEFINITIONS`（`:445`）/ `getDefaultPluginToolNamesForType`（`:450`）都少它。

**补充事实（降低本项严重度）**：这两个导出本身也是**零调用**；`channel-descriptors.ts` 的 7 处 `tools:` 赋值在主进程**也无任何消费者** ⇒ `descriptor.tools` 整条线是死的。所以 D-10 的**实际影响有限**（模型只看 C# 那套，见 S-353 §3.2），但它仍是「三处声明不一致」这个隐患。

## 4. 根因

**S-353 只统一了「怎么读」，没有统一「声明什么」。**

- D-4：改 schema 时只改了「写出去的」，没回头核「读进来的」认不认旧名；
- D-8：刀 1 搬迁后没做「零引用检查」（项目**没有 lint**，见 S-357 —— 这正是 lint 能自动抓的那类）；
- D-9：`@deprecated` 只标在读的一侧，写的一侧没同步；
- D-10：同一个概念分散在 3 个文件，没有单一事实源。

## 5. 修复方向

### 5.1 D-4 —— 加旧名别名表

在 `BeyondGetProp` 旁加一层：

```csharp
private static readonly Dictionary<string, string> LegacyAliases = new(StringComparer.Ordinal)
{
    ["imagePath"] = "filePath",
};
```

`TryGetProp` 命中旧名时按新名处理。**或者**在 S-353 的 changelog 里明确写「旧名已废弃、不做兼容」，并在真机验收清单里列一条 —— 二选一，别两头空着。

倾向**加别名**：成本两行，能救回所有写在旧 prompt / 旧插件里的调用。

### 5.2 D-8 —— 删

删除 `downloadUrl`，并在 `feishu-outbound-media.ts` 头部注明「下载统一走 `readBinarySource`」。

### 5.3 D-9 —— 二选一

- executor 不再写 `file_type`（倾向，因为 schema 里本来就没有它）；
- 或 handler 真的用起来。

### 5.4 D-10 —— 二选一

- **补齐**：`channelSendAudio` 加进 `COMMON_PLUGIN_TOOL_HANDLERS`，三处同步；
- **拆掉**：连同 `descriptor.tools` 整条死线一起删（S-340 那轮清死代码的同类项）。

倾向**拆掉**：既然模型只看 C# 那套、渲染端那套零调用、`descriptor.tools` 也无消费者，留着只是让三处继续漂移。

## 6. 代价与取舍

- **D-4 加别名**会让「参数名」这件事暂时有两套合法写法。若不希望长期维护别名表，就选「写清废弃 + 不兼容」，但那样每个踩到的人都要多排一次错。
- **D-10 拆掉**需要先确认渲染端那套真的没有任何 UI 在消费（`PLUGIN_TOOL_DEFINITIONS` / `getDefaultPluginToolNamesForType` / `descriptor.tools` 三个都要核）。核完再删，别删出空引用。

## 7. 刻意不做

- **不动 `ChannelSendAudio` 的可见性** —— 那是 S-354 的 D-2。
- **不补 `imagePath` 之外的历史别名** —— 只补实际改过名的这一个，不搞「通用别名猜测」。
- **不在本单引入 lint** —— 见 S-357。

## 9. 开放问题（已结）

- **D-10 走「补齐」还是「拆掉」** ⇒ **本刀补**。整理由：拆整条渲染端工具线（`plugin-tools.ts` 475 行 + `descriptor.tools`）零 import 属实，但那是一次**方向性**改动 —— 未来可能真让渲染端直调渠道工具，删了要重建。「三处漂移」这件具体的事，补齐一行即可消除。
  ⇒ **另记一笔待办**（不属本单）：`registerPluginTools` / `unregisterPluginTools` / `PLUGIN_TOOL_DEFINITIONS` / `getDefaultPluginToolNamesForType` 全仓零调用，`descriptor.tools` 零消费者。要么接线、要么清掉，别让它们继续假装是活的。**已归口到 [../raw-requirements.md](../raw-requirements.md) §6.2**，别在本单里追这条。
