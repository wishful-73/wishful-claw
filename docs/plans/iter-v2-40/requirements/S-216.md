## 一、原始需求（老大 2026-10-21 10:31 原话）

> 现在我们不是有内置浏览器么？ 现在内置浏览器 本身有些网页自身是选项卡加载的，结果我们内置浏览器自己又触发了一次刷新，以及内置浏览器有时候是需要去显示 h5 的页面 或者就是需要适配 h5 和 pc 两种的，这种情况下目前无法查看 h5 的样式。需要探索如何解决。

拆成两件事：

1. **网页自己的选项卡切换，被内置浏览器强制重载了一次** —— 站内切的 tab 白切，状态回默认；
2. **看不到 H5 版** —— 需要按 H5 / PC 两种形态看同一个站点的样式，现在只能拿到 PC 版。

## 二、问题 1：站内切换被强制重载

### 2.1 根因（代码已钉死）

`components/layout/BrowserPanel.tsx`：

```tsx
const storedUrl = useUIStore((s) => s.getBrowserState(sessionId, projectId).url)   // :33
const [committedUrl, setCommittedUrl] = useState(storedUrl)                        // :48

useEffect(() => {
  setInputUrl(storedUrl)
  setCommittedUrl(storedUrl)        // ← 病根：把「当前地址」写回「导航目标」
}, [storedUrl])                     // :126-129

<webview src={committedUrl} ... />   // :449 受控 src
```

而导航事件在把当前地址写回 store：

```tsx
const onNavigate = (e) => { setInputUrl(e.url); R.setBrowserUrl(e.url, ...) }        // :278-282
const onNavigateInPage = (e) => { setInputUrl(e.url); R.setBrowserUrl(e.url, ...) } // :284-288
```

串起来就是一条自激回路：

```
站内切 tab（hash / query 变）
  → did-navigate-in-page
  → setBrowserUrl 写 store
  → storedUrl 变
  → useEffect 回写 committedUrl
  → <webview src> 变
  → 整页重新导航
  → tab 状态、表单、滚动位置全丢
```

`committedUrl` 的语义是**导航目标**（用户按回车 / 外部链接 / 恢复会话），`storedUrl` 的语义是**当前实际地址**。现在两者被同一个 `useEffect` 绑成一个，只要是「网址变了」就当成「要求导航」——站内切换、`history.pushState`、锚点跳转全部踩中。

### 2.2 影响面

只有右侧 `BrowserPanel`。`components/free-chat/FreeChatPage.tsx:201` 的 `src={site.url}` 取的是站点配置里的固定 URL，不随导航变化，**不受影响**。

### 2.3 修法候选

| 方案 | 做法 | 评价 |
| --- | --- | --- |
| **甲（建议）** | 拆开两个语义：`committedUrl` 只由**显式导航**驱动（地址栏回车、外部打开、切会话/项目恢复）；删掉 `useEffect([storedUrl])` 回写，改成只在 `sessionId` / `projectId` 变化时同步一次 | 改动最小、语义清楚；`did-navigate` 仍照常更新地址栏显示与 store |
| 乙 | `src` 非受控化：首次挂载后再不交给 React 管，导航一律走 `wv.loadURL()` | 单做无效 —— 下次重渲染 React 仍会把旧 `committedUrl` 写回属性；必须与甲配套 |
| 丙 | `useEffect` 里加相等判断 | **治不了** —— 站内导航时 `storedUrl`（新地址）与 `committedUrl`（旧目标）本来就不等，照样回写 |

**建议甲**，乙作为后续可选项（彻底摆脱受控属性）。

## 三、问题 2：无法查看 H5

### 3.1 现状

`BrowserPanel.tsx:59-66` 只给 webview 设了三样：

```ts
{ partition?, allowpopups: true, useragent? }
```

UA 还是**洗白成桌面 Chromium** 的（`stripElectronFromUserAgent`，见 S-39）。没有 viewport 仿真，也没有设备切换入口。

### 3.2 为什么现在只能拿到 PC 版

站点分流靠 UA 和窗口宽度：

- **UA 是桌面 Chrome** ⇒ 服务端直接返 PC 模板；
- **视口就是面板宽高**（桌面尺寸）⇒ 前端响应式判断也走 PC 分支。

两个信号都在说「我是桌面浏览器」，所以 H5 版根本没有机会出现。

### 3.3 方案候选

| 方案 | 做法 | 效果 | 代价 |
| --- | --- | --- | --- |
| **甲** 仅切 UA | `webview.setUserAgent(移动端 UA)` + reload | 对**按 UA 分流**的站点够用（服务端返 m 站 / H5 模板） | 轻；但纯前端响应式的站点仍按面板宽度渲染 PC 布局 |
| **乙（建议）** UA + Electron 原生设备仿真 | 渲染端 `webview.setUserAgent(移动端 UA)` 切 UA；主进程 `webContents.fromId(id).enableDeviceEmulation({ screenPosition: 'mobile', screenSize, viewSize, deviceScaleFactor, scale })` 切视口，复原用 `disableDeviceEmulation()` | 真正拿到移动端视口，纯响应式站点也能出 H5 布局 | 要加 IPC 通道（webview 只有 `getWebContentsId()`，拿不到 `webContents` 对象）；webview 重建后需重新应用 |
| 丙 只缩放 | `setZoomFactor(0.4)` | 只是把 PC 版缩小，**不是 H5** | 无意义，排除 |

**定案乙**（只切 UA 拿不到纯响应式站点的 H5；老大要的效果等同 F12 设备模式，那就是 UA + 视口一起切），并配一组预置设备：

| 预设 | 视口 | DPR | UA |
| --- | --- | --- | --- |
| PC（默认） | 面板实际尺寸 | 1 | 桌面 Chromium（现状） |
| iPhone 14 | 390 × 844 | 3 | Safari iOS |
| Pixel 7 | 412 × 915 | 2.625 | Chrome Android |
| iPad | 820 × 1180 | 2 | Safari iPad |
| 自定义 | 用户填宽高 | 用户填 | 跟随所选平台 |

### 3.4 技术前提（已核实）

- Electron **43.2.0**（`node_modules/electron/package.json`），`webContents.enableDeviceEmulation(parameters)` / `disableDeviceEmulation()` **原生可用**（`electron.d.ts:17921` / `:17930`，参数接口 `Parameters` 见 `:22931`，字段 `screenPosition: 'desktop' | 'mobile'` / `screenSize` / `viewPosition` / `deviceScaleFactor` / `viewSize` / `scale`）——**不需要** `debugger.attach()` + 手发 CDP 命令；
- `WebviewTag` 的方法集已核（`electron.d.ts:19631` 起）：有 `setUserAgent()` / `getUserAgent()` / `getWebContentsId()`，**没有** `enableDeviceEmulation` ⇒ 切 UA 在渲染端，切视口必须过主进程拿 `webContents` 对象；
- 主进程目前**零** `enableDeviceEmulation` 用法，属于新增能力，不覆盖既有实现；
- webview 通过 `getWebContentsId()` 把 id 传主进程即可定位目标 `webContents`。

### 3.5 agent 可自行切换（老大 2026-10-21 10:42 补充）

> 设备预设 —— iPhone / Pixel / iPad + 自定义  这个是 agent 可以自己切换演示，就跟正常浏览器可以通过 F12 然后切换成 h5 查看一样

即**两条路都要有**：用户手动入口（面板上的设备选择器）+ agent 可调用的工具。后者是重点 —— agent 要能在跑任务时自己判断「这页面得看 H5」，然后切过去截个图，跟人按 F12 一样自然。

**链路已查实**（四处都要动，缺一处工具就不生效）：

| 层 | 文件 | 现状 |
| --- | --- | --- |
| 工具声明 | `Agent/Tools/Providers/BrowserToolProvider.cs` | 9 个浏览器工具（`BrowserNavigate` / `GetContent` / `Screenshot` / `Snapshot` / `Click` / `Type` / `Scroll` / `Evaluate` / `WebSearch`），无设备类 |
| 执行白名单 | `Agent/AgentRuntimeBrowserExecutor.cs:25-36` | `BrowserToolNames` 集合，不在里面的名字不会被识别为浏览器工具 |
| 反向请求派发 | `renderer/src/lib/tools/browser-native-ui.ts:430-450` | `runBrowserTool` 的 switch，`default` 直接抛 `Unsupported browser tool` |
| 占位 handler | `renderer/src/lib/tools/browser-tool.ts` | 每个工具一个占位 `definition`，`execute` 一律返回 `nativeOnlyBrowserResult`（真执行走 Worker 反向请求） |

**新增工具 `BrowserSetDevice`**（命名跟现有 `BrowserXxx` 一致）：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `device` | string | `pc`（默认，复原） / `iphone` / `pixel` / `ipad` / `custom` |
| `width` / `height` | number | 仅 `custom` 用；缺省回落当前预设 |
| `scale` | number | 可选，DPR，缺省按预设给 |

- 可见范围：`Everywhere`（读页面形态属于读操作，不需要 WorkRunsOnly），`excludedScopes` 同样排除 `UnattendedRoles` —— 无人值守的 run 没有窗口给用户看，切了也没人看；
- 返回：当前生效的设备 + 实际视口尺寸（让 agent 知道切没切成功）；
- 切完**不自动截图**，agent 自己决定下一次 `BrowserScreenshot`。

## 六、风险

- **webview 重建即失效**：仿真参数挂在 `webContents` 上，`key` 变化 / 组件卸载重建后必须重新应用，否则「看起来切了 H5，其实是 PC」；
- **`enableDeviceEmulation` 只改视口，不改 UA**：`screenPosition: 'mobile'` 管的是屏幕类型与视口尺寸，UA 得靠 `setUserAgent()` 单独切，两者缺一个都会让站点判错；
- **移动 UA 可能触发站点跳 m 域名**：多数情况是好事（正是用户要的 H5），但会让地址栏跳转，需向用户说明；
- **问题 1 改完要防回归**：切会话 / 切项目时浏览器状态必须照旧恢复 —— 用 ref 对比 `sessionId` / `projectId` 变化来触发同步，别为了修重载把恢复也弄坏。
