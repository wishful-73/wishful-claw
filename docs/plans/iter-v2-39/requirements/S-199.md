> 状态：**待开工** —— 修法**无歧义**（照 desktop 同族先例，约 15 行），**但属可见行为变化，等老大点头**。

> 归属：**iter-v2-39**（现行口径：「不新做主打功能，体验优化 / bug 修复这些都可以列入」）。
> 来源：**自评发现**（2026-10-14，做 **S-195** 时顺带坐实；**非老大登记**）。
> 同族先例：**S-195**（`5b65a231`）已修 **desktop** 的同款空壳 `isDesktopControlToolName`，**浏览器这一份漏了**。

## 一、现象

`BrowserToolCard`（`components/chat/BrowserToolCard.tsx`，491 行，d6228b27 一并移植）**从来没有渲染过**。

7 个浏览器插件工具（`BrowserNavigate` / `BrowserGetContent` / `BrowserScreenshot` / `BrowserSnapshot` / `BrowserClick` / `BrowserType` / `BrowserScroll`）**全部落到通用 `ToolCallCard`**（`tool-block-renderer.tsx:340-361` 的兜底分支），只吐原始 JSON。

浏览器插件**默认启用**（`types.ts:50`：`isAppPluginEnabledByDefault` 含 `BROWSER_PLUGIN_ID`）⇒ **这不是「没人用的死角」，是默认路径**。

**丢的是什么**（`BrowserToolCard.tsx` 逐项对照通用卡）：

| 能力 | `BrowserToolCard` | 通用 `ToolCallCard` |
|---|---|---|
| 图标 | 按 7 个工具分别给（相机 / 显示器 / 鼠标 / 键盘 / 滚动 / 文档 / 地球，`:109-117`） | 统一 |
| 标题 | `Browser Navigate` / `Browser Content` … 人话标题（`:119-128`） | 工具名 |
| 摘要 | 导航给 `action: host/path`（URL 压缩，`:88-97`）；取内容给 `type · N chars`；截图给 `WxH px` | 无 |
| 正文 | 结构化预览，超 `12000` 字符截断并标注（`:52`、`:99-102`） | 原始串 |

## 二、根因（已静态坐实）

`src/renderer/src/lib/app-plugin/browser-tool-names.ts` **全文只有 3 行**：

```ts
export function isBrowserToolName(_name: string): boolean {
  return false
}
```

- **于 `d6228b27`（「全量移植 OpenCowork 聊天渲染系统」）创建时就是空壳** —— 不是后来被改坏的。`git show d6228b27:…/browser-tool-names.ts` 与工作区内容**逐字相同**。
- 两个消费点，**一个真有事、一个纯属无害**（见 §三）：
  - `components/chat/AssistantMessage/tool-block-renderer.tsx:220` —— `if (isBrowserToolName(block.name))` ⇒ **永不命中** ⇒ `BrowserToolCard` 不可达；
  - `components/chat/execution-outline.ts:208` —— `if (isBrowserToolName(name)) return 'browser'` ⇒ **`'browser'` 分类永不产生**（但**没有后果**，见 §三 2）。

**同族对照**：`desktop-routing.ts` 里 `isDesktopControlToolName` 曾经是**一模一样的空壳**，S-195 已按 `types.ts` 的 5 个 `DESKTOP_*` 常量查表修好；本条的浏览器版本**没跟着修**。

## 三、影响面（**只有一处**，另一处已核实为无害）

### 3.1 真影响 —— 专用卡片失效（唯一）

浏览器工具不再走 `BrowserToolCard`（见 §一 对照表），退化成通用 `ToolCallCard`。

`BrowserToolCard` 的全仓引用**只有** `tool-block-renderer.tsx:29`（import）+ `:229`（渲染），且渲染被 `isBrowserToolName` 挡死 ⇒ **491 行是纯死代码**。旁证：它用的 `locales/{zh,en}/chat.json` 里那组 `toolCall.browser.*` 文案同样**从未被读到**。

### 3.2 已核实**无害** —— `'browser'` 分类不可达（**订正，勿再当影响**）

`execution-outline.ts:208` 的 `'browser'` 分类确实永不产生，但**逐条查过消费者，无一有后果**：

| 消费者 | 后果 |
|---|---|
| `AssistantMessage/process-summary.ts:29` 的 `classifyItem` | **先短路**：`if (WEB_CONTEXT_TOOL_NAMES.has(item.name) \|\| item.name.startsWith('Browser')) return 'browser'` —— 在 `switch (item.category)` **之前**就返回了 ⇒ 折叠态摘要里的「N 个浏览器操作」**照常显示**，`workbench.summaryBrowser` **不是死 key** |
| `execution-outline.ts:222-233` 的 `getToolVisibility` | `'browser'` 与 `'unknown'` **同属 `'force'`** ⇒ 折叠 / 展开行为不变 |

⇒ **无其它消费者**（全仓 `category === 'browser'` 零命中）。本条修好后这一处也是**行为中性**。

⇒ 连带修正 `plan-s195/plan.md` §六-4 的结论：它写「不动 `isBrowserToolName` 空壳 —— 已被 `process-summary.ts:29` 的 `startsWith('Browser')` 覆盖，**改它无行为收益**」。**前半句对（摘要确实不受影响），后半句不成立** —— 当时**只查了摘要那条链，漏了 `tool-block-renderer` 的卡片链**（同批 S-195 审查报告 §8.3 也把这条框成了「摘要文案」问题，同漏）。

⇒ **桌面与浏览器在这里并不对称**（别照抄 S-195 的结论）：桌面卡片分支（`tool-block-renderer.tsx:262-268`）**直接内联了 5 个 `DESKTOP_*` 常量**，压根不走 `isDesktopControlToolName` ⇒ S-195 那句「改后行为变化仅限摘要文案」**对 desktop 成立**，而**浏览器这份是唯一真正被空壳挡住的卡片**。

## 四、修法（照 desktop 同族先例，约 15 行）

`browser-tool-names.ts` 改成按 `types.ts` 的 7 个 `BROWSER_*` 常量查表，与 `desktop-routing.ts` **结构完全对称**：

```ts
import {
  BROWSER_CLICK_TOOL_NAME,
  BROWSER_GET_CONTENT_TOOL_NAME,
  BROWSER_NAVIGATE_TOOL_NAME,
  BROWSER_SCREENSHOT_TOOL_NAME,
  BROWSER_SCROLL_TOOL_NAME,
  BROWSER_SNAPSHOT_TOOL_NAME,
  BROWSER_TYPE_TOOL_NAME
} from './types'

const BROWSER_TOOL_NAMES = new Set<string>([…])

export function isBrowserToolName(name: string): boolean {
  return BROWSER_TOOL_NAMES.has(name)
}
```

**不硬编码字符串字面量** —— 常量就在同一目录的 `types.ts`（`desktop-routing.ts` 已是这个写法），写死会跟 `APP_PLUGIN_DESCRIPTORS` 那份清单漂移。

**爆炸半径**：改完只有 **§3.1 一处**行为变化（卡片换上）；§3.2 那条经核实是行为中性 ⇒ **比第一版评估还小**。

## 五、验收判据

1. 调一次 `BrowserNavigate`（或任一 `Browser*`）⇒ **渲染 `BrowserToolCard`**（按工具换图标 + 人话标题 + 摘要），而不是通用卡片。
2. 折叠态摘要**照旧**显示「N 个浏览器操作」（修前修后一致 —— 这条是**回归护栏**，不是新行为）。
3. 桌面 / 图片 / 其它工具卡片**不受影响**（`execution-outline.ts` 分类优先级里 `browser` 排在 `isMcpTool` / `ordinary` / `file-change` / `command` **之后**，不会抢走它们的分类）。
4. `npm run typecheck` 0 错；`npm test` 不降（既有套件全绿）。
