## 三、根因（2026-10-08 16:44 由老大场景收窄后实读确认）

**登记时列的三个候选全部不是**（候选 1「越钉越空自锁」需要 `getRealContentBottom()` 返回 0，实际折叠时行都还在；候选 2「水位线未及时清零」只在流式结束后；候选 3 是另一条链）。老大的场景——**异步并发工具（同时读三个文件）展开三卡、会话仍在输出时各自折叠**——把问题钉在**流式分支**：两个因素叠加，缺一不可。

**根因 ①：单调下界让「真实收缩」永远不被承认。**
`streamingBottomFloorRef` 流式期内只增不减（`trackContentBottom`，iter-36 S-150 加的，本意是滤掉「虚拟行卸载 ⇒ 内容底骤降一整行 ⇒ 下帧回升」的自激噪声）。代价：三张卡各折 100px、内容真实降了 300px，`realBottom` 却纹丝不动 —— 系统仍按历史最高点摆视口，**那 300px 全变成可见留白，而且永远收不回来**。

**根因 ②：回收触发线给到了半屏。**
双向跟随在 `24 ≤ 余量 ≤ 半屏` 期间什么都不做（`useMessageListScroll.ts` 旧 `:228` 直接 `return`）。即使内容底下来了，也要等余量涨过**半屏**（1080p 视口 540px）才回收到 `gapTarget`。

⇒ **①** 让留白必然产生且累计，**②** 让它能攒到半屏才被清理。老大看到的「几百 px、只涨不消」正是两者叠加。

## 四、已知硬约束（无论走哪条方案都不能违反）

1. **收 `min-height` = 制造 `scrollHeight` 骤减 = 浏览器 clamp `scrollTop` = 跳** —— iter-30 实测代价，写死在 `useMessageListScroll.ts:650-655` 与 `docs/plans/iter-v2-30/raw-requirements.md:426`。
2. 若要回收，**顺序**必须是「先把视口对齐到真实内容底，再撤 `min-height`」—— 代码里已有这份实现（`:691-699`），回收直接复用，不要另起一套。
3. **全局 `* { scroll-behavior: smooth }` 必须继续被 inline `scrollBehavior: 'auto'` 覆盖**（`VirtualListContent.tsx:135-137`）—— 这是 iter-30 认定的「真凶」，别碰。
4. 冷却锁（240 ms）与单调下界是 S-150 为治抖动加的，回收方案**不得与其打架**；要动，得给出「为什么这次不会变成拉锯」的推理。

### 4. 真机反馈修复（2026-10-09）

**老大实测（08:27）**：**无跳动 ✅**（⇒「先对齐、再压水位线」成立，这条链不动），但**留白回收更慢**，空白期 0.3~0.5s；08:44 补充「出现留白的时候变多了」；08:45 下令动手。

**病因（两条，都不是参数问题，是事件驱动不完整）**：

1. **确认被冻结（主因）**：`observeFloor` 只在 bottom-anchor effect 被喂，而该 effect 只在 re-render 之后跑 —— 折叠动画停下、又没有新内容到达时计数冻在 1~2，凑不满 K，下界不降，留白挂着。老大那句「当渲染新的输出和组件的时候又正常了」正是证据。
2. **冷却到期无重判**：`shouldReclaim` 命中但 `isCollapseCoolingDown` 为真时直接 `return`，没排 240ms 后的重判；几何稳定后永不重判。S-150 注释里那句「窗口过了按当时的几何重判」实际只写在注释里。

**修法（只治「该不该收」，不碰「怎么收」）**：

| 改动 | 内容 |
|---|---|
| 判定改时间制 | `refloorFrames` → `refloorHoldMs = 48ms`（≈3 帧）；`FloorTracker.lowFrames` → `lowSince`。同一时刻重复观测**幂等** ⇒ 多处喂帧不会把确认时长喂没 |
| `scheduleShrinkProbe` | 偏低未确认时按 `shrinkProbeDelay` 剩余时长排一次定时器 ⇒ 确认延迟 ≈ 48ms，与 render 频率脱钩 |
| `scheduleReclaimRetry` | 回收被冷却压掉时按 `collapseRetryDelay` 排一次 ⇒ 落实「窗口过了再重判」 |
| `resolveReclaimPlan` | 「先对齐 `scrollTop`、再压 `min-height`」抽成**成对**返回值，断言钉住 `scrollTop + clientHeight === minHeight`（无 clamp 余量）—— 「回不去 iter-30」的机器可验证保险 |

**不动的**：跟随姿态、提前量、回收目标、240ms 冷却锁本身、`min-height` 直写 DOM 的约定。两条修法都只在「**回收该不该发生**」这一层。

**门禁**：`typecheck` 0 错；`npm test` **67/67**；`scroll-watermark` 套件 **58 → 88 checks**。实施中一处断言写错（`resolveReclaimPlan` 的 `Math.max(0, …)` 兜的是「不为负」而非「兜到 `gapTarget`」）—— **改断言不改代码**。

**待复验**：空白期是否从 0.3~0.5s 掉到 ≈0.29s（其中 240ms 是冷却锁，将成为唯一瓶颈）；若仍嫌白，再单独动冷却锁（240 → 80）并单独验拉锯。
