## 一、原话 / 来源

## 二、现象（拆两句）

1. 子 Agent 的**渲染卡片不追着贴底**；
2. **滚动条一直在顶部**。

⇒ **「哪个滚动条」尚未坐实** —— 全仓有**三个**候选容器（见 §三），三者成因与修法完全不同。**这一段必须先由老大确认**（§五）。

## 三、候选容器（实读，行号为 2026-10-09 快照）

| # | 滚动容器 | 位置 | 当前行为 | 与描述的吻合度 |
|---|---|---|---|---|
| **A** | **卡片内「步骤列表」** | `components/chat/SubAgentCard.tsx:90`（`SubAgentStepList`，函数体 `:72-139`） | `max-h-[240px] overflow-y-auto`；**整个函数没有任何 `ref` / `useEffect` / `scrollTop` 操作** ⇒ 步骤不断追加时，滚动条停在原位 | ★★★ **卡片主体内唯一「自带滚动条」的容器**（同文件 `:189` HoverCard 的 Prompt 区另有一处，不属卡片主体），字面最吻合 |
| **B** | **子 Agent 详情面板的转录** | `components/layout/SubAgentExecutionDetail.tsx:379` → `components/chat/TranscriptMessageList.tsx:108-117` | `autoScrollToBottom={Boolean(effectiveAgent?.isRunning)}`；该 flag 为假时 **effect 直接 `return`，完全不贴底** | ★★ 是「面板」不是「卡片」 |
| **C** | **聊天窗主滚动** | `components/chat/MessageList/useMessageListScroll.ts`（**S-176 地盘**） | S-176 真机残留（老大 11:13）：「滚动条实际没有到底部、高度没回收、越拉越长、输出结束才回收」 | ★ 更像 **S-176 残留**，不是新问题 |

### A 的细节

- `SubAgentStepList` 内的 `forceUpdate`（`:79`）只服务于审批按钮（同意 / 拒绝）后的重绘，**与滚动无关**；
- 卡片展开时外层是 `motion.div`（`SubAgentCard.tsx:466-471`，0.15s 高度动画，`overflow-hidden`），**内层**才是那个 240px 滚动区。

### B 的细节

- 贴底 effect 的依赖 = `[autoScrollToBottom, renderableMeta.length, revisionKey, streamingMessageId]`，任一变化就 `requestAnimationFrame` 里 `scrollTop = scrollHeight`；
- ⇒ **「跑着的时候」本该贴底**；真不贴底**只可能发生在 `effectiveAgent?.isRunning` 为假**（排队中 / 已结束 / 状态没跟上）。这条要留意：**若 S-178 落地「排队态可见」，排队期 `isRunning=false`，详情面板将完全不贴底。**

## 四、与 S-178 的关系（老大点名的「息息相关」）

| S-178 | **状态文字不对**（排队显示成「工作中」） |

⇒ **建议 S-179 排在 S-178 之后动刀**，或至少两刀同批规划。
