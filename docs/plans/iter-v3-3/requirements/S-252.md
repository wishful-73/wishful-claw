## 3. 硬约束

1. **断言零删减**：改前逐套件记录断言数（`ok  <套件名>  <秒>  <N> assertions`），改后**逐项对齐**，任何减少即判失败。
2. **断言名一字不改**：断言文字是排查时的定位锚，改名等于毁掉可追溯性。
3. **执行顺序不变**：`main` 内的套件调用顺序保持原样（部分套件依赖前序套件写入的 DB 状态）。
4. **`partial class` 修饰一致**：`Program` 已是 `internal static`，新分部必须同样写 `internal static partial class Program`。
5. **`scripts/` 不入库**：`deploy.mjs` 及 `scripts/deploy/*.mjs` 被 `.gitignore` 排除，只在本机生效，**不进提交**；验收以本机 `node scripts/deploy.mjs` 正常打印 usage 为准。
6. **拆完头部标注清理**：降到 500 行以下后删掉「超标待拆分」三行注释。
