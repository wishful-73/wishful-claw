## 一、诉求

我们的需求正文（`requirements/S-{NNN}.md`）已经写了**现象 / 代码链路 / 根因 / 修复方向 / 验证要求**。参考项目那份还多两类段落，而那两类恰恰最值钱：把「我知道这个代价，我是故意的」钉在纸上，防止后人当 bug 修回去。

## 二、参考项目写了什么（实读）

除症状 / 根因 / 修复 / 测试外，它稳定地包含：

### ① 代价（刻意保留）

v2.5.0 原文：

> **代价（刻意保留）**：升级后第一次启动时还没有标记，已经选了「跟随对话」的人会被**最后顶回一次**；从第二次启动起不再发生

### ② 故意不做

v2.3.0 原文：

> **故意不做**：不转格式（`.jpg` 存一张 PNG 只在回执里提醒，不偷偷转码）、不进撤销 / 审查记录（`recordChange` 记的是文本前后内容，二进制放进去只会让 diff 视图出乱码）

### ③ 判据的「为什么是这条」

同篇还有一类，解释**为什么选这个判据**而非另一个：

> 不校验就等于「谁都能让主进程往剪贴板或磁盘里放一段由它决定的内容」
>
> 两条通道各写一份的话，**迟早只有一条被加强**，而弱的那个留着的正是这个口子
