## 一、告警原文

`dotnet build` 每次都会打这两行（同一个包的同一份告警，编译两个目标各打一次）：

```
D:\claw\wishful-claw\src\runtime\WishfulClaw.Worker\WishfulClaw.Worker.csproj :
warning NU1903: 包 "Microsoft.DotNet.ILCompiler" 11.0.0-preview.7.26381.103
具有已知的 高 严重性漏洞，https://github.com/advisories/GHSA-p3jp-9v83-76w9
```

这是本迭代门禁里「2 个警告」的全部来源 —— **0 个错误，0 个我们自己的警告**。

## 三、实际暴露面：零（已逐项查实）

公告原文关键句：

> Applications are **not exposed merely because an affected .NET package is installed**. Exposure requires the application to decompress attacker-controlled Brotli data.

即：装了这个包不等于挨打，得有代码真的去解压攻击者可控的 Brotli 数据。三条入口全部核对：

| 暴露路径 | 我们的情况 | 证据 |
|---|---|---|
| 显式用 `BrotliStream` / `BrotliDecoder` | **0 处** | 542 个 `.cs` 里搜 `Brotli` 零命中 |
| ASP.NET Core `AddRequestDecompression` | **0 处**（我们不是 web 应用） | 同上零命中 |
| `HttpClient` 自动解压 | **显式关死** | 全仓唯一 `new HttpClient` 在 `Infrastructure/Http/WorkerHttpClientFactory.cs:44`，`:36` 明写 `AutomaticDecompression = DecompressionMethods.None` |
| 手动加 `Accept-Encoding` | **0 处** | 542 个 `.cs` 里搜 `Accept-Encoding` / `AcceptEncoding` 零命中 |

`DecompressionMethods.None` 还有个附带效果：连 `Accept-Encoding: br` 都不会自动发出去，服务端根本不会回 Brotli 内容 —— 这条路径从两端都够不着。

**结论：这条告警对我们是纯噪声，不是待修的安全问题。**

## 四、为什么不能「改个版本号」了事

`Microsoft.DotNet.ILCompiler` **不是我们显式引用的包**，是 `<PublishAot>true</PublishAot>`（`WishfulClaw.Worker.csproj:12`）由 SDK 隐式带进来的，版本跟 SDK 绑死：

```json
// src/runtime/global.json
{
  "sdk": {
    "version": "11.0.100-preview.7.26381.103",
    "rollForward": "latestFeature",
    "allowPrerelease": true
  }
}
```

⇒ 要消掉告警，必须装 .NET 11 **rc.3** 的 SDK 再改 `global.json`。而 preview.7 → rc.3 中间跨了 rc.1 / rc.2 / rc.3 三个版本，AOT 发布链路（`build:worker:prod` → `scripts/publish-aot-worker.mjs`）整条要重走并重验。

本机现状（`dotnet --list-sdks`）：`7.0.100` / `10.0.100` / `10.0.302` / `11.0.100-preview.7.26381.103` —— 没有 rc.3。

## 五、处理时机与做法（以后处理时照这个走）

**时机：等 .NET 11 正式版（GA）发布。** 不升 rc.3。理由：

1. 实际风险为零（§三），没有任何紧迫性
2. 升到 rc.3 之后 GA 一出还得再升一次 —— 中间那次纯属白干
3. 等 GA 一次性升，连带把四个 preview 包的版本问题一起解决（`global.json` 一处改完，sln 两条一起重验）

**到时要做的事：**

1. 装 .NET 11 GA SDK
2. 改 `src/runtime/global.json` 的 `version`，`allowPrerelease` 视 GA 情况决定是否保留
3. `dotnet build src/runtime/WishfulClaw.sln -t:Rebuild` ⇒ 期望 0 警告 0 错误
4. `npm test` 全量（C# 33 套会重编）
5. `npm run build:worker:prod` 走一遍 AOT 发布，确认产物能起、能跑一轮对话 —— AOT 换编译器版本最容易在这里出幺蛾子（裁剪 / trim warning / 运行时反射缺失）
6. 打一个安装包，真机验一遍

## 六、明确不做

- **不用 `NoWarn` / `NoWarn=NU1903` 压掉这条告警。** 压安全告警是坏习惯 —— 将来真有能打到的洞也看不见了。这 2 行黄字留着当提醒，成本为零。
- 不动 `WishfulClaw.Worker.csproj` 的包引用（它本来就没显式引 ILCompiler）。
- 不为这条告警动 AOT 配置。

## 七、下次看到这条告警时

先看 §三 —— 只要 `WorkerHttpClientFactory.cs` 还是 `AutomaticDecompression = DecompressionMethods.None`、全仓还是零 `BrotliStream`，就是零暴露，别重新查一遍公告。真正该动的时候是 .NET 11 GA 发布，按 §五 走。
