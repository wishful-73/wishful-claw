# S-222：聊天窗内时间统一为时分（HH:MM），跨天补日期

## 1. 原话 / 来源

> 2026-10-23 09:55，老大：「登记一个需求 聊天窗内的时间都是时分 HH:MM 如果大于一天的显示上日期」

## 2. 目标

聊天窗里出现的每一个时刻，遵循同一条规则：

- **当天** → 只有时分，`09:55`
- **不是当天** → 带上日期，`10-22 23:41`

现在三处落点各写各的：两处只有时分（跨天分辨不出是哪天），一处**今天也强行带日期**（反而更啰嗦）。

## 3. 现状（2026-10-23 实查）

| 落点 | 文件:行 | 现在输出 | 问题 |
|---|---|---|---|
| 用户消息右下 | `chat/UserMessage.tsx:243` | `09:55` | 跨天分辨不出 |
| 助手消息结束行 | `chat/AssistantMessage/action-bar.tsx:160` | `09:55 · 用时 12s` | 跨天分辨不出 |
| 压缩卡片「压缩于 / 你上次发言」 | `chat/ContextCompressionMessage.tsx:24` | `10-23 09:55` | **今天也带日期**，与另两处不同调 |

三处的实现方式也不一致：前两处 `toLocaleTimeString([], {...})`，第三处 `toLocaleString(language, { month, day, hour, minute })`。

### 3.1 范围外（本次不动）

| 位置 | 为什么不归本需求 |
|---|---|
| `activity/ActivityPanel.tsx:88` | 活动面板，**带秒**是有意的（排障要看先后） |
| `workspace-sidebar-items.tsx:44` | 左栏会话列表，不是聊天窗 |
| `usage-detail-table.tsx:109` | 用量明细表，列宽允许完整时间 |
| `AutomationCalendar.tsx:76` | 定时任务日历，显示的是计划时刻 |
| `goal-session-views.tsx:103` | 目标会话独立视图 |
| `locator-utils.ts:271` | 工具定位日志 |
| `file-search-shared.ts:131` | 文件搜索结果的修改时间 |

**耗时不算本需求**：`formatDurationMs`（`· 用时 12s`、S-210 / S-214 的耗时统计）是时长不是时刻，一律不动。

## 4. 方案

### 4.1 单点工具函数

新建 `src/renderer/src/lib/utils/chat-time.ts`：

```ts
export function formatChatTime(value: number, now?: number): string
```

| 条件 | 输出 | 例 |
|---|---|---|
| 与 `now` 同一自然日 | `HH:MM` | `09:55` |
| 同年、非今日 | `MM-DD HH:MM` | `10-22 23:41` |
| 跨年 | `YYYY-MM-DD HH:MM` | `2025-12-31 23:41` |

无效值（`NaN` / `Infinity`）返回空串，调用方据此不渲染 —— 与压缩卡片现有的 `formatStamp` 行为一致。

### 4.2 三处替换

| 落点 | 改法 |
|---|---|
| `UserMessage.tsx` | `toLocaleTimeString([], {...})` → `formatChatTime(createdAt)` |
| `action-bar.tsx` | → `formatChatTime(finishedAt)`，后面的耗时拼接不变 |
| `ContextCompressionMessage.tsx` | 删本地 `formatStamp`，改调 `formatChatTime` |

## 5. 裁定与实现决策

### 5.1 老大已定（2026-10-23 09:55）

- 聊天窗内一律时分 `HH:MM`
- 超过一天补日期

### 5.2 以下由我拍板，不再上报

| # | 决策 | 理由 |
|---|---|---|
| 1 | 「超过一天」按**自然日**判，不按滚动 24 小时 | 用户心智是「今天 / 昨天」，不是「距今 24 小时内」。昨晚 23:50 的消息今早 08:00 看，应该已经带日期 |
| 2 | 年份**只在跨年时**出现 | 今年的历史消息不必每条都背一遍年份 |
| 3 | 固定 24 小时制（`hour12: false`） | 老大要的就是 `HH:MM`；跟随 locale 会在英文面变成 `2:41 PM`，一处宽一处窄 |
| 4 | 压缩卡片一并纳入 | 它现在今天也带日期，与本需求方向相反，不改就成两套口径 |
| 5 | **不做定时刷新** | 跨过午夜后，已在屏幕上的旧消息要等下一次重渲染才更新。为此挂一个午夜定时器不划算，且用户滚动/发消息都会触发重渲染 |
| 6 | 落点 `lib/utils/chat-time.ts` 单点导出 | 三处复用；以后范围要扩也只改这一处 |

## 6. 代价与取舍

- **24 小时制对英文面不常规** —— 美国用户习惯 AM/PM。但换来的紧凑和一致性更值；真要改只动一个函数里的 `hour12`。
- **判据依赖本地时区** —— 改系统时区后，同一条旧消息的显示可能从 `09:55` 变成 `10-22 23:55`。可接受，肉眼只影响历史区。
- **跨午夜不自动更新** —— 见 5.2 第 5 条。

## 7. 刻意不做

- 不碰 §3.1 那 7 处（语境不同：有的要秒、有的是列表列、有的是计划时刻）
- 不做相对时间（「3 分钟前」）
- 不动耗时 / 时长的显示
- 不给日期加「今天 / 昨天」这类文字 —— 要的是省地方，不是更啰嗦

| 场景 | 期望 |

| 今天发的消息 | 用户消息、助手结束行都只显示 `09:55` |
| 昨天的消息 | 显示 `10-22 23:41` |
