## 二、现象

1. **单位到 M 封顶** —— 累计 token 超过 1e9 仍在 M 段显示（`1127.85M`），读数要自己心算。
2. **同一数值、三套实现、三种串** —— 实测 `1127850000` 在三个位置分别吐出 `1127.9M` / `1127.85M` / `1127.85M`；连后缀大小写都不统一（`k` vs `K`）。
3. **漂移会持续扩大** —— 改一处、另两处不动；这个迭代里已多次为「同一数值不同串」付出排查成本。

## 四、方案（老大授权「按推荐」⇒ 本节即定案）

1. **合并成一份** —— 只保留 `lib/format-tokens.ts` 的 `formatTokens`；实现 2 / 3 删除，调用方改 import 来源。
2. **单位序列** —— `k` / `M` / `G` / `T`（1e3 / 1e6 / 1e9 / 1e12）；`< 1000` 直接输出整数原值。
3. **精度规则（统一）** —— 同一单位内：值 `< 10` 两位小数、`< 100` 一位小数、`≥ 100` 整数。
4. **后缀统一小写 `k`**（`M` / `G` / `T` 本为大写）—— 与用户可见面最多的实现 1 一致，也符合 SI 前缀写法。
5. **进位处理** —— 四舍五入后若跨越阈值（`999999` → `999.999k` → `1000k`），升一级单位重算 ⇒ `1.00M`。
6. **防御** —— `!Number.isFinite(n) || n <= 0` ⇒ `'0'`（沿用实现 3 的既有防御；token 无负值）。
7. **`formatTokensDecimal` 直接删除** —— 不再保留两套。
8. **上下文环（`InputArea/context-ring.tsx`）不改调用逻辑** —— 只跟随统一实现，环上刻度自动获得同一口径。

**换算对照（验收判据用）**

| 输入 | 输出 | 说明 |
|---|---|---|
| 0 / 负数 / `NaN` | `0` | 防御 |
| 850 | `850` | < 1000 |
| 1000 | `1.00k` | < 10 → 两位 |
| 1234 | `1.23k` | |
| 12500 | `12.5k` | < 100 → 一位 |
| 123456 | `123k` | ≥ 100 → 整数 |
| 999999 | `1.00M` | **进位升单位** |
| 1127850000 | `1.13G` | `G` 段 < 10 → 两位 |
| 1e12 | `1.00T` | |
