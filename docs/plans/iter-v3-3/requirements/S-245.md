# S-245：耗时读数去掉小数（秒档一律取整）

> 小需求。渲染端 9 处 + 主进程 1 处，C# 无改动。无新功能，只统一一种读数的写法。

## 1. 原话 / 来源

> 2026-10-27 16:27 老大：

> 登记一个小需求 耗时里面 s 出现了 7.3s 这种格式 1.1s 这种 我希望不要有小数。

性质：**体验（排版 / 读数规范）**。渲染端 + 主进程各一处口径。

归属：**v3-iter-3（产品 1.0.3）**。

编号：S-245。

## 2. 目标

耗时读数里**秒档不出现小数**：`7.3s → 7s`、`1.1s → 1s`。

`ms` 档不动（`14ms` 这种是有效信息，取整成 `0s` 就废了）。
`h` / `m` 档本来就没小数，不动。

## 4. 落点

### 4.1 改法：一处定义，全局复用

`lib/format-duration.ts` 的 `formatDurationMs` 是**零依赖叶子模块**（`:42-44` 的注释就是这个理由：能在 node 侧单测）。以它为唯一口径：

1. 秒档改 `Math.round`：`digits` 那套逻辑删掉
   ```ts
   // 现在
   const digits = totalSeconds >= 10 ? 0 : 1
   return `${totalSeconds.toFixed(digits).replace(/\.0+$/, '')}s`
   // 改后
   return `${Math.round(totalSeconds)}s`
   ```
2. 分钟档的秒部分同样取整（`1m23s`，不出 `1m23.4s`）
3. 其余调用点（`#2` `#3` `#4` `#5` `#6` `#8` `#9`）**把手写的实现换成调用 `formatDurationMs`**，删掉本地函数
4. `#7` `formatRetryDelay` 与 `#10` 主进程内联各自改成取整（`#10` 在主进程，引不到渲染端模块，就地改）

### 4.2 边界的取整方式

统一 `Math.round`，与 `#1` 现有 `toFixed(0)` 的四舍五入语义一致 —— 不改成截断（`1.9s` 显示 `1s` 会让人以为慢的更快，反过来怪）。

| 输入 | 现在 | 改后 |
|---|---|---|
| `340ms` | `340ms` | `340ms`（不动） |
| `1100ms` | `1.1s` | `1s` |
| `7300ms` | `7.3s` | `7s` |
| `1960ms` | `2.0s → 2s` | `2s` |
| `12_400ms` | `12s` | `12s`（不动） |
| `83_400ms` | `1m23s` | `1m23s`（不动，秒部分已取整） |
| `5_400_000ms` | `1h30m` | `1h30m`（不动） |

### 4.3 不跟着改的两处（有意保留小数）

| 位置 | 读数 | 为什么保留 |
|---|---|---|
| `InputArea/utils.ts:44-47` `formatRuntimeTtft` | `1.23s` | **首字延迟是性能指标，不是耗时读数**。1.2 与 1.8 的差别对排查有意义，取整就把信号抹平了 |
| `AssistantMessage/utils.ts:340-349` `formatPreciseDurationMs` | `1.2s` | **同上** —— 实施时查出它唯一的调用点是 `use-completion-summary.ts:214` 的 **TTFT**，本号原以为它是「折叠块耗时」，勘误见 §9.4 |
| 同文件 `formatRuntimeThroughput` | `12.34 tok/s` | 吞吐同理 |

分界线：**「这件事做了多久」→ 取整；「快不快」→ 保留精度**。

## 6. 风险

| # | 风险 | 处置 |
|---|---|---|
| 1 | **删本地函数漏改调用点** ⇒ 编译报错或某处继续出小数 | 每处删之前先搜该函数名在本文件的引用；`typecheck` 兜底 |
| 2 | `sub-agent-run-data.ts` 的 `formatElapsed` 可能被别处 import | 先搜全仓引用再删，有外部调用就保留导出、内部转调 |
| 3 | 取整后 `1.4s` 显示 `1s`、`1.6s` 显示 `2s` —— 视觉上「跳字」以为卡了 | 统一 `Math.round` 四舍五入；`ms` 档存在 ⇒ 1s 以下仍有精度，观感可接受 |
| 4 | 把 TTFT / 吞吐一起「顺手统一」了 | §4.3 明确保留，验收第 9 条专门盯 |
| 5 | 主进程那份改完没单测覆盖 | `plugin-command-stats` 若有测试则补断言；无测试则人工看一次输出文本 |

## 7. 不做什么

- **不改 `ms` 档** —— 1s 以下保留毫秒整数
- **不改 h / m 档的小时部分** —— 本来就没小数
- **不动 TTFT / 吞吐这两个性能指标** —— 见 §4.3
- **不新建 `lib/duration` 之类的公共层** —— `format-duration.ts` 已经是那个层，够用
- **不动更新弹窗 / 下载进度里的剩余时间** —— `updater` 侧自己一套格式化，不在本次口径内
- **不修「59.6s 进位成 60s」的既有进位瑕疵** —— 本次只去小数，进位行为原样保留（已在测试里显式锁住）
