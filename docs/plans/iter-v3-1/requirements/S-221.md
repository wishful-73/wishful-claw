# S-221：官网首页右侧悬浮联动导航（板块锚点）

## 1. 原话 / 来源

> 2026-10-23 09:20 老大：

> 先登记一个官网改进需求 首页元素很多 目前都是依靠下拉去看下面的元素 我希望增加右侧悬浮块，增加一个联动导航 把主页大板块的变成超链接

性质：**官网侧新功能**，无软件改动。

## 2. 目标

首页现有 7 个大板块，全部靠鼠标滚轮往下翻，用户不知道下面还有多少内容、也回不到某一块。要补一条**常驻的右侧悬浮导航**：

1. 悬浮块列出首页各板块，本身就是超链接
2. 滚动时高亮当前所在板块（联动）
3. 点击即跳转到该板块

### 3.2 锚点基础已经存在

- **平滑滚动**：`index.css:24-25` 已是 `html { scroll-behavior: smooth }`
- **跳转偏移**：`components/ui.tsx:45` 的 `Section` 统一带 `scroll-mt-24`（96px），顶栏高 `h-14`（56px）⇒ 留 40px 余量，锚点不会被吸顶栏遮住。**锚点跳转不需要额外处理**
- **模板复用点**：`Section` 已把 `id` 透传到 `<section>`，六个板块零改动（除 Hero）

### 3.3 顶栏导航不承担这件事

`components/site-header.tsx:35-45` 渲染 `site.ts:73` 的 `nav`，是**页面级**导航（首页 / 使用指引 / 更新日志外链 / FAQ），只有 `./#faq` 一个锚点。

⇒ 悬浮块与顶栏分工清晰：**顶栏管跨页面，悬浮块管页内板块**。不合并、不互相替代。

## 4. 方案

### 4.1 落点

新增 `website/src/components/section-rail.tsx`，在 `App.tsx` 的 `<main>` 之后挂一次（与 `SiteMist` 同级）。

`/guide`（`doc-page.tsx`）与 `/download`（`download-page.tsx`）不含首页板块，**不挂**。

### 4.2 交互

| 项 | 做法 |
|---|---|
| 位置 | `fixed right-*`，垂直居中，`z-40`（低于顶栏 `z-50`，不与吸顶栏抢层） |
| 形态 | **竖排文字常显**（`[writing-mode:vertical-rl]`），不用圆点。`text-xs`；未选中 `text-ink-900/75`，选中 `text-ink-950` + `font-semibold` + 右侧 2px `bg-accent` 竖条 |
| 选中效果 | 当前板块那一项深色加粗 + 竖条标记；**不做进度条**。品牌色文字对白底仅 ≈3.6:1、不达 AA，颜色信号交给竖条 |
| 点击 | `<a href="#{id}">`，靠 `html` 的 smooth scroll 落地 |
| 联动 | `scroll`（`passive`）+ `rAF` 合并，每次**全量**重算「阈值线以上最后一个 section」；页顶短路给第一项、页底兜底给最后一项。**不用 `IntersectionObserver`** —— 回调只交付本次变化的 entries，上滚时相交集合为空会落进「保持上一个」，回顶／上滚必错 |
| 小屏 | `lg`（1024px）以下 `hidden` |
| 无 JS 降级 | **N/A**。本站纯 CSR（`index.html:15-16` 空 `#root` + `main.tsx:6-10` 挂载，`vite.config.ts:36` `appType:'mpa'` 无 SSG），禁 JS 整页空白。真意是**导航项为真 `<a href>`、不依赖 JS 跳转**，这一条按此验 |
| 可读性 | 文字常显会与通栏内容重叠（`Features` / `Advantages` 全宽铺满，见 `ui.tsx:47`），未选中项 `text-ink-900/75`、字号 `text-xs`，悬停升到 `text-ink-950` |

### 4.3 需要补的锚点

Hero 目前没有 id（`sections/hero.tsx:22` 是裸 `<section>`，不是 `Section` 组件、也没有 `scroll-mt`，挂上去落点同样是 `scrollY = 0`）。**不碰 `hero.tsx`**，改在 `App.tsx` 的 `<SiteHeader />` 之前插零高锚点 `<span id="top" aria-hidden="true" className="block h-0" />` —— 它 `top = 0`，点击落点是真正的 `scrollY = 0`，且位置保证先于任何区块，后续 Hero 结构怎么改都不受影响。

## 5. 裁定与实现决策

### 5.1 老大已拍板（2026-10-23 09:23）

| # | 议题 | 裁定 |
|---|---|---|
| 1 | 悬浮块形态 | **直接呈现文字，不要圆点** |
| 2 | 进度条 | **不做**，有选中效果即可 |
| 3 | 小屏 | **隐藏** |

### 5.2 以下由我拍板，不再上报

- Hero 纳入导航，作「概览」兼回到顶部 —— 老大说的是「大板块」，Hero 就是第一块
- 顶栏 `./#faq` 保留不动，与悬浮块 `#faq` 指向同一处，不冲突
- 判定线用「视口上部 30%，上限 420px」，取「线以上最后一个 section」；页顶短路、页底兜底。不用「相交即选中」（板块高低差大，后者会抖）
- 未选中项 `text-ink-900/75`（≈5.50:1），兼顾常显可读与不抢内容

## 6. 代价与取舍

- **多一个常驻元素**。首页已有 `SiteMist` 背景 + 吸顶栏，悬浮块是第三个固定层。控制手段：`lg` 以下不出现、`z-40` 压在顶栏之下、未选中项 75% 不透明度
- **文字常显与通栏布局的冲突是结构性的**（`Features` / `Advantages` 故意去掉宽度收束）。只能靠不透明度和字号压下去，不能靠留白——留白就等于又回到圆点
- **判定边界会抖**。板块高低差很大（`value-ladder` 是窄带 `pb-5`，`features` 是长块），所以取「阈值线以上最后一个」而不是「首个相交者」
- **滚动监听成本可忽略**。7 个元素在同一 rAF 帧内**批量读** `getBoundingClientRect`，只读不写、不触发重排；且比 observer 的「维护相交集合」更简单，不会有上滚残影

## 7. 刻意不做

- **不做移动端抽屉/悬浮按钮**：375px 上点开一个导航层去跳板块，比直接滑快不了多少
- **不做阅读进度百分比**：官网是营销页，不是长文，进度条没有意义
- **不改顶栏导航结构**：与悬浮块职责不同，合并会把「跨页面」和「页内」两件事搅在一起
- **不给 `/guide`、`/download` 也加**：那两个页面没有大板块，是文档页 / 下载页
- **不引入滚动库**（如 `react-scrollspy`）：原生锚点 + 一次 rAF 合并的 `scroll` 足够，官网目前零外部 UI 依赖

| 场景 | 期望 |
