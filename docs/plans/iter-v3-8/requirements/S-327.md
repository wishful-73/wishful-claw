### ⚠️ 两个必须先定的设计点

**1. 模型 Provider 的目录名不能叫 `Providers/`**

`Agent/Tools/Providers/` 已存在（25 个文件：AskUser / Browser / Cron / Desktop / Ssh / Web / Widget… 是**工具提供者**）。`docs/project-structure.md:56` 已经专门写过一句「⚠️ 别混」—— 说明这个坑踩过一次。

建议叫 **`Llm/`** 或 **`ModelProviders/`**，别再用 `Providers/`。我倾向 `Llm/`：短、无歧义、和 `Tools/Providers` 一眼分得开。

**2. `AgentRuntimeTools.cs`（463 行）不在 52 个之列**

它是 `AgentRuntime*` 族里的「工具注册总入口」，但名字里没有 Executor。归 `Executors/` 还是留根目录，实施时按实际职责定，别按前缀机械分组。

### 执行纪律

- **一刀一簇**：每刀只动一个目录，`dotnet build` 两个 sln 各自 0 错才走下一刀
- **不改逻辑**：只 `git mv` + 改 `namespace`。看到顺手能优化的地方**记下来另开单**，别掺在搬迁里 —— 掺了就没法判断编译错误是搬迁错还是改动错
- **namespace 必须跟着走**：`WishfulClaw.Agent.Executors`。留旧 namespace 等于把「文件位置」和「类型身份」拆成两套，比不搬更糟
- **`InternalsVisibleTo` 不受影响**（按程序集名授权，不按 namespace）
- **测试项目里 `using WishfulClaw.Agent;` 的调用点要跟着改**（`tests/**` 里对 `SessionConversationManager` 等的直接引用）
