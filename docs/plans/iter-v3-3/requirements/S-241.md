# S-241：插件基座（2/5）· 视图独立窗口与生命周期

> 本号是 **R-4 插件基座**拆分出的第 2 条（共 5 条：S-240 ~ S-244）。依赖 S-240。

## 1. 原话 / 来源

> 2026-10-27 14:00 老大：

> 先只做 window（独立窗口），够「能听」用，也不用动主区的页面路由。

> 2026-10-27 13:57 老大：

> 另一种就是带 UI 属于用户自己使用的。这种插件的 UI 是插件自带。

性质：**新增能力（架构地基）**。主进程 + 渲染端，无 C# 改动、无后端改动。

归属：**v3-iter-3（产品 1.0.3）**。

编号：S-241。

## 2. 目标

把 S-240 声明的 `views[]` 真正打开成**独立窗口**，插件自带 HTML 自己渲染；并把**进程生命周期**管住（不能一开就漏、一崩就死）。

## 3. 现状（2026-10-27 实读源码）

### 3.1 `webviewTag` 已开，但没人用

`src/main/index.ts:123` `webviewTag: true` —— 载体基础在，全仓无 `<webview>` 使用点。

### 3.2 现有独立窗口的两个先例，都不是插件窗口

| 窗口 | 文件 | 特征 |
|---|---|---|
| 剪贴板浮窗 | `clipboard-enhancer.ts:574` | `frame: false` + `alwaysOnTop: true` |
| 快捷启动器 | `quick-launcher.ts:2127` | `frame: false` + `transparent: true` |

⇒ 「开一个独立 BrowserWindow」这件事有先例可照抄，但两者都是**主程序自己**的窗口，没有「按插件隔离、可重开、可回收」这套。

### 3.3 生命周期管理是零

全仓没有 `render-process-gone` 处理、没有窗口空闲回收、没有按 pid 树收子进程的工具函数。

## 4. 落点

### 4.1 窗口配置（老大 14:00 / 14:03 定案，权限全开）

```ts
new BrowserWindow({
  width, height,            // 来自 views[].window，缺省 1100×760
  webPreferences: {
    nodeIntegration: true,
    contextIsolation: false,
    sandbox: false,
    partition: `persist:plugin-${pluginId}`   // 只为自己保留登录态与缓存
  }
})
```

加载 `views[].entry`（`loadFile`，路径经 S-240 归一校验）。

### 4.2 生命周期四条

| 场景 | 行为 |
|---|---|
| 启用插件 | 不预开窗口，首次点击才开（懒起） |
| **关窗** | 窗口销毁，但**插件进程状态保留**（会议中重开要快）；重开走新建窗口 |
| **空闲回收** | 窗口隐藏 / 无活动 N 分钟（缺省 15）→ 销毁窗口释放内存；QwenASR 类常驻子进程由插件自己按需重启 |
| **崩溃自愈** | `render-process-gone` → 记录 + 允许重开；不自动狂重启（1 分钟内 ≤ 3 次，超过标红并停手） |
| **主程序退出** | 按 pid 树收掉插件起的子进程（`taskkill /T` 或 node 侧 `tree-kill` 等价实现） |

### 4.3 文件落点

| 文件 | 内容 |
|---|---|
| 新增 `src/main/plugins/plugin-window.ts` | 开窗 / 重开 / 销毁 / 崩溃处理 / 窗口注册表（`pluginId → BrowserWindow`） |
| 新增 `src/main/plugins/plugin-lifecycle.ts` | 空闲计时、pid 树回收、退出钩子 |
| 新增 `src/main/ipc/plugin-view-handlers.ts` | `plugin-view:open` / `close` / `list` / `status` |
| `src/main/index.ts` | 注册 `render-process-gone`、`app.on('before-quit')` 钩子 |

## 5. 验收

1. 假插件声明 `views[0].mode: 'window'` → 点击入口，独立窗口打开，窗口内是插件自己的 HTML
2. 窗口内 `require('fs')` / `process.versions.node` **可用**（证明权限全开生效）
3. 关窗再点入口 → 秒开（< 1s），不残留旧窗口
4. 窗口内 `process.crash()` → 主程序不挂，入口仍可点开
5. 窗口内存泄漏自测：开 / 关 10 次，主进程内存不持续增长
6. 插件启动一个 `ping -t` 子进程 → 主程序退出后，该进程**消失**（pid 树回收生效）
7. 主窗口与插件窗口互不影响：插件窗口卡死时长按，主窗口仍可操作

## 6. 风险

| # | 风险 | 处置 |
|---|---|---|
| 1 | **权限全开 = 插件可任意 exec、任意读写**（老大 14:03 已知情接受） | 不做权限限制；仅保留「安装时告知」 |
| 2 | 插件窗口 OOM 拖慢整机 | 空闲回收 + 崩溃次数上限；不做内存硬限制 |
| 3 | `partition` 与主窗口共享 session 会串登录态 | 强制 `persist:plugin-<id>`，不复用默认分区 |
| 4 | 插件窗口崩了自动狂重启 | 1 分钟 ≤ 3 次，超过停手并标红（避免死循环吃 CPU） |

## 7. 不做什么

- **不做 `mode: 'panel'`** —— 老大定先只做 window
- **不做插件权限沙箱 / 白名单** —— 老大 14:03 明确「避免不了的东西，没必要去防」
- **不做窗口内 IPC 白名单桥** —— 权限全开，`wishful` 只是可选糖（见 R-4）
- **不做多窗口同一插件**（每个插件同时最多 1 个窗口）
