## 三、技术选型（2026-09-21 老大「按照你的推荐来」）

| 项 | 选定 | 理由 |
|---|---|---|
| 技术栈 | **Vite + React 19 + Tailwind 4** | 复用本仓现有依赖，**不引新工具链**；Astro 虽更利 SEO，但要几百 MB 新依赖，不值当 |
| 依赖归属 | **独立 `package.json`** | 官网依赖与主程序隔离，互不污染 |
| 位置 | **根级 `website/`** | 与 `src/` 并列 —— 概念上不属于 electron 应用 |

## 四、门禁零污染（2026-09-21 已核证）

放根级 `website/` 后，现有链路**一条都不用改**：

| 链路 | 现状 | 是否扫到 `website/` |
|---|---|---|
| `tsconfig.node.json` | `include` = `electron.vite.config.*` / `src/main/**` / `src/preload/**` / `src/shared/**` | **不会** |
| `tsconfig.web.json` | `include` = `src/renderer/src/**` / `src/preload/*.d.ts` / `src/shared/**` | **不会** |
| `electron-builder.yml` `files` | **白名单**（只收 `out/**/*` + `package.json` + 若干根文件，且已 `!src/*`） | **不会进安装包** |
| `.gitignore` | `node_modules/`、`dist/` 为宽泛匹配 | 官网产物已被忽略 |
| `scripts/run-tests.mjs` | 认 `test:*` 脚本名（TS）+ 目录名 `WishfulClaw.*RegressionTests`（C#） | 除非官网加 `test:*` 脚本 |

**尾注**：官网若要纳入主门禁，只需给它加 `test:*` 前缀的脚本（`run-tests.mjs` 自动收）；不想纳入就别用该前缀。

## 附录：下载源设计结论（推迟实施，备查）

**问题**：GitHub Releases 国内不稳 —— 这**同时**是官网下载页的病（官网方案 L270）**和** app 内更新链路的病（S-111：巡检失败只落日志、打包时 electron-builder 拉二进制超时）。

**结论**：**一个源，两个消费方**。

```
腾讯云 COS（免备案，约 0.5 元/GB 外网下行）
├── wishful-claw-0.2.N-setup.exe     ← 官网下载页点这里
├── latest.yml                       ← app 内更新（electron-updater）读这里
└── latest.json                      ← 官网下载页读这里（由 latest.yml 派生）
```

- `latest.yml` 由 electron-builder **已经产出**，字段（`version` / `path` / `sha512` / `size` / `files[].url`）正好是官网下载页需要的全部信息 ⇒ 发版脚本**顺手转换**即可，不用新写数据源。
- 官网页面**运行时读 `latest.json`**（而非构建时注入）⇒ 发版**零官网构建**，正合官网方案「下载页独立、便于只改一处」的初衷。
- 发布流程插入点：`docs/release-workflow.md` 4.3「上传资产」之后加一节「同步下载源」，**现有步骤一个不动**。
- 遗留决策（届时拍）：COS 上线后 GitHub Release 那段**是否保留**（海外兜底 or 只留 COS）。

**启动条件**：老大 2026-09-21 指定 —— **等官网备案过后再调整**。
