# S-221：官网首页右侧悬浮联动导航（板块锚点）

## 1. 原话 / 来源

> 2026-10-23 09:20 老大：

> 先登记一个官网改进需求 首页元素很多 目前都是依靠下拉去看下面的元素 我希望增加右侧悬浮块，增加一个联动导航 把主页大板块的变成超链接

性质：**官网侧新功能**，无软件改动。

## 2. 目标

首页现有 7 个大板块，全部靠鼠标滚轮往下翻，用户不知道下面还有多少内容、也回不到某一块。要补一条**常驻的右侧悬浮导航**：

1. 悬浮块列出首页各板块，本身就是超链接
2. 滚动时高亮当前所在板块（联动）
3. 点击即跳转到该板块

## 3. 现状（2026-10-23 实查）

### 3.1 首页板块顺序

`website/src/App.tsx:27-33`：

| # | 组件 | 已有锚点 id | 文件 |
|---|---|---|---|
| 1 | `Hero` | **无** | `sections/hero.tsx:22` |
| 2 | `ValueLadder` | `value-ladder` | `sections/value-ladder.tsx:12` |
| 3 | `Features` | `features` | `sections/features.tsx:102` |
| 4 | `Advantages` | `advantages` | `sections/advantages.tsx:9` |
| 5 | `DownloadCta` | `download` | `sections/download-cta.tsx:10` |
| 6 | `QuickStart` | `quick-start` | `sections/quick-start.tsx:65` |
| 7 | `Faq` | `faq` | `sections/faq.tsx:6` |

### 3.2 锚点基础已经存在

- **平滑滚动**：`index.css:24-25` 已是 `html { scroll-behavior: smooth }`
- **跳转偏移**：`components/ui.tsx:47` 的 `Section` 统一带 `scroll-mt-24`（96px），顶栏高 `h-14`（56px）⇒ 留 40px 余量，锚点不会被吸顶栏遮住。**锚点跳转不需要额外处理**
- **模板复用点**：`Section` 已把 `id` 透传到 `<section>`，六个板块零改动（除 Hero）

### 3.3 顶栏导航不承担这件事

`components/site-header.tsx:35-45` 渲染 `site.ts:73` 的 `nav`，是**页面级**导航（首页 / 使用指引 / 更新日志外链 / FAQ），只有 `./#faq` 一个锚点。

⇒ 悬浮块与顶栏分工清晰：**顶栏管跨页面，悬浮块管页内板块**。不合并、不互相替代。

## 4. 方案

### 4.1 落点

新增 `website/src/components/section-rail.tsx`，在 `App.tsx` 的 `<main>` 之后挂一次（与 `SiteMist` 同级）。

`/guide`（`doc-page.tsx`）与 `/download`（`download-page.tsx`）不含首页板块，**不挂**。

### 4.2 交互

| 项 | 做法 |
|---|---|
| 位置 | `fixed right-*`，垂直居中，`z-40`（低于顶栏 `z-50`，不与吸顶栏抢层） |
| 形态 | **竖排文字常显**，不用圆点。未选中 `text-ink-900/45`，选中 `text-accent` + 加粗 + 左侧一道竖线标记 |
| 选中效果 | 当前板块那一项换色加粗；**不做进度条** |
| 点击 | `<a href="#{id}">`，靠 `html` 的 smooth scroll 落地 |
| 联动 | `IntersectionObserver` 观察各 `<section>`，取「视口上部 30% 内最靠上的 section」为当前项；用 observer 而非 `scroll` 事件，避免每次滚动触发布局计算 |
| 小屏 | `lg`（1024px）以下 `hidden` |
| 无 JS 降级 | 每一项是真 `<a>`，禁 JS 也能跳，只是不高亮 |
| 可读性 | 文字常显会与通栏内容重叠（`Features` / `Advantages` 全宽铺满，见 `ui.tsx:50`），未选中项压到 45% 不透明度、字号 `text-xs`，悬停整条升到 100% |

### 4.3 需要补的锚点

Hero 目前没有 id（`sections/hero.tsx:22` 是裸 `<section>`）。加 `id="top"`，让悬浮块第一项可作「回到顶部」。

### 4.4 板块清单（对外文案）

7 项，按 `site.ts` 的既有标题口径取，不新造词：

| 锚点 | 文案 |
|---|---|
| `top` | 概览 |
| `value-ladder` | 上手门槛 |
| `features` | 它能干什么 |
| `advantages` | 为什么是它 |
| `download` | 下载 |
| `quick-start` | 快速上手 |
| `faq` | 常见问题 |

> 实施时以 `site.ts` 各段 `title` 的实际文案对齐，这里只是占位。

## 5. 裁定与实现决策

### 5.1 老大已拍板（2026-10-23 09:23）

| # | 议题 | 裁定 |
|---|---|---|
| 1 | 悬浮块形态 | **直接呈现文字，不要圆点** |
| 2 | 进度条 | **不做**，有选中效果即可 |
| 3 | 小屏 | **隐藏** |

### 5.2 以下由我拍板，不再上报

- Hero 纳入导航，作「概览」兼回到顶部 —— 老大说的是「大板块」，Hero 就是第一块
- 顶栏 `./#faq` 保留不动，与悬浮块 `#faq` 指向同一处，不冲突
- observer 判定用「视口上部 30% 内最靠上的 section」，不用「相交即选中」（板块高低差大，后者会抖）
- 未选中项降到 45% 不透明度，解决文字常显与通栏内容重叠

## 6. 代价与取舍

- **多一个常驻元素**。首页已有 `SiteMist` 背景 + 吸顶栏，悬浮块是第三个固定层。控制手段：`lg` 以下不出现、`z-40` 压在顶栏之下、未选中项低不透明度
- **文字常显与通栏布局的冲突是结构性的**（`Features` / `Advantages` 故意去掉宽度收束）。只能靠不透明度和字号压下去，不能靠留白——留白就等于又回到圆点
- **`IntersectionObserver` 的判定边界会抖**。板块高低差很大（`value-ladder` 是窄带 `pb-5`，`features` 是长块），所以取「最靠上者」而不是「首个相交者」
- **滚动监听成本**。用 observer 而非 `scroll` 事件，避免每次滚动触发布局计算

## 7. 刻意不做

- **不做移动端抽屉/悬浮按钮**：375px 上点开一个导航层去跳板块，比直接滑快不了多少
- **不做阅读进度百分比**：官网是营销页，不是长文，进度条没有意义
- **不改顶栏导航结构**：与悬浮块职责不同，合并会把「跨页面」和「页内」两件事搅在一起
- **不给 `/guide`、`/download` 也加**：那两个页面没有大板块，是文档页 / 下载页
- **不引入滚动库**（如 `react-scrollspy`）：observer + 原生锚点足够，官网目前零外部 UI 依赖

## 8. 验收

| 场景 | 期望 |
|---|---|
| 首屏加载 | 右侧出现竖排文字导航（7 项），「概览」为当前项（品牌色加粗） |
| 滚动到「它能干什么」 | 该项自动高亮，前一项恢复常态 |
| 点「下载」 | 平滑滚到下载块，落地位置在吸顶栏下方（不被遮） |
| 点「概览」 | 回到页面顶部 |
| hover 某一项 | 整条升到 100% 不透明度，移开回落 |
| 1024px 以下 | 悬浮块不出现，页面布局与现在一致 |
| 禁用 JS | 各项仍可点击跳转 |
| `prefers-reduced-motion` | 不做过渡动画（跟随现有 CSS 的降级约定） |
| 三个页面遍历 | `/` 有悬浮块；`/guide`、`/download` 无 |
