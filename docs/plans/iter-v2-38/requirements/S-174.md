## 九、暂缓记录与重开前置（2026-10-08 16:52 勘测后补）

### 9.1 参考项目的性质（勘测修正）

**我之前把 C 描述成「提示词 → 生图 → 落素材库」的线性流程，给了老大「参考项目是既定工作流」的错误印象。勘测后修正：它是节点图引擎。**

`graph-types.ts:1-7` 原文：

> A graph is a set of typed nodes wired by edges (left = input, right = output). Config nodes read their upstream text/image nodes and generate results into image/text nodes.

| 要素 | 实据（`components/draw/graph/`） |
|---|---|
| 节点种类 | `CanvasNodeKind = 'text' \| 'image' \| 'config' \| 'video'` |
| 配置节点三态 | `ConfigNodeData.mode = 'image' \| 'text' \| 'video'`（**视频本来就在**，含 Seedance 参数：resolution / duration / fps / seed / frameRole …） |
| 自由连线 | `EdgeLayer.tsx` / `connection-context.ts` |
| 每节点运行态 | `NodeExecutionStatus`（queued / running / succeeded / failed / cancelled / **interrupted**）+ `runId` + `NodeExecutionSnapshot` |
| 事件与触发器 | `CanvasNodeEventType`（`run.queued` / `run.progress` / `run.succeeded` …） / `CanvasTrigger`（节点事件 → 触发另一节点） |
| 项目持久化 | `draw-projects-store.ts` / `ProjectSwitcher.tsx` / `graph-persistence.ts` |
| 主进程 | 仅 `db/draw-runs-dao.ts` + `ipc/draw-agent-workspace-handlers.ts` —— **很薄** |

**工程判断**：47 个文件里真正是「引擎」的只有 `graph/` 下十来个逻辑文件，其余大头是**画布皮肤**（`graph-geometry` / `GraphMinimap` / `EdgeLayer` + 六个图像操作对话）。**后端薄、UI 厚。**

### 9.2 「自定义」的三个档位（重开时先定档）

| 档 | 含义 | 参考项目现状 | 工作量 |
|---|---|---|---|
| **1** | 画布自由连线：节点种类代码写死，用户自由摆放、连线、触发 | ✅ 已具备 | 大（移植 ~40 文件 UI） |
| **2** | 节点类型**可扩展**：加新节点不改引擎（注册表 / 插件） | ❌ 无 —— `node-factory.ts` 是写死的 if 链 | 中（重构档 1 骨架） |
| **3** | 任意工具 / 脚本 / MCP 都能当节点 | ❌ 无 | 极大 |

**助手建议**：目标定在**档 1**，移植时**顺手把骨架留对**（节点描述集中成表而非散在 if 链），为档 2 留口子；档 3 不在近期范围。
