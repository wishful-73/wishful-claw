# S-289 · 用量统计折线图未 hover 时圆点太大太抢戏 —— 不交互时不该有圆点

> 归属：**移交 v3-iter-5**（2026-10-30 16:55 老大登记）。
> 定性：**纯视觉噪音**，不是缺陷 —— 图能读、数据没错，只是「没在交互的时候点了一地圆点」。
> 改动面：**一个文件、一处条件渲染**（`components/settings/usage/line-chart.tsx:79-95`）。

## 一、原话

老大 2026-10-30 16:55：

> 「用量统计的**曲线图，未选中时，也就是鼠标没有移上去之前的圆点太大了，有点抢戏**，未 hover 时**没有圆点都是可以的**。」

## 二、现状

`UsageLineChart`（`src/renderer/src/components/settings/usage/line-chart.tsx`）在每个系列的每个数据点上**无条件**渲染一个 `<circle>`：

```tsx
{item.buckets.map((bucket, bucketIndex) => (
  <circle
    cx={xOf(bucketIndex)}
    cy={yOf(bucket.requestCount)}
    r={hoveredBucket === bucketIndex ? '4' : '2.5'}      // ← 非 hover 也画，半径 2.5
    fill={modelColor(seriesIndex)}
    opacity={hoveredBucket === bucketIndex ? 1 : 0.72}   // ← 非 hover 半透明常驻
    ...
```

三个放大问题的因素：

| # | 因素 | 效果 |
|---|---|---|
| 1 | **非 hover 也画** | 圆点数量 = `系列数 × 时间桶数`。默认 24 小时视图 + 3 个模型就是 72 个点；一天 24 桶 × 5 个模型 = 120 个点，图上直接缀满 |
| 2 | **`r=2.5` 不算小** | 折线本身 `strokeWidth=2.5` —— **点的直径正好等于线宽**，视觉上「点和线一样粗」，读起来像一串珠子而不是一条趋势线 |
| 3 | **`opacity=0.72`** | 半透明拼接后成片，比实心更容易糊成一条带子 |

`bar-chart.tsx` 没有这个问题（柱子本身就是形状）。

## 三、根因不是「半径调小就行」

老大的诉求是「未 hover 时**没有**圆点」，不是「圆点小一点」。只把 `r` 调到 1.5 仍然会：①同屏上百个点；②每点多一行 `<title>` 提示，鼠标划过折线时弹原生 tooltip，和右上的 `ChartTooltip` 浮层**同时出现**，信息重复且互相遮挡。

**顺带记一笔冗余**：每个 `<circle>` 上的 `<title>`（`:91-93`）是多余的 —— `ChartTooltip` 是**列级**的（`chart-primitives.tsx:109`，传 `bucket` + 全部 `series`），hover 时已经把这一列所有系列的数据摆出来了。所以删点可以连同 `<title>` 一起删，不会丢信息。

## 四、方案（推荐 A）

### A. 未 hover 只画线，hover 只画那一列的圆点

```tsx
// 线照旧
<path d={smoothPath(points)} ... />

// 圆点只在 hover 的那一列出现
{hoveredBucket != null && item.buckets[hoveredBucket] && (
  <circle
    cx={xOf(hoveredBucket)}
    cy={yOf(item.buckets[hoveredBucket].requestCount)}
    r="4"
    fill={modelColor(seriesIndex)}
    stroke="var(--background)"
    strokeWidth="1.5"
    vectorEffect="non-scaling-stroke"
  />
)}
```

- 未交互：干净的趋势线，`<title>` 与常驻点一起消失；
- hover：原有那套「放大到 4、实心、带描边取底」的高亮**原样保留**，视觉反馈一点没减；
- 代码量**减少**（删掉 list 渲染 + 三条三元表达式）。

### B. 备选（不推荐）：只调小常驻点

`r=2.5 → r=0` 就是 A；`r=1.5 + opacity 0.4` 只是把「抢戏」变成「脏」，且点数问题没解。

**选 A。** 老大原话已经给到这一档了（「没有圆点都是可以的」）。

## 五、边界与取舍

- **触屏 / 无 hover 设备**：折线图上永远不会有圆点。可接受 —— `getHoveredBucketIndex` 走 `mousemove`，触屏本来也拿不到列级 tooltip，两条能力同源。
- **`preserveAspectRatio="none"` 的椭圆变形**：`chart-primitives.tsx:241-245` 记着这个坑，但 `useMeasuredSize` 让 viewBox 与容器 **1:1**，只在首帧（`FALLBACK_SIZE 800×320`，`:267`）或 resize 那一帧有短暂拉伸。**本条不动它** —— 改它属于图表坐标系改造，与「要不要显示点」无关。
- **不新增测试套件**：这是 JSX 条件渲染，没有值得抽的纯判据（抽出 `shouldRenderDot()` 只会造一个一次性导出，与 S-270「出口越少越好」的教训相反）。验收靠真机 4 条 + `typecheck`。
- **顺手可选（不加也行）**：`line-chart.tsx` 的 `<svg>` 缺 `role="img"` + `aria-label`，而同目录 `bar-chart.tsx:58-59` 有。一行补齐，零风险。

## 六、真机验收（4 条）

1. 用量统计 → 曲线图，**鼠标不碰图**：任何系列都没有圆点，只剩折线；
2. 鼠标在图内横向移动：**只有光标所在那一列**出现圆点（该列所有系列各一个），半径与描边和改动前 hover 时一致；
3. 鼠标移出图表：圆点全部消失，无残影；
4. 切到柱状图再切回来、切换时间范围（24 小时 / 7 天）：无圆点残留、无报错。
