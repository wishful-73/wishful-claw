## 一、现象与根因

**澄清一个前提**：下载按钮**不是硬编码** —— `download-buttons.tsx:19` 读 `latest.json` 的 `downloads[urlKey]` 渲染。病根是**版本清单有两份**：

| 文件 | 谁生成 | 谁读 | 后果 |
|---|---|---|---|
| `release/latest.yml` | **electron-builder 自动**（含 version / url / sha512 / size） | app 内更新 | 权威 |
| `website/public/latest.json` | **人手写**（URL 里带版本号） | 官网下载按钮 | **每次发版都要改**；已不同步过一次 —— 2026-09-23 官网线上仍是 0.2.33 的链接 |

第二个症状：官网**只托管了 exe**。`release/` 目录本是 electron-updater 的标准 generic 源，一个文件夹三件：

```
wishful-claw-0.2.34-setup.exe           全量包
wishful-claw-0.2.34-setup.exe.blockmap  差量块映射（必须与 exe 同目录、同前缀，updater 自己拼名字找）
latest.yml                              清单
```

只放 exe ⇒ 官网侧的**差分下载与 app 内更新都不成立**（这是 S-140「丢了差分」那条题的另一面）。

## 二、现状取证（2026-09-23 13:40 实测）

| 项 | 现状 | 位置 |
|---|---|---|

| 平台表 | `platforms[].urlKey` = `windows` / `macos` / `linux` | `website/src/content/site.ts` |

| 打进安装包的 feed | `provider: github` + owner/repo | `release/win-unpacked/resources/app-update.yml` |
| 「查看全部版本」 | `https://github.com/wishful-73/wishful-claw/releases/latest` | `src/main/lib/distribution.ts:6` |
| 线上站点 | `/data/sites/wishfulclaw`（Nginx 三 server 块 + Let's Encrypt + HSTS，2026-09-23 12:57 上线） | 服务器 `119.45.103.252` |
| 线上现状 | 只有「exe 直链」形态的 `latest.json`（还是 0.2.33），**无发布目录、无 blockmap、无 latest.yml** | 线上 |

## 三、定稿方案（老大 13:41 确认口径）

**核心：发布目录 + 清单单一真源**

```
/data/sites/wishfulclaw/
├── index.html · download.html · guide.html · changelog.html · assets/ · screenshots/
└── releases/                       ← 发版唯一要更新的地方（整目录覆盖）
    ├── latest.yml
    ├── wishful-claw-0.2.34-setup.exe
    └── wishful-claw-0.2.34-setup.exe.blockmap
```

1. **官网开 `releases/` 目录**，放 electron-builder 产出的三件（**必须同目录、成套**）。
2. **前端改读 `./releases/latest.yml`** —— `version` 与 `files[0].url` 都在里面，由 builder 自动生成，**发版零手改**；下载链接 = `./releases/<files[0].url>`（相对路径，根部署 / 子目录部署都解析得到）。
   - YAML 只取两个字段，用正则即可（格式由 builder 固定生成）；**取不到就不渲染按钮**、走 GitHub 兜底入口，不让页面挂掉。
   - 备选做法（**不推荐**）：发版脚本把 `latest.yml` 转成 `latest.json`、前端仍读 JSON。多一份要同步的产物，正是本案要消掉的东西。
3. **`website/public/latest.json` 退役**（删文件；`LatestInfo` / `useLatestInfo` 改造为读 yml 的同名 hook，页面调用点不变）。
4. **`electron-builder.yml` 的 `publish:` 切 `generic`** + `url: https://www.wishful-claw.work/releases/` ⇒ **app 内自动更新也走官网**（这是 S-129 的另一半，与官网按钮共用同一份清单）。
5. **`docs/release-workflow.md` 追加「官网发布」节**：GitHub Release 那套步骤**保留**，在其后追加「把 `release/` 三件传到官网 `releases/`」。
6. **差分**：generic 下 updater 用「本地已装版本 + 新 blockmap」算差量 ⇒ 服务器**不需要留旧包**，只留最新最干净。
7. **`distribution.ts` 的「查看全部版本」**指向官网 changelog 页（官网已有 `changelog.html`）。

**待裁定**

- **① 目录名** —— 暂用 `releases/`。
- **② 历史版本留不留** —— 推荐**只留最新**（回滚靠 GitHub Release，本地 `release/` 也留当前版）；要留 2~3 版也可（每版约 110 MB）。
- **③ 更新日志能否「上传即生效」** —— 现阶段 `changelog.md` 是构建时内联（`changelog-page.tsx:1`），发版要重建官网；改运行时 `fetch` 可免，但属本项之外的独立小改。

## 四、验收

| 项 | 标准 |
|---|---|
| 官网按钮 | 发版后**不改任何手写文件**，按钮自动指向新版本（改 `latest.yml` 一处即生效） |
| 下载链接 | 指向 `releases/` 下的 exe；`releases/<name>.exe.blockmap` 可达（非 404） |
| app 内更新 | `app-update.yml` 的 feed 指向官网；实机点「检查更新」拿到 `update-available` |
| 差分 | 打包版日志出现 blockmap 下载、**无 fallback 全量**（S-140 的观察点一并闭环） |
| 文档 | `release-workflow.md` 含官网发布步骤 |
