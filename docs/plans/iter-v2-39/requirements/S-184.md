## 二、已查明事实（静态读码，2026-10-10）

### A —— 项目目录为什么有 6 份（**已判定非 bug，归档**）

**现场**：`D:\claw\wishful-claw\.wishful-claw\personas\` 下实有 **6 个目录**：

```
aming/  default/  jarvis/  lao-zheng/  taozi/  tingjie/
```

每个目录含 `AGENTS.md` / `IDENTITY.md` / `ONTOLOGY.md` / `SOUL.md`。

**与内置 preset ID 集合完全一致** —— `PersonaPresetService.cs:20-23`：

```csharp
public static readonly HashSet<string> BuiltinPresetIds =
[
    "default", "lao-zheng", "jarvis", "taozi", "tingjie", "aming"
];
```

资源在 `src/runtime/WishfulClaw.Persona/Resources/Personas/{id}/`。**全局目录 `%USERPROFILE%\.wishful-claw\personas\` 为空** ⇒ 这 6 份是**从内置 preset 落盘**的，不是从用户全局库拷的。

**落盘代码**：`PersonaStore.CopyToProject(personaId, projectFolder)`（`PersonaStore.cs:318-343`）—— `personaId` 为空时 `idsToCopy = BuiltinPresetIds`，**一次把 6 个全 `SavePersona` 到项目目录**；IPC 面 = `persona/apply-to-project`（`PersonaModule.cs:147-163`）。

**唯一调用点**：`PersonaPanel.tsx:121-129` `handleCopyFromGlobal` → `applyToProject(null, wf)`，挂在**用户点击的按钮**上；**全仓无 `useEffect` 自动触发路径**。

> **结论（经老大 2026-10-10 09:43 确认）**：代码里**不存在「打开项目就自动拷」的路径**；这 6 份是**测试期间经设置页「从全局复制到项目」按钮人为落盘的**。⇒ **非产品缺陷，A 出局**，老大手动清理即可。本段保留作归档。

### B —— 无法点击切换查看

`ProjectArchivePage.tsx:344-359` 人格按钮组：

```tsx
{personas.map((p) => (
  <Button
    key={p.id}
    ...
    onClick={() => setActiveTab('persona')}   // ← 当前就在 persona tab，空操作
  >
```

- **`onClick` 只是 `setActiveTab('persona')`** —— 而用户此刻就在 `persona` tab ⇒ **点了等于没点**；
- `:360-366` 预览区**硬编码 `personas[0]`**，组件内**没有 `selectedPersonaId` 之类的选中态**。

⇒ 点任何一个按钮都没反应，预览永远显示列表第一个 ⇒ 与「切换查看」的预期不符。

### C —— 无法删除

- 人格 tab 内**没有任何删除入口**（`:318-370` 只有列表 + 预览）。
- 删除能力**已存在于设置页**：`PersonaPanel.tsx:114-119` `handleDelete` → `persona/delete`（`PersonaModule.cs:123-143`），**支持 `workingFolder` 参数**（项目层删除）。
- ⇒ 项目档案页没接这条路。

### D —— 附带发现：两处人格列表的语义不一致

| 位置 | 数据源 | 语义 |
|---|---|---|
| 设置页 | `PersonaStore.ListPersonas`（`PersonaStore.cs:75-104`） | **三层合并**：内置 preset → 全局磁盘 → 项目层，**项目层覆盖同名** |
| 项目档案页 | `loadPersonas` → `listDir(项目 personas 目录)`（`ProjectArchivePage.tsx:92-114`） | **只看项目层物理文件**，不做合并 |

⇒ 两处列表回答的不是同一个问题：设置页是「全局 + 项目」的并集，项目档案页是「项目目录里躺了什么」。

**定性**：这本身是**设计选择，不单列为缺陷**；但它决定 B 的实现口径 —— 项目档案页展示的是「项目目录里实际存在的文件」，**落盘进项目的 6 份本来就该出现在这里**。⇒ **问题不在「显示了什么」，而在「显示了却点不动、删不掉」。**

## 三、开放问题（**待老大拍板**）

> 原第 1 条（A 的触发性质）已由老大 2026-10-10 09:43 裁定 —— **A 非 bug，出局**。

1. **C 的删除边界** —— 项目层里 `default` / `lao-zheng` 这类**内置同名副本**允许删吗？删了是否**只影响本项目**？（`DeletePersona` 对内置 preset 的保护**只在全局作用域生效** —— `PersonaStore.cs:299-302`，**项目层可删**。）**助手默认按「项目层可删、只影响本项目」实现**，若与预期不符请指正。
2. 项目档案页是否要改用**合并语义**（`ListPersonas`）而不是现在的 `listDir(项目目录)`？
   - 现状读码：它展示的是「项目目录里实际存在的文件」—— **落盘进项目的都显示，语义上自洽**；
   - 但用户视角可能与设置页（内置 + 全局 + 项目三层并集）**对不上账**。
   - **助手倾向**：**保持 `listDir` 语义**（「项目档案」就该是这个含义）**+ 补上切换 / 删除**，不动合并。
