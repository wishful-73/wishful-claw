# S-345 浏览器工具判据 `isBrowserToolName` 是恒假桩，三处下游全部失效

> 状态：✅ **已修复**（2026-11-06 11:4x，刀 36 = `6da8fe02`）—— `browser-tool-names.ts` 重写成 `Set` + `has`，`tool-block-renderer.tsx` 两处判据同步；`npm run typecheck` 三配置 0 错、`npm test` 127/127。三处下游（浏览器图卡 / `BrowserToolCard` / 时间轴 `browser` 分类）随之复活，**需真机验收**（见 §四）
> 性质：缺陷（空实现被当真值依赖）。**本迭代修**。
> 归属：本迭代。与 S-342 同族（接口在、调用方在、实现是空的），但危害更大 —— S-342 那两个是「拿不到数据」，这个是**一整类工具的特有渲染全部消失**。

---

## 一、是什么

`src/renderer/src/lib/app-plugin/browser-tool-names.ts` 全文 3 行：

```ts
export function isBrowserToolName(_name: string): boolean {
  return false
}
```

**恒返回 `false`**。参数名带下划线前缀也是标准「本函数不使用该参数」的写法，说明写的人知道它没实现。

同目录下的对照物 `desktop-routing.ts`（21 行）是**活的标准写法**：

```ts
const DESKTOP_CONTROL_TOOL_NAMES = new Set<string>([
  DESKTOP_SCREENSHOT_TOOL_NAME,
  DESKTOP_LIST_WINDOWS_TOOL_NAME,
  ...
])

export function isDesktopControlToolName(name: string): boolean {
  return DESKTOP_CONTROL_TOOL_NAMES.has(name)
}
```

浏览器这边该判的名字**全都存在**，就在 `src/renderer/src/lib/app-plugin/types.ts:14-21`：

| 常量 | 值 |
|---|---|
| `BROWSER_NAVIGATE_TOOL_NAME` | `'BrowserNavigate'` |
| `BROWSER_GET_CONTENT_TOOL_NAME` | `'BrowserGetContent'` |
| `BROWSER_SCREENSHOT_TOOL_NAME` | `'BrowserScreenshot'` |
| `BROWSER_SNAPSHOT_TOOL_NAME` | `'BrowserSnapshot'` |
| `BROWSER_CLICK_TOOL_NAME` | `'BrowserClick'` |
| `BROWSER_TYPE_TOOL_NAME` | `'BrowserType'` |
| `BROWSER_SCROLL_TOOL_NAME` | `'BrowserScroll'` |
| `BROWSER_SET_DEVICE_TOOL_NAME` | `'BrowserSetDevice'` |

八个常量，一个 `Set`，一个 `has` —— 就是 `desktop-routing.ts` 那 8 行的形状。**零件全在，只是没接线。**

## 二、三处下游失效（全部实测）

调用点共 3 处（含 import 共 5 处命中）：

### ① `tool-block-renderer.tsx:127-128` —— 浏览器截图不进图卡

```tsx
hasVisualResult:
  block.name === IMAGE_GENERATE_TOOL_NAME ||
  block.name === 'visualize_show_widget' ||
  (isBrowserToolName(block.name) &&
    (block.input as { action?: string }).action === 'screenshot') ||
  !!decodeBashArtifacts(toolOutput),
```

恒 `false` ⇒ 整项永远不成立。

**而且这段本身还有第二层错**：它判的是 `block.input.action === 'screenshot'`，但真实工具名是 `BrowserScreenshot`（名字里就写着 screenshot），根本没有 `action` 字段。两层错叠在一起 —— 就算把 `isBrowserToolName` 修对，`input.action` 那一半仍然是错判据。

→ 后果：**浏览器截图不进图片卡片，用户看不到图**。与老大 11-05 报的「桌面截图卡片 `?×?` 点开啥都没有」是同一类症状，只不过桌面截图那边有真实现（`desktop-routing.ts`），坏的是图片落盘链路；这边是判据直接不通。

### ② `tool-block-renderer.tsx:279-298` —— `BrowserToolCard` 整段死代码

```tsx
if (isBrowserToolName(block.name)) {
  ...
  return (
    <ScaleIn className={liveScaleInClassName}>
      <BrowserToolCard ... />
    </ScaleIn>
  )
}
```

恒不进入 ⇒ **浏览器工具全部落到后面的通用卡片**。

注意 `BrowserToolCard` 本身是**活的、完整的**：`BrowserToolCard.tsx` + `BrowserToolCard/icons.tsx`（六个工具各自的图标）+ `BrowserToolCard/summary.ts`（七个工具各自的中文摘要，S-250 从主文件搬出），`tool-block-renderer.tsx:26` 也老老实实 import 了。

→ 现状：**一套写好的专属卡片、六个图标、七种摘要，全部挂在恒假条件后面，一次都没渲染过。**

### ③ `execution-outline.classify.ts:196` —— 时间轴 `'browser'` 分类永不命中

```ts
if (isMcpTool(name)) return 'mcp'
if (ORDINARY_CONTEXT_TOOL_NAMES.has(name)) return 'context'
if (FILE_CHANGE_TOOL_NAMES.has(name)) return 'file-change'
if (COMMAND_TOOL_NAMES.has(name)) return 'command'
if (isBrowserToolName(name)) return 'browser'   // ← 恒 false
if (isDesktopControlToolName(name)) return 'desktop'
...
// 落到这里
if (status === 'streaming' || status === 'running' || status === 'canceled') {
  return 'attention'
}
return 'unknown'
```

前后左右都是活判据（`isMcpTool` / `isDesktopControlToolName` / `ORDINARY_CONTEXT_TOOL_NAMES`），**就卡在中间这一个假的上面**。

→ 后果：浏览器工具在时间轴分组里被归进 `attention`（运行时强行露出、不参与折叠）或 `unknown`。**S-315 立的折叠规则对浏览器工具完全不生效** —— 这正是老大 11-05 10:43 报「连续 3 次工具调用出现 3 个折叠块而不是 1 个」的一个候选成因。

## 三、怎么修

**第一层（必做）**：把 `browser-tool-names.ts` 照 `desktop-routing.ts` 的形状写实 —— 八个常量进 `Set`，`has` 返回。3 行 → 约 15 行。

**第二层（同一刀内做掉）**：`tool-block-renderer.tsx:127-128` 那个 `input.action === 'screenshot'` 判据删掉，改成 `block.name === BROWSER_SCREENSHOT_TOOL_NAME`。理由：工具名本身就是判据，`action` 字段是凭空假设的。

**不做的事**：
- 不改 `BrowserToolCard` 内部（它没坏）
- 不动 `visual-context.ts:111` 的 `'browserscreenshot'` 小写归一化（那是另一套语义，给视觉上下文用的）
- 不动 `execution-outline.classify.ts` 的其它分类顺序

## 四、验收

| # | 场景 | 期望 |

| 1 | dev 实例让 agent 用 `BrowserScreenshot` 截一张 | 聊天窗出**浏览器专属卡片**（不是通用卡片），卡片里有图 |
| 2 | 同一轮里连做 `BrowserNavigate` → `BrowserClick` → `BrowserSnapshot` | 时间轴**折成一个折叠块**（`browser` 分类生效），标题是浏览器而不是「需要关注」 |
