### 2.3 语义与影响

「提示词快照」是渲染端缓存的一份 prompt 前缀，用于增量对比 / 缓存命中。现在函数空 ⇒ **快照永不清**，导致：

- 计划 / 任务变更后，源会话下一次请求可能沿用**旧快照**算增量
- follow-up 被 claim 或 fail 后，源会话上下文里仍留着旧的任务状态

这跟 S-317 / S-319 / S-322 那批「prompt cache」需求是**同一条线**，但那些处理的是后端缓存命中率，这里处理的是**前端快照失效**。

### 2.4 开工要做

1. 先确认「快照」到底存在哪（`chat-store` 里搜 `promptSnapshot` / 类似字段）—— 若**存储本身也不存在**，那这 16 处调用是空转，正解是**删接口 + 删 16 处调用**
2. 若存储存在、只是清理没实现 ⇒ 按 2.3 实现

## 五、实施记录（2026-11-06 10:5x，刀 35 / commit `6b501efb`）

两个空壳**处置方向相反**，先说结论：

| 项 | 处置 | 理由 |
|---|---|---|
| `selectSessionScopedAgentState` / `findSubAgentInSelection` | **补真实现** | 调用方把返回值直接接到了渲染判断上，恒空是真 bug |
| `clearSessionPromptSnapshot` + `SessionPromptSnapshot` 类型 + 16 处调用 | **全删** | store 里根本没有 `promptSnapshot` 字段，这个功能从没实现过 |

### 5.1 选择器为什么要补而不是删

`useMessageListData.ts:141` 与 `StaticMessageTranscript.tsx:64` 把 `hasOrchestrationData` 接到 `buildOrchestrationRuns` 的开关上。恒 `false` 的后果是：**只有 sub-agent、没有 team 的会话，编排时间轴永远不渲染**。这是行为缺口，不是无害桩。

`SubAgentCard.tsx:245-250` 是唯一「绕过」的调用点 —— 它有 `scoped ?? activeSubAgents[id] ?? completedSubAgents[id] ?? history.find(...)` 四级回落，所以卡片本身一直正常。这个对比正是「真 bug 但没被用户看见」的原因。

### 5.2 实现要点：选择器必须返回稳定引用

`useAgentStore(selector)` 用 `Object.is` 比对返回值。每次调用都造新对象会让订阅方**无限重渲染**（原桩用常量引用正是为了避开这个）。

做法：按 `sessionId` 缓存，key 内包含**源引用三元组 + 运行状态** —— `activeSubAgents` / `completedSubAgents` / `subAgentHistory` 三个 map 的引用，加上该会话的工具调用 buckets 引用和 `runningSessions[sessionId]`。任一变化才重建，否则返回同一个对象。

会话数设了上限 32，超了整表清空重积累 —— 防长期使用后 Map 只增不减。

### 5.3 `hasActiveToolCallOutput` 的判定口径

agent-store 里**没有**这个字段（原桩是编出来的）。真值要从工具调用 buckets 里算，`streaming` / `pending_approval` / `running` 算「正在输出」，`completed` / `error` / `canceled` 不算。

buckets 来源分两种：live 会话在 `pendingToolCalls` / `executedToolCalls`，非 live 在 `sessionToolCallsCache[sessionId]` —— 与 `resolveSessionToolCallTarget`（`utils/change-set-utils.ts:65`）的判定一致。

### 5.4 快照清理为什么全删

`SessionPromptSnapshot` 的注释自己写着 `// ─── Session Prompt Snapshot (placeholder, 迭代七完善) ───`。全仓搜 `promptSnapshot` 只命中**类型定义**和**方法名**，store state 里没有对应字段 ⇒ 迭代七从没把它做出来，16 处调用是纯装饰。

删掉**行为逐字节不变**（本来就是空函数），但少了一层误解：后来的人看到「有 16 处调用」会以为这功能是活的。
