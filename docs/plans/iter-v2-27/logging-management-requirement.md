# v2-iter-27 追加需求：日志配置接管与日志管理

- 状态：口径已确认（2026-09-10），待实现
- 归属：`v2-iter-27`
- 需求类型：现有日志体系的配置接管与管理界面补充

## 1. 背景

项目现有日志体系已经可以输出日志，也已有日志等级配置。当前问题是：

- 日志配置仍由程序级 JSON 配置维护，用户需要直接面对配置文件；
- 应用内没有日志管理入口；
- 模型请求发生重试时，用户无法方便地查看对应日志，难以判断重试原因、次数和最终结果。

本需求不重新设计日志系统，不调整模型重试次数、重试策略或退避逻辑。

## 2. 配置接管

将日志配置接入应用已有的统一配置存储（`settings/general.json` 中的设置 Store），与其他应用配置放在同一处管理。

已确认口径（2026-09-10）：

- 日志配置只有一个字段：日志输出等级，不新增「启用/关闭」开关；
- 等级沿用现有四个值：`error` / `warn` / `info` / `debug`，不扩展等级模型；
- 默认等级为 `error`，即默认只记录异常；
- 环境变量 `WISHFUL_CLAW_LOG_LEVEL` 保留为开发期启动覆盖，优先级高于持久化配置。

要求：

- 日志页面读取和保存统一配置中的日志等级；
- 日志写入逻辑读取统一配置中的日志等级值，保存后运行时立即生效，无需重启；
- 原程序级日志 JSON 不再作为日志配置的读写来源；
- 错误日志始终强制记录（`error` 是过滤下限，任何等级设置下都不会过滤掉错误日志）；
- Worker 重试日志经 stderr 以 warn 级落盘：默认 `error` 等级下不可见，需要排查重试问题时将等级调到 `warn` 及以上。

## 3. 页面入口与布局

设置导航中，在「关于」下方增加「日志」页面：

```text
设置
├── 关于
└── 日志
```

日志配置和日志查看位于同一个页面，上方为配置区，下方为查看区。

### 3.1 上方：日志配置

展示并管理现有日志配置：

- 日志输出等级（默认 `error`，只记录异常）；
- 保存配置。

不新增「日志启用/关闭」开关。页面只负责接管统一配置，不维护一份独立的日志页面配置。

### 3.2 下方：日志查看

日志文件按“每日一个日志文件”组织，采用文件预览布局：

```text
日志查看
├── 左侧：日志文件列表
│   ├── 2026-08-05.log
│   ├── 2026-08-04.log
│   └── 2026-08-03.log
└── 右侧：选中文件预览
```

行为要求：

- 进入日志页面时不默认读取日志内容；
- 左侧展示日志文件列表，按日期倒序排列；
- 用户点击某个日志文件后，才读取该文件并在右侧预览；
- 未选择文件时，右侧显示请选择日志文件的空状态；
- 支持手动刷新日志文件列表和当前预览文件；
- 日志文件不存在或读取失败时显示明确错误状态；
- 日志预览区域支持滚动查看；
- 离开页面后不继续后台轮询日志。

## 4. 日志清理

在日志查看区域提供历史日志清理操作：

- 用户指定天数；
- 删除指定天数之前的日志文件；
- 执行删除前二次确认；
- 完成后刷新左侧日志文件列表并反馈清理结果；
- 如果当前预览文件被清理，清空右侧预览并提示文件已不存在。

该功能只操作现有日志文件，不改变日志文件命名规则和输出格式。

## 5. 重试排查目标

本需求的直接目标是让用户可以查看已有日志，辅助排查模型请求重试问题。

代码探查和实现时需要确认现有重试路径是否已经写入足够的日志信息，至少应能判断：

- 是否发生重试；
- 重试原因；
- 当前重试次数；
- 最终成功、失败或取消。

如发现既有重试路径缺少必要日志，只补充可观测性日志，不改变重试行为。

## 6. 不纳入本需求

- 不重新实现日志框架；
- 不重新定义日志等级；
- 不调整模型重试次数、无限重试语义、退避策略或 Provider fallback 策略；
- 不继续维护原程序级日志 JSON；
- 不增加远程日志上传；
- 不默认加载或持续轮询日志内容；
- 不把日志内容写入数据库。

## 7. 验收标准

1. 从设置导航可以进入「日志」页面，入口位于「关于」下方。
2. 页面上方可以读取、修改并保存统一配置中的日志等级（仅一个等级字段，无启用开关），保存后立即生效。
3. 日志写入逻辑使用统一配置中的等级值，错误日志仍然强制记录。
4. 页面下方显示每日一个日志文件的左侧列表。
5. 初次进入页面时右侧不加载日志内容。
6. 点击左侧日志文件后，右侧可以预览对应文件内容。
7. 可以清理指定天数之前的日志，并在清理后刷新列表。
8. 日志查看失败、文件不存在和空列表状态均有可见反馈。
9. 模型重试相关日志可以通过文件预览功能查看，且不改变原有重试行为。
10. TypeScript、C# 和 Native AOT 验证遵循项目现有迭代标准。
