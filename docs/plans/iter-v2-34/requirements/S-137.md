# S-137 · shell 渲染组件「停止进程」点击无反应

- 2026-09-22：**老大提出**（原话：「shell渲染组件 有个停止进程 点击没反应」）。

**现象**：点「停止进程」**毫无反应** —— 无报错、无 toast、无状态变化。

**现状勘测（2026-09-22，根因已定位）**：

**① 前台按钮 —— 用户看到的那个**

- 位置：`src/renderer/src/components/chat/ToolCallCard/output-blocks/bash-output.tsx:211-226`，渲染条件 `canStopForegroundExec = !process && status === 'running' && !!toolUseId && !!foregroundExecId`（`:85-86`）。
- 点击 → `abortForegroundShellExec(toolUseId)` → `src/renderer/src/stores/agent-store/slices/background-process-slice.ts:56-59` 查 `foregroundShellExecByToolUseId[toolUseId]`，**取不到就静默 `return`**。
- 而写入方 `registerForegroundShellExec`（`agent-store/types.ts:401`、`background-process-slice.ts:27`）**全仓零调用点** ⇒ map 恒空 ⇒ **必然静默返回**。
- 按钮之所以还会显示，是 `foregroundExecId = foregroundExec?.execId ?? toolUseId`（`bash-output.tsx:48-50`）的兜底撑起来的。

**② 后台按钮** —— 依赖 `backgroundProcesses`（`process` 存在才渲染，`bash-output.tsx:179-209`），而 `initBackgroundProcessTracking` / `registerBackgroundProcess` **同样零调用点** ⇒ 恒空 ⇒ **那组按钮根本不出现**。

**③ 公共断点**：`src/renderer/src/lib/ipc/channels.ts` 的 `SHELL_*` / `PROCESS_*` 整族，**主进程只注册了 5 个 OS 集成类 `shell:*`**（`openExternal` / `openPath` / `showItemInFolder` / `trashPath` / `openWithApp`）；`shell:exec` / `shell:abort` / `shell:started` / `shell:output` / `PROCESS_KILL` **主进程与 C# 侧均零 handler**。该文件头部自注 `Ported from OpenCowork` ⇒ 整套 IPC 从 OpenCowork 搬来、**从未接线**。

**④ C# 侧的骨架（关键发现）** —— `Bash` 工具的 C# 实现**已经有可中止的骨架，只是没接线**：

- `ShellExecuteTool.cs:24` —— `private static readonly ConcurrentDictionary<string, RunningProcess> Running` —— **声明后全仓无写入无读取**。
- `ShellTypes.cs:14-32` —— `internal sealed class RunningProcess`，带 `Abort(reason)`（`Process.Kill(entireProcessTree: true)`）—— **同样无任何使用点**。

**⑤ 顺带查出一个独立真 bug** —— `ShellExecuteTool.Process.cs:94`：

```csharp
catch (OperationCanceledException) when (!cancellationToken.IsCancellationRequested)
{
    timedOut = true;
    TryKillProcessTree(process);
    ...
}
```

`when` 条件把**外部取消**（会话「停止」取消 token）排除在 kill 分支之外 ⇒ 外部取消时异常向上抛（`ShellExecuteTool.cs:200-206` 的 `catch (OperationCanceledException) { throw; }`），**子进程不被 kill，留成孤儿**。只有超时才杀进程树。

**架构差异（决定修法）**：OpenCowork 的 shell 走 worker 请求 `shell/exec`，**main 手里有进程句柄**，所以它的 `shell:abort` 由 main 直接调 `nativeWorker.request('shell/abort')`。**我们的 `Bash` 是 C# 内联执行**（`ShellExecuteTool` 是 `IToolExecutor`，在 agent run 内直接 `Process.Start`），**main 手里没有句柄** ⇒ 中止**只能由 C# 侧执行**，main 只做转发。⇒ OpenCowork 的 `shell-handlers.ts` 只能抄**设计**（`runningShellProcesses` Map + `shell:abort` handler + 输出流 `shell/output` 广播），**抄不到能跑的代码**（它自己渲染层也是零调用点）。

**待裁定（二选一）**：

- **A 删**：确认前台 shell 已走 C# 工具事件流后，删死 IPC 族 + `background-process-slice` 死方法 + 前台停止分支，停止统一走主会话停止按钮。
- **B 接（推荐）**：骨架现成 —— C# 填 `Running` 表 + 暴露按 `toolUseId` 中止的入口（走现成 `agent/xxx` worker 请求通道，`src/runtime/WishfulClaw.Agent/AgentRuntimeModule.cs` 的 `agent/clear-session` 是模板），main 转发，前端按钮改成真调用。保留「单个 shell 单独停」能力。**顺带修 ⑤ 的取消不 kill 进程树。**

**体量**：中等（跨 C# + main + 渲染三层）。

**独立性**：不依赖 S-135 / S-136，可独立实施。
