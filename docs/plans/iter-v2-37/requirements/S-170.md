# S-170：DeepSeek 内置服务商默认协议改为 OpenAI Chat

> 状态：**已登记，待实施**（2026-10-08）。来源：老大 2026-10-08 08:27「登记一个简单需求归属 37 迭代　DeepSeek 的内置 api 服务商 默认协议改成 openai chat」。

## 一、原话 / 来源

老大 2026-10-08 08:27：

> 「登记一个简单需求归属37迭代 DeepSeek的内置api服务商 默认协议改成openai chat」

## 二、现象

内置服务商 **DeepSeek** 当前默认走 **Anthropic 协议**，而 DeepSeek 官方对外主推的是 **OpenAI 兼容端点**：

| 项 | 现状值 |
|---|---|
| `builtinId` | `deepseek` |
| `type` | `'anthropic'` |
| `defaultBaseUrl` | `https://api.deepseek.com/anthropic` |
| `version` | `3` |

诉求：把默认协议换成 **OpenAI Chat**（`type: 'openai-chat'`），端点随协议切到 OpenAI 兼容地址。

**旁证**（models.dev 全量元数据，2026-09 快照）：`deepseek` provider 的 `api` 字段 = `https://api.deepseek.com`，`npm` = `@ai-sdk/openai-compatible` ⇒ 官方生态默认按 OpenAI 兼容接入。

## 三、代码链路

| 环节 | 位置 | 现状 |
|---|---|---|
| preset 定义 | `src/renderer/src/stores/providers/deepseek.ts:10-66` | 单 preset，`type: 'anthropic'`、`defaultBaseUrl: '.../anthropic'`、`version: 3` |
| 协议枚举 | `src/shared/types/provider.ts:11-19` | `ProviderType` 含 `'openai-chat'`（**不是** `'openai'`） |
| 首建投影 | `provider-materialization.ts:16-37` `createProviderFromPreset` | 新记录直接取 preset 的 `type` / `defaultBaseUrl` |
| 启动调和 | `provider-materialization.ts:105-140` `reconcileProviders` | **已持久化的 builtin 记录原样保留**，preset 改动不生效 |
| 退回投影 | `provider-store-helpers.ts:86-103` `pruneUnownedBuiltinProviders` | 打开 AI 服务商管理页时，`isUnownedBuiltin` 为真的记录 `resetProviderToPreset` ⇒ preset 改动此时才生效 |
| 判据 | `provider-materialization.ts:57-67` `isUnownedBuiltin` | 要求：有 `builtinId`、非 `virtual`、**未 enabled**、**无 apiKey**、**未 `typeOverridden`**、`requiresApiKey !== false`、**`baseUrl === preset.defaultBaseUrl`** |

## 四、根因 / 诉求

**不是 bug，是默认选型调整。** 现默认 Anthropic 协议；诉求改为 OpenAI Chat。

## 五、修复方向

改 `deepseek.ts` 三处：

1. `type: 'anthropic'` → `'openai-chat'`
2. `defaultBaseUrl` → `https://api.deepseek.com`（老大 2026-10-08 08:31 裁定：**不带 `/v1`**）
3. `version: 3` → `4`（preset 版本推进）

**就这三处，一个不多。** `thinkingConfig`、`defaultModels`、价格、`deprecatedModelIds` 一律不动（依据见下）。

#### thinkingConfig 裁定依据（官方文档实读，2026-10-08）

用内置浏览器实读 `https://api-docs.deepseek.com/zh-cn/api/create-chat-completion`（Chat Completions API），三个关键事实：

1. **`thinking` 是官方 OpenAI 端点的一等参数**，不是 Anthropic 专属：
   > **thinking** object nullable —— 控制思考模式与非思考模式的转换。**type** string，`enabled` / `disabled`，默认 `enabled`。
   ⇒ 我方现有 `bodyParams: { thinking: { type: 'enabled' } }` / `disabledBodyParams: { thinking: { type: 'disabled' } }` **就是官方格式，原样保留即可**。
2. **`reasoning_effort` 也是官方参数**，且对未知档位有兼容映射：
   > **reasoning_effort** string —— `none` / `low` / `high` / `max`。`none` 关闭思考；默认强度 `high`。**出于兼容考虑，`minimal` 映射为 `low`，`medium` / `xhigh` 映射为 `high`**。
   ⇒ `provider-store-helpers.ts:122` 的 `ensureDefaultReasoningEffort` 自动补的 `['medium','high','xhigh']` + `default:'medium'` **不会 400**，会被官方映射为 `high`。
3. **思考内容字段名 = `reasoning_content`**（响应 `message.reasoning_content` / 流式 `delta.reasoning_content`），非 `reasoning`。

我方 `openai-chat` 路径的下发行为（`OpenAIChatRequestBuilder.cs:401-487` 实读）与此吻合：

- 思考开：`bodyParams` 原样写入 ⇒ 发 `thinking: { type: 'enabled' }` ✓
- 思考关：`disabledBodyParams` 原样写入 ⇒ 发 `thinking: { type: 'disabled' }` ✓
- 非 OpenRouter 且 `effectiveEffort` 非空 ⇒ 顶层追加 `reasoning_effort`（`:482-486`）✓

⇒ **结论：本需求只动 `type` / `defaultBaseUrl` / `version` 三处，`thinkingConfig` 一个字不改。**

**唯一需留意的官方约束**（与本需求无关，仅备查）：思考模式下 `tool_choice: required` 或指定具体 tool 会返回 `400`；`temperature` 在思考模式下不生效。

## 六、代价与取舍

**核心风险：改了 preset，已配 DeepSeek 的老用户拿不到新协议，且会被永久钉在旧配置上。**

推演（基于 `isUnownedBuiltin` 判据）：

- **未启用过的用户**（无 apiKey、未 enabled）⇒ 打开 AI 服务商管理页时被 `resetProviderToPreset` ⇒ **新 `type` + 新 `baseUrl` 生效** ✓
- **已启用 DeepSeek 的用户**（填了 key）⇒ 记录保留 ⇒ **`type` 与 `baseUrl` 都不变**，仍打 `/anthropic` 端点 ✗
- 更糟：改 `defaultBaseUrl` 后，老记录的 `baseUrl` 是旧值 ⇒ `provider.baseUrl !== preset.defaultBaseUrl` 恒为真 ⇒ **永远不满足 `isUnownedBuiltin`** ⇒ 这条记录再也不会被退回投影，**永久钉住**。

⇒ 三条可选路径：

- **A（最小改动，✅ 已裁定）**：只改 preset（内置的虚拟投影）。**只有新用户 / 未启用过的用户**享受新协议；**已配置用户维持现状不动**，不迁移、不刷新。代价：老用户仍走 Anthropic，新协议只对新装 / 未启用过的用户生效。
- **B（加一次性迁移）**：升级时把 `builtinId === 'deepseek'` 且 `baseUrl` 仍等于**旧** `defaultBaseUrl`（`.../anthropic`）且 `type` 未被 override 的记录，一并刷新 `type` + `baseUrl`。代价：多一段迁移代码与判据。**不做。**
- **C（登记为通用规则）**：把「`defaultBaseUrl` 变更也要随 preset 刷新」做成 `reconcileProviders` 的通用规则。代价：影响面全量 builtin，风险大，本轮不划算。**不做。**

**裁定（2026-10-08 08:32）**：老大拍 **A** —— 「已配置用户不管啊，我们只是改内置的虚拟的」。
即：本需求只动 preset 数据，**不写任何迁移代码**；已物化（已启用 / 已填 key）的 DeepSeek 记录保持原样。

## 七、刻意不做

- **不动模型清单** —— 本次只切协议与端点，`defaultModels`（`deepseek-flash` / `deepseek-v4-pro`）与价格一律不碰。
- **不动 `deprecatedModelIds`** —— 与协议无关。
- **不动其它 provider** —— 只 DeepSeek 一家。
- **不写老用户迁移代码** —— 老大裁定 A：已配置用户不管。不碰 `reconcileProviders`、不加一次性迁移、不改 `isUnownedBuiltin` 判据。
