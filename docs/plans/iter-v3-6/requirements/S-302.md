# S-302 · 安装包里白带的 Monaco 语言服务 —— 16.4 MB 没人用

> 状态：**✅ 已实施（v3-iter-6，待真机验收）**
> 登记：2026-11-02 14:15 ｜ 实施：2026-11-02 15:20
> 来源：老大 2026-11-02 14:11「大部分用户其实不写代码，这东西没用」；14:13「先登记 把这两项登记上」
> 关联：**S-303（CodeGraph 剥离）同属「替所有用户预装程序员功能」这条线**

## 一、现状

安装后 414.6 MB 里，`resources/app.asar` 占 52.8 MB，其中 `out/renderer` 45.92 MB / 213 文件。renderer 产物里最大的六个文件：

| 文件 | 大小 |
|---|---|
| `assets/ts.worker-*.js` | **12.63 MB** |
| `assets/index-*.js` | 8.80 MB |
| `assets/setup-*.js` | 6.81 MB |
| `assets/css.worker-*.js` | 1.78 MB |
| `assets/html.worker-*.js` | 1.18 MB |
| `assets/json.worker-*.js` | 0.80 MB |

**四个语言 worker 合计 16.39 MB，占 renderer 产物的 36%。**

## 二、根因（实施中更正过一次）

### 2.1 表层：`setup.ts` 显式 import 了四个 worker

```ts
import editorWorker from 'monaco-editor/esm/vs/editor/editor.worker?worker'
import jsonWorker from 'monaco-editor/esm/vs/language/json/json.worker?worker'
import cssWorker from 'monaco-editor/esm/vs/language/css/css.worker?worker'
import htmlWorker from 'monaco-editor/esm/vs/language/html/html.worker?worker'
import tsWorker from 'monaco-editor/esm/vs/language/typescript/ts.worker?worker'
```

### 2.2 但删掉这四条 import 无效（已实测证伪）

按原方案只删 import + 删 `getWorker` 分支后，`npm run build` 仍产出全部四个 worker，`out/renderer` 仍是 45.92 MB / 213 文件。

产物内反查（`cssMode-*.js` / `htmlMode-*.js` / `jsonMode-*.js` / `tsMode-*.js` / `setup-*.js`）证明引用来自 monaco 自己的包内代码：

- `node_modules/monaco-editor/esm/vs/language/*/workerManager.js` 里写死 `new Worker(new URL('ts.worker.js', import.meta.url), { type: "module" })`，Vite 静态识别 `new URL(..., import.meta.url)` 后**无条件打包**，与本项目是否 import 该 worker 无关；
- `monaco-editor/esm/vs/editor/editor.main.js` 无条件 import 四个 `monaco.contribution.js`，把上面四条 workerManager 拉进图。

**⇒ 真正的根因是 `setup.ts` 的 `import * as localMonaco from 'monaco-editor'` 全量导入。** 不换入口，删多少条 `?worker` import 都没用。

## 三、我们用 Monaco 只做两件事

| 文件 | 用途 | 状态 |
|---|---|---|
| `components/editor/CodeEditor.tsx` | 文件预览面板，**可编辑可保存**（有 `onChange` / `onSave`） | 活，被 `lib/preview/viewers/` 的 fallback / html / markdown / svg 四个 viewer 引用 |
| `components/editor/MonacoDiffEditor.tsx` | 预览面板的 diff 视图 | 活，`components/layout/preview/content.tsx:21` 以 `lazy()` 动态导入 |

这两个场景要的是**语法高亮 + 编辑 + diff**，不是 IDE。TS 语言服务（类型检查、自动补全、跳转定义、重构）从来没有被依赖，也没有对外宣传过。

## 四、方案（实施时更正）

换 monaco 入口，从「全量」改成「只要编辑器 + 语法高亮」：

```ts
import * as localMonaco from 'monaco-editor/esm/vs/editor/editor.api'
import 'monaco-editor/esm/vs/editor/editor.all'
import 'monaco-editor/esm/vs/basic-languages/_.contribution'
import editorWorker from 'monaco-editor/esm/vs/editor/editor.worker?worker'
```

三个入口的分工：

| 入口 | 作用 |
|---|---|
| `editor.api` | 编辑器 API 本体（`editor` / `languages` / `Uri` / `Range` …），并自带 `internal/initialize` |
| `editor.all` | 编辑器全部 contrib（查找替换、折叠、多光标、codicon 样式等），**不含任何语言服务** |
| `basic-languages/_.contribution` | 注册 90+ 种语言的 monarch 语法定义，主线程懒加载，**不需要 worker** |

配套删掉：`getWorker` 里 json / css / html / typescript 四个分支、TS compilerOptions / diagnosticsOptions、以及早已无引用的 `RENDERER_GLOBALS_D_TS` 死代码常量。

`editorRemoteLanguageServiceEnabled` 设置项**保留** —— 它只管 model URI 的 scheme（`in-memory:` vs `ssh:`，见 `lib/monaco/workspace.ts` 的 `createModelUri`），与内置语言服务 worker 无关。

## 五、判据与实测

| 判据 | 怎么验 | 结果 |
|---|---|---|
| 打包产物里 ts / css / html / json 四个 worker 文件消失 | `out/renderer/assets/` 实测 | ✅ 全消失，只剩 `editor.worker`（0.52 MB） |
| 体积收益 ≥ 16 MB | `out/renderer` 前后对比 | ✅ **−17.33 MB**（45.92 → 28.59） |
| 文件编辑器仍能打开、编辑、保存 | dev 实例真机 | ⏳ 待验收 |
| diff 仍能正确渲染增删行 | dev 实例真机 | ⏳ 待验收 |
| 无运行时报错（worker 404） | dev 实例控制台 | ⏳ 待验收 |

**反向验证**：只删 import 不删 `getWorker` 分支 ⇒ 打开 .ts 文件时 `new tsWorker()` 会抛错。两处必须一起删。
**反向验证（本轮新增）**：只删 import + 分支、不换入口 ⇒ 产物不变，四个 worker 原样在包里（已实测）。

### 5.1 实测数据

| 指标 | 改动前 | 改动后 | 变化 |
|---|---|---|---|
| `out/renderer` | 45.92 MB / 213 文件 | **28.59 MB / 123 文件** | **−17.33 MB / −90 文件** |
| `ts.worker` | 12.63 MB | 消失 | ✅ |
| `css.worker` | 1.78 MB | 消失 | ✅ |
| `html.worker` | 1.18 MB | 消失 | ✅ |
| `json.worker` | 0.80 MB | 消失 | ✅ |
| `editor.worker` | 0.52 MB | 0.52 MB | 保留 |
| `setup-*.js` | 6.81 MB | 6.81 MB | 不变 |

**收益全部来自四个 worker（16.39 MB）+ 随之消失的 mode/语言服务 split chunk（约 0.94 MB），不是来自 setup chunk 本身** —— `editor.all` + `basic-languages` 的体积与原全量导入基本一致。这一条是原方案（§七）预期错了的地方：按需导入省的是 worker，不是 setup。

语法高亮未退化：产物内 `tokenizer` 命中 137 处，monarch 定义齐全。

## 七、原「不做」条目已作废（保留记录，防止后来者重开）

原 §七 写：*「改成按需导入理论上还能再砍 setup 的一部分，但 monaco ESM 按需导入极易踩坑，本迭代不做」*。

**这条是错的，而且是 S-302 唯一的解。** 理由见 §2.2：不换入口，四个 worker 就永远在包里，删 import 是空转。实施代价也不高 —— 三条 import 加一次 typecheck 就通了，没有踩到「`editor.api` 与 contributions 的边界 / language 注册时机 / diff 编辑器依赖」任何一个坑（`loader.config({ monaco: localMonaco })` 的类型也直接兼容）。

## 八、风险

用户编辑 `.ts` / `.json` / `.css` / `.html` 时**失去智能提示**（补全、类型检查、悬停提示、格式化），**保留语法高亮**。当前没有任何入口依赖智能提示，也没有对外宣传过。将来若要做「代码编辑器」体验，应按 S-303 的思路做成可选插件，而不是重新塞回主包。
