## 一、事实（配置文件原文，不是推断）

| 文件 | `include` |
|---|---|
| `tsconfig.web.json` | `src/renderer/src/env.d.ts`、`src/renderer/src/**/*`、`src/preload/*.d.ts`、`src/shared/**/*` |
| `tsconfig.node.json` | `electron.vite.config.*`、`src/main/**/*`、`src/preload/**/*`、`src/shared/**/*` |

`tsconfig.json` 只是 `references` 这两个配置的壳，`files: []`。

⇒ **`tests/**` 两个配置都不覆盖。**

门禁脚本：

```
typecheck      = typecheck:node && typecheck:web
typecheck:node = tsc --noEmit -p tsconfig.node.json --composite false
typecheck:web  = tsc --noEmit -p tsconfig.web.json --composite false
```

⇒ `npm run typecheck` **一个测试文件都不编译**。

测试怎么跑：每个套件一条 `test:*` 脚本，`esbuild --bundle` 打包成 cjs 再 `node` 执行。esbuild **只剥类型、不做类型检查**。

⇒ 测试里的类型错误，从头到尾没有任何一步会报。

## 二、影响

1. **类型错误静默存在**：测试里写 `const n: number = 'str'`、调错函数签名、`import` 了不存在的导出 —— `npm test` 全绿。
2. **静态守卫形同虚设**：本仓习惯用「能红的断言」防回归。但如果断言本身写错了（比如 `satisfies Required<Session>` 里字段名打错），断言会**恒真**，从此变成假保险 —— 比没有更糟。
3. **重构安全网漏水**：测试是重构的唯一保险，保险自己没编译过，等于不知道保险有没有上。
4. 现规模：**119 个测试套件目录**（2026-11-01 实测；`npm test` 119/119），全部受影响。

## 三、修法候选

| 方案 | 做法 | 评价 |
|---|---|---|
| **A（推荐）** | 新增 `tsconfig.test.json`：`extends` `tsconfig.web.json`，`include` 加 `tests/**/*`，`types` 加 `node`；`typecheck` 追加 `tsc --noEmit -p tsconfig.test.json --composite false` | 不动现有两个配置，测试有独立语义（node 环境 + DOM 类型混用），改动面最小 |
| B | 把 `tests/**/*` 并进 `tsconfig.web.json` 的 `include` | 会让 renderer 配置背上 node 类型；`src/renderer` 与测试的 lib 假设不同，容易互相污染 |
| C | 每个 `test:*` 脚本前加 `tsc --noEmit <file>` | 88 条脚本全改，且单文件检查拿不到跨文件类型 |

### 4.1 四个错是同一类：箭头函数 + 裸块 的 ASI 陷阱

`tests/live-cursor/program.ts:25` 是：

```ts
const text = (): { type: string } => ({ type: 'text' })
```

第 28 行紧跟一个**裸块** `{`（顶层作用域分组）。按 ECMAScript 的 ASI 规则，`)` 后换行遇 `{` **不插分号** —— `{` 可以作为「函数调用实参」继续解析，所以 tsc 把它读成：

```ts
const text = (): { type: string } => ({ type: 'text' })({ …块内容… })
```

`{ const a = 1 }` 在类型位置不是合法类型字面量 ⇒ 在 `'text'` 处报 `TS1003`，回溯到裸块处报 `TS1005 '=>' expected`。

**逐行二分验证**（每次只加一行）：

| 变体 | 内容 | 结果 |
|---|---|---|
| `step-27` | 第 25~27 行（含注释） | 干净 |
| `step-28` | 再加第 28 行裸块 `{` | **报错** ← 触发器就是这一行 |
| `v2-block-ret` | 箭头函数改成 `=> { return {…} }` | 干净 |
| `v3-ifblock` | 裸块换成 `if (true) { … }` | 干净 |
| `v4-nobraces` | 后面不跟块 | 干净 |
| `v5-semicolon` | 原样 + **行尾加分号** | **干净** |

⇒ **修复方式是加一个分号**（`v5` 已验），不是改结构。

### 4.2 为什么 `npm test` 一直是绿的

`npm test` 走 `esbuild --bundle --format=cjs`，esbuild 在 `)` 后换行遇 `{` 时**插分号**（更符合直觉，但不符合规范），所以运行时行为是对的、tsc 报的是真规范问题。**两边不一致本身就是这个需求要消灭的东西** —— 类型检查接进来之后，这类分歧会在提交前暴露，而不是靠人肉发现。

### 4.4 第二轮实测：语法错一修，暴露 37 个语义错（2026-11-02 08:4x）

**为什么第一轮只数出 4 个**：tsc 在**语法错误**存在的文件上会抑制语义分析。4 个 `TS1005` / `TS1003` 是解析期错误，解析没过的文件根本不进类型检查。把那 4 个修掉（加 2 个分号）再跑，真实规模才露出来。

**本轮用的配置**（与方案 A 一致，**不是** §四 第一轮那个 node 基座）：

```json
{

  "include": [
    "src/renderer/src/env.d.ts",
    "src/renderer/src/**/*",
    "src/preload/*.d.ts",
    "src/shared/**/*",
    "tests/**/*"
  ],
  "compilerOptions": { "composite": false }
}
```

3. `tests/updater-state/suites/gates.ts:21` —— import 的 `createInstallHarness` 与本地第 164 行同名函数重复。

### 4.6 配置坑：`types: ["node"]` 会误伤（已实测）

第一版配置照 §4.3 写了 `"types": ["node"]`，结果多出 **34 个假 `TS7016`**（`react-syntax-highlighter/dist/...` 找不到声明文件）。原因：一旦显式写 `types`，tsc 就**不再自动加载** `node_modules/@types/*`，`@types/react-syntax-highlighter` 被一起排掉。去掉 `types` 后这 34 个假错全部消失。

⇒ `tsconfig.test.json` **不写 `types`**，让 `@types` 自动加载。

**真缺陷（§二.2 说的「假保险」）确认并修掉**：

`tests/screenshot-dir/program.ts:106` 原来写 `SCREENSHOTS_SUBDIR !== CHAT_IMAGES_SUBDIR`。两侧都是字面量类型（`'screenshots'` / `'images'`），tsc 判恒真 —— 这条断言从写下那天起**没验过任何东西**。改成比较运行值：

```ts
new Set([SCREENSHOTS_SUBDIR, CHAT_IMAGES_SUBDIR]).size === 2
```

将来两个常量撞成同一个名字时，这条会真的变红。

`tests/browser-keepalive/program.ts` 的 `assert` 从 `(condition: boolean, message) => void` 改成 `asserts condition` —— 这是正向改进：`:197` 的 `assert(plan.action === 'reject', …)` 从此真的把联合类型收窄到 `reject` 分支，`:198` 访问 `plan.reason` 合法（字段本来就有，见 `browser-keepalive.ts:43-44`），**不是**去 `src` 里加字段。
