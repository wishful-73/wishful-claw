# S-214：设置页「关于」里独立的「使用指引」板块删掉，指引统一走官网

> 状态：**已登记，待开工**（2026-10-20 老大登记，iter-v2-40）。
> 类型：**体验优化**（信息架构重复项收敛，非 bug）。
> 归属：**iter-v2-40**。
> 来源：**老大 2026-10-20 10:52 之后** —— 「设置页的关于，里面的使用指引板块删掉，访问官网实际上就能去查看指引，官网的描述需要改一下」。
> 轨道：**软件侧**（渲染端设置页），**零 Worker 改动**。官网侧是否同步见 §五.1。

---

## 一、现象 / 现状

设置页 →「关于」目前是四块：标题 + 版本号 → 产品介绍 + 核心能力 → **官网** → **使用指引** → **应用更新**。

「官网」和「使用指引」两块**指向同一个站点**，区别只是路径：

| 板块 | 动作 | 实际 URL |
| --- | --- | --- |
| 官网 | `openWebsite()` | `https://wishful-claw.work` |
| 使用指引 | `openUserGuide()` | `https://wishful-claw.work/guide` |

而官网站点顶栏第一项就是**使用指引**（`website/src/content/site.ts:75`）—— 打开官网首页，点顶栏即可进指引。**独立板块是重复入口，且「查看指引」按钮与「访问官网」按钮长得一样、并排放着，纯属噪音。**

## 二、根因（重复的成因）

`about.guide` 这一块是 S-160 时期产物：当时指引从仓库 `docs/user-guide.md` 迁到官网 `/guide`，为了让老用户仍有一键入口，加了这块。**迁完后官网顶栏本身就有指引入口，这个板块没再被回顾过** ⇒ 重复入口留到今天。

## 三、目标

1. 设置页「关于」删掉**整个「使用指引」板块**（`sec-about-guide`）。
2. 指引入口收归到「官网」板块 —— **在它的描述里说清「指引在官网上」**，用户不至于因为少了一个按钮就找不到指引。
3. 清掉随之变成死代码的东西（`openUserGuide` / `USER_GUIDE_URL` / `about.guide.*` 两语言键），不留半截。

## 四、非目标

- **不动官网 `/guide` 页本体**（`guide-page.tsx` 的 eyebrow / title / description、`guide-nav.ts`、`user-guide.md` 一律不动）—— 除非 §五.1 的确认结果指向官网侧。
- **不动官网站点顶栏**（`site.ts:75` 的「使用指引」是现在唯一的正式指引入口，必须留着）。
- **不动「应用更新」板块**、不动「更新日志」外链。
- **不新增替代入口**（不要在设计上再造一个「帮助」按钮）。
- **不动** `WEBSITE_URL` / `WEBSITE_HOST` / `openWebsite`。

## 五、待确认

1. **「官网的描述需要改一下」指的是哪一句** —— 本条按**主口径**理解：设置页「关于 → 官网」区块的描述 `about.website.desc`（zh `settings.json:868` = 「下载安装包、查看使用指引与更新日志」，en `:868` = 「Downloads, user guide and release notes」）。**备选口径**是官网 `/guide` 页首屏 description（`guide-page.tsx:43`「项目下会话怎么干活…」）—— 两种口径改动面差一个文件，**实施时确认一句即可**，不影响其余改动。
2. **设置页左侧导航项的描述要不要保留「使用指引」字样** —— `settings.nav.about.desc`（zh `settings.json:70`「产品介绍、使用指引与应用更新」，en `:70`「Product intro, user guide and app updates」）。板块删了，这句就成了对不存在内容的承诺。**默认处理**：改成「产品介绍、官网与应用更新」/「Product intro, website and app updates」。

## 六、修法

### 6.1 删板块（`components/settings/SettingsPage.tsx`）

删掉 `:355-369` 整个 `SettingsSection id="sec-about-guide"`（title / description / hint / 「查看指引」按钮）。`SettingsSection` 本身、「官网」与「应用更新」两块保持原样。

### 6.2 官网区块描述改成指引的第一落点

`about.website.desc` 两语言同步改（措辞按此方向，实施时定稿）：

- zh：`使用指引、更新日志都在官网上，安装包也从这里下`（原「下载安装包、查看使用指引与更新日志」）
- en：`User guide and release notes live on the site; downloads too`

**要点：把「使用指引」放到句子最前面** —— 用户扫一眼就知道点了能看到指引，而不是只剩「下载安装包」这一层理解。

### 6.3 清死代码

删板块后 `openUserGuide` / `USER_GUIDE_URL` **在渲染端只剩定义、零调用**（已全量 grep：引用点仅 `user-guide.ts:13,15` 与 `SettingsPage.tsx:19,364`）⇒ 一并删掉 `lib/user-guide.ts` 里的这两项，保留 `WEBSITE_URL` / `WEBSITE_HOST` / `openWebsite`。

`:7-12` 那段关于「指引指向官网而非 GitHub blob、不要再引入仓库 docs 链接」的注释，随 `USER_GUIDE_URL` 一起删 —— **但把结论搬进 `openWebsite` 的注释**（一句话：指引在官网 `/guide`，本站顶栏已有入口，不要在应用内再造入口），避免以后有人又加回来。

### 6.4 i18n 键删除

zh / en `settings.json` 同时删 `about.guide` 整块（`label` / `desc` / `hint` / `open`）。`SettingsPage.tsx` 里四处 `t('about.guide.*')` 随 JSX 一起消失，**不留 defaultValue 兜底残片**。

## 八、风险

- **少一个入口后的可发现性**：唯一补偿是「官网」区块的描述文案。若描述里没明写「使用指引」，用户会觉得指引消失了 ⇒ 6.2 的措辞是本需求的实际价值点，别弱化。
- **两语言键不同步**：zh 删了 en 没删（或反之）不会报错，会留脏键 ⇒ 必须同刀改完，改完 `npm run typecheck` + 启一次设置页确认无 `about.guide` 缺键警告。
- **别顺手删多了**：`WEBSITE_HOST` 展示与「由心相团队开发与维护」属官网板块内容，保留。
- **老版本用户**：本改动只影响新版本渲染端，无迁移问题（无落库数据）。
