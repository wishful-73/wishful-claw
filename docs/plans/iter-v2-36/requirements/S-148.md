# S-148 PDF 预览失败时显示裸英文「Failed to load PDF file.」

- **登记日期**：2026-09-23
- **登记来源**：老大 16:43「这是一个 bug 登记 Failed to load PDF file.」
- **分支**：`dev/v2-iter-36`
- **状态**：✅ 已实施（`57d71068`，2026-09-25）

---

## 一、现象

预览一个 PDF，加载失败时界面上直接显示一行英文：

```
Failed to load PDF file.
```

既不是中文，也不说为什么失败（加密？文件坏了？worker 没起来？），用户看到的就是这一句。

---

## 二、根因（已定位）

**这句话不在我们仓库里** —— 全仓 `grep 'Failed to load PDF'` 零命中。它是 **react-pdf `<Document>` 组件的内置默认 `error` 文案**：

`src/renderer/src/lib/preview/viewers/pdf-viewer.tsx:140`

```tsx
<Document
  file={{ data: pdfData }}
  onLoadSuccess={onDocumentLoadSuccess}
  loading={…}          // ← 只覆盖了 loading
  // error 没传 ⇒ 用 react-pdf 的默认值 'Failed to load PDF file.'
>
```

我们只覆盖了 `loading`，没覆盖 `error`，于是失败时库把自己的英文默认值端上来。

**失败发生的时机**：走到这一步说明**二进制已经读进来了**（`pdfData` 有值，`error` 为 null），是 **pdf.js 解析/渲染阶段**失败，与读文件无关。所以不能拿下面那个读文件分支的文案来解释。

---

## 三、同类面（同一个 bug 的更大范围）

`src/renderer/src/lib/preview/viewers/` 下 **13 个 viewer 的提示语全部是硬编码英文**，一条 i18n 都没走：

| 类别 | 实例 |
|---|---|
| 加载中 | `Loading PDF...`（pdf:97）、`Loading...`（pdf:145）、`Loading document...`（docx:69）、`Loading spreadsheet...`（spreadsheet:309）、`Loading image...`（image:226）、`Loading audio...`（audio:99）、`Loading video...`（video:97）、`Loading font...`（font:100） |
| 读文件失败 | `Failed to read file`（pdf:54 / docx:46 / spreadsheet:158）、`Failed to read image file`（image:88）、`Failed to read audio file`（audio:66）、`Failed to read video file`（video:64）、`Failed to read font file`（font:67） |
| iframe 无障碍标签 | `title="PDF Preview"`（pdf:82）、`"HTML Preview"`（html:36）、`"SVG Preview"`（svg:43）、`"Dev Server Preview"`（dev-server:96）、`"Microsoft Office Preview"`（office-online:35） |

⇒ 「Failed to load PDF file.」只是**最先被撞见的那一个**。同类问题一次收干净，别下回又一个个报。

---

## 四、改法（待老大裁定细节）

1. **必修**：给 `<Document>` 传 `error`，走 i18n（中文如「PDF 加载失败」），不再用库的默认英文。
2. **建议**：失败时能区分「读文件失败」与「解析/渲染失败」两种文案 —— 现在两条路径共用一句英文，排错时分不清是路径问题还是文件本身的问题。
3. **建议**：上表 13 个 viewer 的加载态 / 失败态 / iframe `title` 统一走 i18n（`preview.*` 一组键）。
4. **可选**：是否把 pdf.js 抛出的原始原因（如加密、结构损坏）透出给用户，还是只给一句中文 —— 等裁定。

---

## 五、验收

1. 预览一个**无法解析**的 PDF ⇒ 界面显示中文文案，不再出现 `Failed to load PDF file.`。
2. 预览一个**路径不存在**的文件 ⇒ 显示的是「读文件失败」那一条，与上一条**可区分**。
3. 正常 PDF 预览不受影响（翻页、页码照常）。
4. 切到英文界面时，上述文案是英文（i18n 双语文案到位）。

---

## 六、备注

- 范围仅限预览器文案，不动 pdf.js / react-pdf 的加载链路本身。
- `react-pdf` 是可选依赖（`pdf-viewer.tsx:10` 有 `@ts-ignore`），改 `error` 时注意保持该依赖缺失时不崩。
