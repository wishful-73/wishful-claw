# v2-iter-24：全局产品经理 Agent + 会话临时 Todo + 上下文恢复可靠性（进行中，需求重写中）


**目标**：建立一个全局 Agent 作为通用小助手/产品经理，能够跨项目查看工作上下文、维护自己的全局任务、向具体项目会话发送消息和工作请求，并根据会话的显式回复继续推动工作；同时将项目会话 Agent 的临时 Todo 按 OpenCowork 语义补齐为可靠的会话内执行辅助，并修复压缩快照恢复回压缩前全量历史的问题。

**可靠性前置**：在继续扩大 v2-iter-24 功能前，先完成 `plan-context-manifest`：由 `sessions.current_snapshot_id` 指向不可变压缩快照 manifest；普通消息/展示 mutation 不得使已提交 snapshot 失效；重启恢复必须使用 snapshot 前缀 + cursor 后增量，不能静默把压缩前历史重新送入 provider。

**任务边界**：

- 会话临时 Todo 使用 `tasks` 表和 `TaskCreate/Get/Update/List`，由当前会话 Agent 自主判断是否创建；输入可以来自用户或全局 Agent，均按同一规则处理。Todo 可以一轮完成，也可以跨多轮推进，用户和全局 Agent 都不管理、不读取、不统计。
- 全局任务使用独立 `global_tasks` 表，由全局 Agent 管理；一个全局任务可以向多个项目/会话分派工作，通过 `global_task_dispatches` 记录工作请求、投递状态和会话显式回复。
- Task Board 是全局 Agent 的任务管理和协调工作台，主数据源是全局任务及分派记录，不展示或依赖会话内部 Todo。
- 全局 Agent 发给目标会话的是外部消息/工作请求，不直接调用目标会话的 Todo 工具；目标会话是否建立临时 Todo完全由自身决定。

**边界**：本迭代不根据会话 Todo 状态推导全局任务状态，不让全局 Agent 读取或操作会话 Todo，不把全局任务自动映射为会话 Todo；默认只实现可靠投递和可见回复，不未经单独确认自动唤醒空闲会话执行。

**验证标准**：会话临时 Todo 的持久化、跨多轮推进、重启恢复和会话隔离闭环通过；全局 Agent 能跨项目创建全局任务、向多个会话发送消息/工作请求并接收显式回复；Task Board 能展示和推动全局任务及分派记录，且不泄漏会话 Todo。
