## 〇、重大订正（14:55，读 `scripts/deploy.mjs` 后）

老大 14:54「你看下脚本里面呢，我让另一个会话写了怎么上传的脚本」⇒ 读脚本后发现**两处必须推翻自己的东西**：

### ① 我此前「官网下载按钮是 404 死链」的判断 —— **错了**

实测：

```
GET https://wishful-claw.work/downloads/wishful-claw-0.2.34-setup.exe  →  200  application/octet-stream
```

脚本把安装包放**站点目录之外**的 `/data/downloads/wishfulclaw`，nginx 用 `/downloads` 映射过去（`CFG.downloadsDir` / `CFG.downloadUrlPrefix`）。**按钮是活的，不是死链。** 我上一条只 curl 了 `/releases/latest.yml` 就下了结论，没查 nginx 这一层。

### ② 我原方案「官网开站点内 `releases/` 目录」有硬伤 —— **改掉**

`deploy.mjs` 的 `deploySite` 是**整体替换站点目录**：

```bash
sudo mv '/data/sites/wishfulclaw' /data/sites/.prev-deploy
sudo mv /data/sites/.staging-deploy/dist '/data/sites/wishfulclaw'
```

⇒ 资产放站点内，**每次发站都会被清掉**。脚本作者用「站点外目录 + nginx 映射」规避了这点（脚本注释原话：「刻意放站点目录之外 —— site 发布会整个换掉站点目录，安装包放里面会被一起清掉」）。
⇒ **方案改为复用脚本的下载目录** `https://wishful-claw.work/downloads/`，**不新建 `releases/`**。

### 真正要解决的问题没变，而且更清楚了

| 路径 | 现状 |
|---|---|
| `/downloads/wishful-claw-0.2.34-setup.exe` | **200** ✅ |
| `/downloads/wishful-claw-0.2.34-setup.exe.blockmap` | **404** ❌ |

⇒ 下载目录里**只有 exe** ⇒ 官网侧**差分不成立**、app 内更新走官网也不成立。老大最初的第二问「这个下载理论上是一个文件夹，里面有 exe 安装包，也有增量的一些相关文件才对」，指的正是缺的这两件。

## 三、目标形态

```
/data/downloads/wishfulclaw/                              ← nginx: https://wishful-claw.work/downloads
├── latest.yml                                            ← electron-builder 自动生成（唯一清单）
├── wishful-claw-0.2.35-setup.exe                         ← 站点下载按钮指向它
└── wishful-claw-0.2.35-setup.exe.blockmap                ← 差分下载靠它
```

- **一份清单喂两个用途**：官网按钮读 `version` + `files[0].url`；app 内更新读 `sha512` / `size` / `path`。
- **`latest.yml` 内容一字不改**：`url` / `path` 都是相对文件名，`generic` provider 只要 `<feed>/latest.yml` 与 `<feed>/<path>` 同目录可达。
- **发版零手改**：覆盖三件即完（前端运行时读清单，**不需要重新构建站点**）。
- **只留最新版本**（老大 14:53 定）：差分不需要服务器留旧包，回滚靠 GitHub Release。
