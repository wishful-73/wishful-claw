## 范围与功能单元（交付 18 条 / 移交 3 条 / 否决 1 条 / 撤销 3 条）

### 门禁先自证（刀 0）

- **S-296 `tests/**` 进 `typecheck`（刀 0）** —— 门禁本身，先补齐再干活。此前 100 多个测试套件从没被 `tsc` 编译过：`npm test` 走 esbuild 只剥类型、不查类型，断言写错会恒真。新增 `tsconfig.test.json` 并挂进 `typecheck` 串行链（`typecheck:node` → `typecheck:web` → `typecheck:test`），此后门禁是三条串行、不再是两条。**这一刀的收益在下游立刻兑现**：后续每刀新增的断言都在这层类型检查之下。

### 五张「不报错」的脸（刀 1~6）

- **S-298 更新说明二次点开就没了（刀 1，commit `3008dc35`）** —— 不是拉不到，是**重复检查把已拿到的说明抹掉**。11-02 09:24 老大复测反馈「实际更新时没有遇到了」⇒ 现象已停，本条按修复收口。
- **S-299 定时任务被 15 轮掐断（刀 2）** —— 老大 20:11 拍板：**默认不限，轮次手动设**。改动的实质是「把 `0 = 不限` 贯通到底」—— 一轮 1 秒和一轮 3 分钟在同一个数字下被同等对待才是真问题。
- **S-300 全局任务可选归属项目（刀 3）** —— 全局任务加 `project_id` 属性字，项目会话只能查本项目任务、且只读（三条语义见 plan §三，按建议实施）。老大原话是「可选**属性**」，属性不等于搬家 ⇒ 全局任务板照旧显示，加归属标签。
- **S-292 渠道 `/compress` 是 no-op（刀 4）** —— 选「删命令」而非真压：界面按钮走 `compressSessionContext` 本来就是好的，只有渠道命令是死路，真压需在 main 复制 provider 上下文，代价与收益不匹配。
- **S-293 preview / dev 污染生产库 schema（刀 5）** —— 判据拆两半：纯函数 `assessDataDirRisk` 负责「这个目录该不该写」，DLL 侧只负责调用。生产库里出现只存在于本迭代 DDL 的空表，是这条需求的现场证据。
- **S-291 定时任务推送历史回复（刀 6）** —— `ActiveAutoReply` 记 `baselineMessageCount`（注册回执时的水位）：本次零输出时不再翻到上一次的 assistant 消息。与上面四条同源 —— 押「会话里最后一条 assistant 就是本次结果」。

- **测试套件 119 → 122**（`npm test` 全程绿）。新增的套件都挂在「一条判据一个纯函数」的口径上：需要跨语言共用判据的地方，两侧各写一遍并用注释互相指名。
- **`dotnet build` 用 `-t:Rebuild` 才是可信口径**：增量构建 1.5 s 就跑完，读到的是 `obj/` 缓存。收尾验收一律 Rebuild。
- **格式**：新增与大改文件全部 CRLF / UTF-8 无 BOM / 裸 LF = 0。
- **官网本迭代零改动** ⇒ 发版只走 `installer`，不重发站点。
- **PowerShell 读 UTF-8 中文文档仍会出 GBK 乱码**（`Get-Content`），规矩未变：读用 `[IO.File]::ReadAllText($p,[Text.Encoding]::UTF8)`，写用 `UTF8Encoding($false)`；长中文先用 Write 落地再搬运，不走 here-string。
