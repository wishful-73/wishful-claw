# S-147 请求日志的报错信息支持一键复制

- **登记日期**：2026-09-23
- **登记来源**：老大 16:05「再新增一个需求 请求日志里面如果请求报错有错误信息，希望有复制图标点击后可以复制」
- **分支**：`dev/v2-iter-36`
- **状态**：✅ 已实施

---

## 一、定位

「请求日志」= 设置 → 用量统计 → **请求明细**（`components/settings/usage-detail-table.tsx`）。
判定依据：该页脚注原话是「统计基于模型请求日志（每次 HTTP 请求一行，含重试与失败）」，行数据里带着
`status` / `errorKind` / `errorMessage` / `httpStatusCode`。

**失败行（`row.status === 'error'`）的现有呈现**：

- 成本列显示 `⚠ <errorKind>`（如 `rate_limit`）；
- **完整错误信息只挂在 `<tr title>` 上** —— 悬浮能看到全文，但既没有可见文本，也没有任何复制入口。

⇒ 用户想把这串东西拿去排查 / 贴给上游，只能自己照着悬浮提示手敲。

---

## 二、改法

在成本列的 `⚠ <errorKind>` 之后加一个**复制图标按钮**：

- **只在有错误文本时渲染**（`errorMessage?.trim() || errorKind?.trim()` 非空），不给空按钮占位；
- 点击复制的是**悬浮提示里的那一整段** —— `errorMessage` 优先，退回 `errorKind`；
- 点击后 1.5s 内换成对勾，与仓库里其它复制按钮同款写法（`change-review-helpers` /
  `file-change-diff`）；点击时 `stopPropagation`，避免将来行上挂点击行为时打架；
- `<tr title>` **保留**（悬浮看全文仍是快速通道）。

新增 i18n 键 `usage.detail.copyError`（zh「复制错误信息」/ en「Copy error message」），
按钮的 `title` 用它。

---

## 三、验收

1. 失败行且有错误信息 ⇒ 行上出现复制图标；点一下，剪贴板拿到完整错误信息。
2. 失败行但**没有**错误信息 ⇒ 不出现按钮（不给空入口）。
3. 非失败行不受影响（仍显示成本）。

---

  `errorMessage`，只是此前没被用起来）。
