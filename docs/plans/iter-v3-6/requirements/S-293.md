# S-293 preview / dev 构建污染生产库 schema —— `pickDataDir` 没拦住「非打包构建指向已存在的生产目录」

> 登记：v3-iter-5 移交（`../iter-v3-5/raw-requirements.md` §4.1）
> 归属：**v3-iter-6 刀 5**（11-01 20:5x 已退出刀 0，降为普通刀）
> 类型：工程护栏（纯函数加判据）
> 状态：**✅ 代码完成 · 待真机验收**（2026-11-02）

## 一、现象与原证据

10-31 现场：生产库出现只存在于 v3-iter-5 DDL 的 `message_parts` / `global_message_dispatches` 两张**空**表，而当时跑的是 1.0.3。

**原证据已失效**：11-01 实测生产库 `message_parts` **284 行**、`global_message_dispatches` **0 行** —— 1.0.5 已发布，这两张表就是 1.0.5 的正式 DDL，284 行是生产实例自己正常写入的。⇒ 污染痕迹被正式版本覆盖，当时怎么进去的无法复核。

## 二、剩余真实风险

只有一个：**我们自己开发时显式把数据目录指向生产库**（`WISHFULCLAW_DATA_DIR`）。用户侧零风险 —— dev 默认走 `.wishful-claw-dev`。

代价不对称：今天只多两张空表，哪天加了 `ALTER TABLE`，代价就不是修 bug 而是恢复数据。

## 三、判据设计

`shared` 层不能引 `node:fs`（同时被 `tsconfig.web.json` 编译）⇒ 拆成两半：

- **纯函数** `assessDataDirRisk(decision, isPackaged, probe)`（`src/shared/data-dir.ts`）
- **探测** `inspectDataDirRisk()`（`src/main/lib/data-dir.ts`）—— 用 `existsSync` 探「目录存在 + 有 `index.db`」，再交给纯函数

三级判定：

| 情形 | 级别 | 理由 |
|---|---|---|
| 打包版 | `ok` | 生产实例用自己的库天经地义 |
| 非打包 + **未显式配置** | `ok` | 默认目录 `.wishful-claw-dev` 里的 `index.db` 是它自己写的，拦它等于拦掉正常开发 |
| 非打包 + 显式 + 目录不存在 / 无 `index.db` | `ok` | 新建，没有污染可言 |
| 非打包 + 显式 + 有库 + **末段就是 `.wishful-claw`** | **`block`** | 「拿生产库开发」，没有合理解释 ⇒ 拒绝启动 |
| 非打包 + 显式 + 有库 + 其它目录名 | `warn` | 可能是用户自己的第二份库 ⇒ 放行 + 日志 |

**逃生舱**：`WISHFULCLAW_ALLOW_SHARED_DATA_DIR=1` 把 `block` 降级为 `warn`。不给开关，唯一的选择就是去改代码 —— 那比显式放行更难查。

## 四、实施记录（2026-11-02）

| 文件 | 改动 |
|---|---|
| `src/shared/data-dir.ts` | 新增 `DataDirProbe` / `DataDirRisk` / `assessDataDirRisk` / `WISHFULCLAW_ALLOW_SHARED_DATA_DIR_ENV`；`lastSegment()` 手写切分（不引 `node:path`） |
| `src/main/lib/data-dir.ts` | 新增 `inspectDataDirRisk()`：`existsSync(dir)` + `existsSync(join(dir,'index.db'))`，含逃生舱降级 |
| `src/main/index.ts` | 启动序列**建目录 / 单实例锁之前**判一次：`block` ⇒ `dialog.showErrorBox` + `app.exit(1)` + `throw`；`warn` ⇒ `console.warn` |
| `tests/data-dir/program.ts` | 断言 17 → **25**：打包版 ok、默认目录 ok、不存在/空目录 ok、生产目录名 block、尾部带分隔符仍 block、其它已有库 warn、block 说明必须带逃生舱名 |

顺序为什么重要：一旦单实例锁拿到，Worker 可能在后面任意时刻把 schema 改掉。所以判据必须在 `mkdirSync` / `app.setPath` / `requestSingleInstanceLock` **全部之前**。
