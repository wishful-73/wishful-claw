## 已否路线一：变声器（老大 14:40 提问，14:42 分析后否）

- `window.speechSynthesis` 的音频由浏览器**直接交给系统音频输出**，JS 侧**拿不到任何音频出口**（无 `MediaStream`、无 `AudioBuffer`、无回调）⇒ Web Audio 无从介入。**不是代价大小的问题，是通路不存在。**
- 且变声器改的是**音色特征**（音高 / 共振峰），**改不了合成质量**；「难听」的根因是音质。花代价把一种机械音变成另一种机械音，不划算。
- **零代价的伪变声顺带项**：`utterance.pitch` 改一行即可改音调（变调不变速），但多半只会更难听 —— 可作兜底微调，**不作为目标**。

- 仓库**有整套云端 TTS 链路**：C# `openai-audio/speech`（`OpenAIAudioModule.cs:22` → `OpenAIAudioTools.SpeechAsync`）真实注册可用；前端 `lib/pet/pet-voice-audio.ts`（`synthesizeClip` / `playClip` / `streamAndPlay` 流式边下边播）+ `lib/pet/pet-voice.ts`（句子切分、`createPetSpeechSession`、音色预设）也真实；支持 OpenAI `/audio/speech` 与 chat-audio（MiMo TTS）两种 transport，音色 OpenAI 11 种 / MiMo 9 种。

**落地**：

| 项 | 说明 |
|---|---|
| `speakMessage` 加可选 `onEnd` 回调 | 念完 / 出错时触发一次；两个消息朗读入口不传，行为不变 |
| 导出 `stopSpeaking()` | 掐掉当前朗读 |
| 设置页语音段加「试听」按钮 | 播放中变「停止」，点击即掐 |

**预设文本落 i18n（`general.speech.preview.sample`）跟随界面语言**，不硬编码 —— 中英混排会被 `detectLang` 判成中文，英文音色就试不出来；跟随界面语言时，「音色 = 自动」能直接试出实际生效的那个音色。

**一处实现坑**：`synth.cancel()` **也会把上一条的 `end` 事件打出来**。若直接 `setPreviewing(true)` → `speakMessage(...)`（内部先 cancel），旧条的 `end` 会同步回调 `onEnd` → 把刚置上的 `true` 冲成 `false` ⇒ **正在念却显示「试听」**。处理：`speech.ts` 用模块级 `current` 认领当前 utterance，**在 `cancel()` 之前**赋值；`onEnd` 里先比 `current === utterance`，不符就返回。

## 音调上限能不能往上加？—— 实测：不能（2026-09-22 15:21）

老大问「音调上限还可以加不」。**结论：加不了，2 就是硬顶。**

探针 `.wishful-claw/tmp/pitch-probe.js`（Electron 43.2.0 / Chromium 150.0.7871.129）赋 `SpeechSynthesisUtterance.pitch` 后读回：

| 赋入 | 读回 | 行为 |
|---|---|---|
| 0 / 0.5 / 1 / 1.5 / **2** | 同值 | 正常接受 |
| **2.5 / 3 / 4 / 10** | **2** | **夹回上限 2** |
| −1 | 0 | 夹回下限 0 |

`rate` 同源（下限 0.1、上限 10，赋 20 读回 10）。

⇒ 滑条往上加**没有意义**：拖到 3 和拖到 2 在 API 层就是同一个值，用户只会以为滑条坏了。**要更宽的变调只能自己做音频流**，而这条已在本文「已否路线一」否掉（`window.speechSynthesis` 拿不到音频出口）。
