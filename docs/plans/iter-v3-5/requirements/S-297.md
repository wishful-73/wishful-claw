## 一、事实

`src/renderer/src/components/layout/search-dialog.tsx` 原 :39：

```ts
const sessions = useChatStore((s) => s.sessions)
```

`SearchDialog` 挂在应用壳上，**对话框关着也一直在树里**。流式输出每帧换 `sessions` 数组引用 ⇒

1. 本组件每帧重渲（整棵 JSX 树重新创建，`open=false` 时 Radix 不挂子树，但树照样新建）；
2. `recentSessions` 的 `useMemo` 依赖 `[sessions, activeSessionId]` ⇒ **每帧对全部会话做 `filter + sort + slice`**（dev 库 100 条）。

跟对话框开没开完全无关。S-247 §21.3 摘订阅 A/B 实测：dev nomount 90 行场景 **0.38 → 0.16 MB/s**，占残量 **58%**。

同款 `DispatchDialog.tsx:54` 实测 ≈0（噪声内）⇒ **不动**。

## 二、改法

新增 `src/renderer/src/components/layout/search-dialog/recent-sessions.ts`（单测可跑，不 import store）：

| 导出 | 作用 |
|---|---|
| `buildRecentSessionsSignature(sessions, activeSessionId, limit=5)` | **单次遍历**取 top-5，只拼一个字符串。不 sort、不 slice、不产数组 |
| `selectRecentSessions(...)` | 真要渲染时才调，一次 sort + slice |
| `RECENT_SESSIONS_LIMIT` / `EMPTY_RECENT_SESSIONS` | 常量 |

两者共用内部 `pickRecentSessions` 的排序口径（`updatedAt` 倒序，同值按 `id` 升序保证确定性），
避免「签名算的 5 条」和「渲染的 5 条」错位。分隔符用 `\u0001` / `\u0002`（title 里可能带 `:` `|`，用可打印字符会撞车 —— 侧栏 S-247 签名踩过同款坑）。

`search-dialog.tsx` 改成：

```ts
const recentSessionsSignature = useChatStore((s) =>
  open ? buildRecentSessionsSignature(s.sessions, s.activeSessionId) : ''
)
const recentSessions = useMemo(() => {
  if (!open) return EMPTY_RECENT_SESSIONS
  const state = useChatStore.getState()
  return selectRecentSessions(state.sessions, state.activeSessionId)
}, [open, recentSessionsSignature])
```

关键点：**关闭态 selector 直接返回常量 `''`**（零计算、字符串相等 ⇒ zustand 不通知），
只有打开时才按 top-5 签名重算；打开态下别的会话在流式 churn **不触发**重算。

`DispatchDialog` 按实测不动。

## 四、回归套件 `tests/search-recent-sessions`（14 断言，已进 `npm test`）

钉两件事：

1. **渲染口径**：倒序取 5、排除当前会话、limit、同值按 id 升序、空库空签名、title 带 `:`/`|`/`,` 不撞车。
2. **签名口径（双向）**：
   - top-5 内 `title` / `updatedAt` 变了 ⇒ 签名**必须变**（否则显示陈旧数据，最难查的那类）；
   - **top-5 之外**的会话 churn 或被删 ⇒ 签名**必须不变**（这就是性能修复本身，写错等于修复白做）。
3. 源码守卫：`search-dialog.tsx` 不许再直订 `s.sessions`、必须用 `buildRecentSessionsSignature`、
   关闭态必须短路。守卫前先剥注释（说明性注释里会写出「原来那行」，不剥会误报 —— 第一次跑就撞上了）。

**反向验证**（`.wishful-claw/notes/s297-reverse-verify.mjs`，跑完自动还原）：

| 破坏方式 | 结果 |
|---|---|
| 签名去掉 `title`（漏字段） | 红，命中「top-5 内的 title 变了」 |
| 签名不截断 top-5（退回全量） | 红，命中「【性能核心】top-5 之外 churn」 |
