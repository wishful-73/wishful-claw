# S-203：官网页脚（含备案条）在高分辨率屏幕上不贴底 —— 内容不满一屏时 footer 悬在半空

> 状态：**已实施，待收尾裁定**（2026-10-16 实施完成；官网 `npm run build` 0 错；视觉验收并入迭代阶段六）。
> 类型：**bug**（样式缺陷）。
> 归属：**iter-v2-40**。
> 来源：**老大 2026-10-14 17:33 登记** —— 「官网样式 底部的备案这个条 我换一个分辨率高的显示屏 底部就没有再底部了」。
> 轨道：**官网侧**（独立于软件版本，与 S-182 / S-186 同轨）。

---

## 一、现象

换到高分辨率显示屏后，官网页脚底部那条（`© 2026 WishfulClaw · ICP 备案号 · 公安备案`）**不再贴在视口底部** —— 它下面留出一段空白，页脚悬在页面偏下的位置。

分辨率越高（垂直方向像素越多），底下那段空白越大。

## 二、根因

`website/src/index.css` 的 `#root` **没有任何高度或布局约束**，四个页面入口在 `#root` 里渲染的都是同一种结构：

```
<SiteHeader /> <main>…</main> <SiteFooter />
```

落点：

- `App.tsx:19-31`（首页）
- `components/doc-page.tsx:45-100`（使用指引，`SiteFooter` 在 `:99`）
- `download-page.tsx:13-69`（下载页，`SiteFooter` 在 `:68`）

页面内容总高**小于视口高度**时，`<footer>` 就紧跟在 `<main>` 内容结束的位置，**没有任何机制把它推到视口底部**。

⇒ 这不是「页脚定位错了」，是**页面容器缺少「撑满视口 + 把页脚顶到底」的布局**（sticky footer 缺失）。

低分辨率屏上内容本身就超过一屏，所以看不出问题；换高分辨率屏后内容不满一屏，症状才暴露 —— 与老大描述逐字吻合。

## 三、影响面

| 入口 | 组件 | 页脚 | 是否受影响 |
|---|---|---|---|
| 首页 `/` | `App.tsx` | ✅ | **是** |
| 使用指引 `/guide` | `guide-page.tsx` → `components/doc-page.tsx` | ✅ | **是** |
| 下载页 `/download` | `download-page.tsx` | ✅ | **是** |
| 下载中转页 `/go` | `go-page.tsx` | ❌ 无页脚 | 否（自身已 `min-h-screen` 居中） |

四个入口**共用同一份 `src/index.css`**（`main.tsx` / `guide-main.tsx` / `download-main.tsx` / `go-main.tsx` 各 `import './index.css'`）⇒ 容器层的改动**一处生效**。

## 四、修法

**容器撑满视口 + 内容区吃掉剩余高度**，两处小改：

1. `website/src/index.css` —— 给 `#root` 加：

   ```css
   #root {
     display: flex;
     flex-direction: column;
     min-height: 100vh;
   }
   ```

2. 三个带页脚的页面组件 —— 各自的 `<main>` 加 `flex-1`（`App.tsx` / `doc-page.tsx` / `download-page.tsx`）。

⇒ 页脚成为 flex 子项，被 `main` 的 `flex-1` 顶到容器底部。**内容超过一屏时行为完全不变** —— `flex-1` 只在「还有剩余空间」时才起作用。

`go-page.tsx` 的 `<main>` 已有 `min-h-screen` + `items-center justify-center`，在 flex column 容器里会被拉伸填满，**居中效果不变** ⇒ 不需要改。

**取舍点（记录，供裁定）**：`100vh` 与现有 Tailwind `min-h-screen` 语义一致（都是 `100vh`）。移动端浏览器地址栏收放会让 `100vh` 略高于可视区，更稳的写法是 `100dvh` —— 但那会**改变移动端现有行为**，不在本条范围内，故沿用 `100vh`。

## 五、验收判据

1. **高分辨率屏**（或把浏览器窗口拉高到内容不满一屏）：首页 / 指引页 / 下载页的页脚**贴视口底部**，下方无空白。
2. **内容超过一屏**时：页脚位置与修前**一致**（滚动到底才看到），不出现「页脚跟着视口浮在中间」。
3. `/go` 中转页的居中效果**不变**。
4. `cd website; npm run build` 0 错。

## 六、非目标

1. **不改页脚的内容与样式**（配色、字号、备案信息文案）。
2. **不改任何页面的内容高度或区块顺序**。
3. **不动 `/go` 页的布局**。
4. **不引入 `100dvh`**（见 §四 取舍点）。

## 九、代价与取舍（实施后回填）

- `min-height: 100vh` 沿用 Tailwind `min-h-screen` 同值，**不引入 `100dvh`**（见 §四 取舍点）—— 移动端地址栏收放时 `100vh` 会略高于可视区，是既有的、不动它。
- 三个页面各自挂 `flex-1` 而非在 `#root` 上统一处理：因为 `go-page.tsx` 也走 `#root`，给它加统一规则会把无页脚的 `/go` 一起改掉。分散挂类名是**有意的**，不是遗漏。

## 十、刻意不做

1. 不改页脚内容 / 样式（配色、字号、备案文案）—— 与症状无关。
2. 不动任何页面的内容高度与区块顺序。
3. 不动 `/go` 页布局。
4. 不引入 `100dvh`。
