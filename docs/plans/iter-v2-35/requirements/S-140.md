### 2.3 机制

差分需要**旧基准包**：`%LOCALAPPDATA%\wishful-claw-updater\installer.exe`。

- 写入者 = NSIS 安装器 `node_modules/app-builder-lib/templates/nsis/include/installer.nsh:93`
  `!insertmacro copyFile "$EXEPATH" "$LOCALAPPDATA\${APP_INSTALLER_STORE_FILE}"`（**无条件执行**，已核实）。
- electron-updater 读它 + 服务器拉的旧版 blockmap（URL 由新路径把版本号换成 `app.version` 得到，`util.js:38`）算差异块。
- 写入分支条件：`APP_INSTALLER_STORE_FILE` 只在「**非 web installer 且 `APP_BUILD_DIR == null`**」时定义，而 `USE_NSIS_BUILT_IN_COMPRESSOR` **硬编码 = false** ⇒ 走内嵌包分支 ⇒ **确实会写基准**。

### 2.4 已排除项

- **sha512 逐字节复核 MATCH**：`installer.exe` = `BBukXVkt…I2w==`（与 `release/latest.yml` 一致）。
- `Created = 2026-09-23 08:26:16` / `Modified = 08:25:38` ⇒ 从 `pending\` 复制、保留源时间 ⇒ **只有 app 内更新安装才写基准**。
- 安装目录 `C:\Program Files\WishfulClaw` **410 MB**（远超 108 MB 包）⇒ 确认非 web installer、非 `APP_BUILD_DIR` 分支；注册表 `DisplayVersion = 0.2.34`。
- 卸载只清 `$APPDATA`（Roaming），**不动** `%LOCALAPPDATA%` 基准。
- 依赖版本从未变：`app-builder-lib` **26.15.3**（`02e57d3f` / `e2ba660c` / `e9fcd627` / `07782bae` 各快照一致）。
- 本机只有 `C:\Users\龚翼` 一个用户目录，无其它 `wishful|claw` 名 updater 缓存目录 ⇒ **「改名换缓存目录」假设不成立**。

## 三、当前结论

1. **发布侧无问题** —— 产物规格与历史一致，不是「这次打的不一样」。
2. **失败原因是本地差分基准缺失** ⇒ electron-updater 按设计 fallback 全量。这是**一次历史事故**，不是持续状态。
3. **基准现已就位**（sha512 与 0.2.34 包一致）⇒ **0.2.34 → 0.2.35 应能走差分**。下次发版盯日志 `Download block maps` 之后是否还跟 `ENOENT`。

### 2. 34 对 updater 的全部改动 = 3 处，都不删基准

34 里唯一碰 updater 的是 `31b53119`（S-111），`git show` 全文核对，只有：


⇒ **只 `emptyDir(cacheDir\pending)`，绝不碰根目录 `installer.exe`。S-111 无罪。**
