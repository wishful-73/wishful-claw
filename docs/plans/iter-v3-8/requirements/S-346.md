## 一、是什么

`src/renderer/src/lib/app-plugin/image-tool-retry.ts` 全文 13 行，核心是后 3 行：

```ts
export function resolveImageGenerateRetry(_error: string): ImageGenerateRetryState | null {
  return null
}
```

**两个问题叠在一起**：

1. **恒返回 `null`** —— 什么也不做
2. **形参叫 `_error: string`，唯一调用点传的实参却是 `toolUseId`** —— 名字和实参语义完全对不上，说明这函数是被掏空后留下的壳，签名都没跟着改

## 二、调用点（唯一，实测）

`src/renderer/src/components/chat/ImagePluginToolCard.tsx:201`，在一个确认框之后：

```tsx
const handleRetry = async (): Promise<void> => {
  if (!toolUseId || !retryState) return
  const confirmed = await confirm({
```

按钮渲染在 `:297`：

```tsx

```

**用户视角**：图片生成撞上 `awaiting_retry` 状态 → 卡片出现「重试」按钮 → 点它 → 弹一个「已完成 X / 共 Y，是否重试」的确认框 → 点确认 → **弹窗关掉，什么也没发生**。

这个体感比「没有按钮」更糟：按钮 + 确认框 + 文案样样齐备，走完全程才发现是死的。

也就是说：**后端已经把「该重试了」完整告诉前端了，前端的提示、计数、确认框全都做好了，唯独最后那一下「发出去」是空的。**

## 四、怎么修

**先查清「发出去」该走哪条路，再动代码。** 三种可能，实施时按实际选：

1. **如果 `toolUseId` 足以重发** —— 后端有按 `toolUseId` 重跑图片生成的端点/通道，那 `resolveImageGenerateRetry` 改成调用它。此时函数名该改成 `retryImageGenerate`（名字对着实参，别再留 `_error` 这种错签名）
2. **如果重试走的是「往会话里补一条用户消息」** —— 那这里改成构造一条 `{ type: 'retry_image', toolUseId, completedCount, totalCount }` 的消息提交，因为后端要靠这些参数知道跳过哪几张
3. **如果后端根本没有重试入口** —— 那这个按钮是**从没接通的功能**，正确处置是**删掉按钮 + 提示块**（连同 `retryRequired` / `retryHint` / `retryCaveat` / `waitingRetry` 几个 i18n 键），而不是留一个骗人的按钮。同时 `_retryState` 若也就没人用了，一并清

**判断依据**：查 `src/main` 与 native worker 侧有没有对应通道。查不到就走第 3 条。**不猜。**

## 六、实施判定（2026-11-06 11:4x）—— 走方案 3

**查通道的结果：没有。** 三层证据，缺一条都不足以定案：

1. **`parseRetryState` 读的字段根本不存在**。它读 `input._retryState` —— `input` 是**模型传给工具的入参**，不是后端回来的结果。模型不可能带 `_retryState` 这个字段，所以 `parseRetryState` 恒返 `null`，`retryState` 恒 null，`isAwaitingRetry` 恒 false。
2. **全仓 C# 侧 `awaiting_retry` 零命中**。搜 `_retryState` / `awaiting_retry` / `retryState`：main、preload、native worker、`src/runtime` 全部 0 处。也就是说没有任何后端会「进入等待重试状态」。
3. **`AgentRuntimeImageGenerateExecutor.cs`（113 行）是一次性 reverse-request**。`image:generate` 的语义是：调一次，成功返回结果、失败返回 `{ error }`。**没有「分批生成 + 第 N 张失败 + 停下来等用户确认」这个概念**，所以就算按钮能点，后端也没有可续跑的状态。

**结论**：这不是「按钮坏了」，是**按钮从来就不存在**——`retryState` 恒 null ⇒ 整个提示块和按钮块永不渲染。登记时说的「点了没反应」，实际是「**根本点不到**」。这套 UI 是从 OpenCowork 抄卡片时一起带过来的，移植时后端没接。

**处置**：全线删除。

|---|---|
| 整个文件 13 行 | `src/renderer/src/lib/app-plugin/image-tool-retry.ts` |
| `parseRetryState` 28 行 + `handleRetry` 16 行 + 重试提示/按钮块 33 行 | `ImagePluginToolCard.tsx` |
| `toolUseId` prop 及其调用方传参 | `ImagePluginToolCard.tsx` + `tool-block-renderer.tsx` |
| 7 个 i18n 键 × 2 语言 | `locales/zh/chat.json`、`locales/en/chat.json` |
| `Button` / `confirm` 两个随之失效的 import | `ImagePluginToolCard.tsx` |

**保留**：`requestedCount`（`:235` 的 `countValue` 仍在用，卡头「共 N 张」是活的）；`TriangleAlert`（`hasError` 块仍在用）。

**零可观察变化** —— 删的东西本来就不渲染。§五 的验收清单**整体作废**（场景 1、2 构造不出来），只需确认场景 3 不受影响，而场景 3 走的代码一行没动。
