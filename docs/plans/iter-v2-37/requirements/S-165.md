## 一、参考项目踩的坑

走 Google 的 OpenAI 兼容层时，工具调用**整帧给全**（id / name / arguments 同帧到齐，还多带一个 `extra_content.google.thought_signature`），**一个 `index` 都不带** —— 上游没写错，是它的解码器只认「流式片段」那一种形状，把合法帧判成 `invalid tool call`，`retryable: false`，整轮中止、正文一个字都没有。

它的修复是**三步归格**，顺序不能换：

1. 同 `id` 的调用已存在 → 并进去（`id` 比位置权威；还在分片累积时按前缀认）
2. `position` 那一格还可用 → 用它（**空着是常态；里面那个调用还没 `started` 也算可用** —— 这一帧正是它的下一片）
3. 否则 → 另开一格

第 ③ 步是**并行调用的命门**：省 index 的上游把并行调用一条一条发，第二条的 position 同样是 0 —— 并进去会把两个调用**串成一个**，参数被拼成非法 JSON，回传时少一个 `tool_use` id，下一轮直接 400。

## 二、我们的实现（2026-09-29 实读 `OpenAIChatSseParser.cs`）

归格就一行：

```csharp
// OpenAIChatSseParser.cs:20
var index = JsonHelpers.GetInt(fragment, "index", toolBuffers.Count);
```

`ToolCallBuffer` 按 `int index` 存在 `Dictionary<int, ToolCallBuffer>`（`:16`），flush 时 `OrderBy(item => item.Index)`（`:76`）。

### 2.1 不会踩的两个坑（我们比它稳的地方）

| 参考项目的症状 | 我们 |
|---|---|
| 合法帧被判 invalid ⇒ **整轮中止、正文全空** | ✅ **不会** —— 我们对不合法帧是**跳过**不是中止（`TryCreateCompletedToolCall` `:96` 只返回 `false`），没有那种严格校验 |
| 无 `index` 的**并行**调用被串成一个 | ✅ **不会** —— 缺省时 fallback 到 `toolBuffers.Count`，逐帧递增 ⇒ 两条并行调用会落到 `0` 与 `1` 两格 |

### 2.2 但有三个真隐患

**隐患 1 —— `Count` 作 fallback 的语义是「新建一格」，不是「找可用格」。**

`toolBuffers.Count` = **已建格数**。当上游**混合**显式 / 缺省 `index` 时（有的第一帧带 `index`、后续帧不带，或反之）：

- 帧 1：`index: 0` 带 `id=A` ⇒ 建 `buffer{0}`，此时 `Count = 1`
- 帧 2：**无 `index`**，其实是 A 的 `arguments` 续片 ⇒ fallback = `Count` = **1** ⇒ **另建 `buffer{1}`**

⇒ 同一个调用被劈成两格：A 参数不全，另多出一个空调用。参照项目第 ② 步（「里面那个调用还没 `started` 也算可用」）本可以救回来 —— 我们**没有这一步**。

**隐患 2 —— 完全没有 `id` 归并兜底。**

`:27-30` 只在**已选定的那一格**上设 id：

```csharp
if (JsonHelpers.GetString(fragment, "id") is { Length: > 0 } id && string.IsNullOrEmpty(buffer.Id))
    buffer.Id = id;
```

⇒ `id` 帧与参数帧一旦被分到不同的 index 格，**不会合并**（参照项目第 ① 步正是干这个的）。

**隐患 3 —— 无 `index` 的片可能插到显式大 `index` 的前面。**

flush 按 `Index` 排序（`:76`）。若已有 `buffer{5}`（显式 index）而 `Count = 1`，此时来了一个无 `index` 的续片 ⇒ 落到 `index = 1` ⇒ **排序后排到 5 前面** ⇒ **工具执行顺序被打乱**。

### 2.3 现实概率

我们的主流上游（DeepSeek / OpenAI / Anthropic / 智谱）**都是标准分片形状**（每帧带 `index`），所以上面三条**平时不会现形**。风险集中在走**兼容层**的路径（Google 兼容层是已知的怪形状），或上游实现不规范时。

⇒ **无实测症状，属预防性加固。**
