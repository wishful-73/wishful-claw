## 一、A 档：必须你亲手过（6 组）

### A-1 全 Agent 层 SQL 收口（刀 23~29，S-328 / S-333 / S-334 / S-335 / S-336 / S-337 / S-338）

**为什么必测**：这是本迭代最大的一刀 —— **9 张表、30 处手写 SQL 字面量全部改成常量/参数化**。写错一个列名、漏一个 WHERE，不会报错，只会「悄悄查不到数据」。

**怎么测（不用刻意造场景，正常聊两轮就覆盖了）**：

| # | 动作 | 要看到什么 |
|---|---|---|
| 1 | 新开一个会话，发一条消息，等回复 | 消息正常落库；**切走再切回，消息还在** |
| 2 | 左侧会话列表 | 列表正常、标题正常、时间正常；**不重复、不丢** |
| 3 | 让 agent 起一个子 agent（团队 / Task） | 子 agent 卡片能出；展开能看到它的运行记录 |
| 4 | 让 agent 建一个任务（task） | 任务板 / 任务页能看到这条；状态能改 |
| 5 | 打开右侧「目标 / 计划」相关面板 | 之前有的数据还都在；**没有变空** |
| 6 | 切换项目 | 项目下会话、任务、目标都对得上号 |

> **重点看「有没有变空」**。SQL 改错最典型的表现不是报错，是**列表突然空了**。你之前用过的项目 / 会话 / 任务，现在打开应该跟改之前一模一样。哪个空了就是哪张表改错了，把表名告诉我。

### A-2 浏览器工具判据复活（刀 36，S-345）+ 卡片摘要兜底（刀 39，S-348）

**为什么必测**：`isBrowserToolName` 之前是 `return false` 的假桩，导致**三套东西从来没渲染过一次**。这是它们**第一次**出现在你屏幕上，我要你确认「长得对」而不是「能出来就行」。

| # | 动作 | 要看到什么 |
|---|---|---|
| 1 | 让 agent 开内置浏览器，访问一个页面，然后**截图** | 出现**图片卡片**（不是一行灰字） |
| 2 | 让 agent 做几个浏览器动作（点击 / 输入 / 滚动） | 出现 `BrowserToolCard` —— 带浏览器图标、带中文摘要（如「点击 XXX」）的卡片 |
| 3 | 同时看**右侧时间轴 / 执行大纲** | 浏览器动作会被归到 **「浏览器」分类**下（之前会散在「其他」里或干脆不出现） |
| 4 | 让 agent 把浏览器切成手机形态（iPhone / Pixel / iPad / 自定义尺寸各试一次） | 卡片**主行**显示中文摘要（`桌面形态` / `iPhone` / `Pixel` / `iPad` / `自定义 390 × 844`），**副行**显示「浏览器设备模拟」，展开有「设备 / 视口」两行。**任何一格都不许出现 `BrowserSetDevice` 这种裸英文** |

> ⚠️ 注意：`BrowserToolCard` 这套卡片**代码写了很久但从未被渲染过**，可能有视觉上不协调的地方（对齐、图标大小、摘要文案）。**发现有丑的地方直接拍照给我，这是第一次验收，改起来最便宜。**

### A-4 子 agent 按会话过滤（刀 35，S-342）

**为什么必测**：`selectSessionScopedAgentState` 之前**恒返空**，等于「叫它按会话筛，它永远给你空」。我补了真实现，但这个函数**有 16 个调用点**，任何一个对不上就会表现为「看不到子 agent」或者「串会话看到别人的」。

| # | 动作 | 要看到什么 |
|---|---|---|
| 1 | 在会话 A 起一个子 agent，让它跑起来 | 子 agent 面板**能看到**它 |
| 2 | **切到会话 B**（B 没有子 agent） | 子 agent 面板**是空的** —— 不要看到 A 的那个 |
| 3 | 切回会话 A | A 的子 agent **还在** |
| 4 | 会话 A 跑完之后 | 跑完的子 agent 还留着记录，不是一跑完就消失 |

### A-5 内存回收（刀 8，S-322 会话闲置淘汰）

**为什么必测**：这是本迭代治内存的**根**，而内存问题只有真机能看出来。

| # | 动作 | 要看到什么 |
|---|---|---|
| 1 | 正常用，多开几个会话、聊十几轮 | 内存会涨 —— **涨是正常的，不用管** |
| 2 | **放着不管**（去干别的，5~10 分钟） | 回来看，内存**降下来了** |
| 3 | 再切回刚才闲置的会话，发一条消息 | 会话**能正常续上**（上下文还在，不用重新加载出问题） |

> 判断标准只有一句话：**「放着不动，它会不会自己降」**。会降就是对的。你之前说的「一次性冲高没事，不回收才是问题」——这条就是验收那件事。

### A-6 记忆库四 Tab（`9a4acfeb`，S-325 / S-326 —— 无刀号，介于刀 8 与刀 9 之间）

**为什么必测**：刀序表里没有它的位置（16:40 才登记、当晚插做），验收清单初版因此漏了这一项。而它动的是 `DbMemoryTools` —— 把 15 处手写 SQL 收进 Db 层，是**记忆库所有读写的唯一入口**，不是文档改动。

| # | 动作 | 要看到什么 |
|---|---|---|
| 1 | 设置 → 记忆库 → **四个 Tab**（热记忆 / 条目 / 库 / 归档）逐个打开 | 每个都能列出内容，不空、不报错 |
| 2 | **追加**一条记忆 | 立即出现在列表里；**重启后还在**（这一步才证明 SQL 通） |
| 3 | **改**一条记忆的正文 | 改完刷新仍是新内容 |
| 4 | **降级候选**、**批量状态**、**re-heat** 各点一次 | 状态跟着变，没有「点了没反应」 |
