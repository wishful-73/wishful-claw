## 范围与要点

### S-129 + S-143：官网成为完整更新源

- **病根**：版本清单有两份 —— `release/latest.yml`（electron-builder 生成，app 内更新读）与 `website/public/latest.json`（**人手写**、URL 带版本号，官网按钮读）⇒ 每次发版都要手改，且**已不同步过一次**（线上仍是 0.2.33 链接）；官网还**只托管了 exe**，blockmap / latest.yml 都没有 ⇒ 官网侧差分与 app 内更新都不成立。
- **定案**：官网托管 builder 三件（`latest.yml` + `setup.exe` + `.blockmap`，同目录成套），前端**改读 `latest.yml`**（清单单一真源，发版零手改），`latest.json` 退役；`electron-builder.yml` 的 `publish` 切 `generic` 指向 `https://wishful-claw.work/downloads/`。只留最新版本，差分不需要旧包。
- **发版不重建官网**：站点前端**运行时**读 `./downloads/latest.yml`，只换下载目录里的三件即生效；`deploy.mjs installer` 不碰官网，站点内容有改动才另跑 `site`。
- **S-143**：ICP 备案号（蜀ICP备2026057067号）进页脚 → 更新日志页下架、入口跳 GitHub → 公安备案（川公网安备51080202020186号）+ 徽标图。
- ⚠️ `scripts/deploy.mjs` 不在版本库（`.gitignore` 刻意排除，内含服务器地址与部署密钥路径），换机器要手动拷。

### S-144 / S-153：沙箱路径边界

- **S-144**：agent 调文件工具时不传 `workingFolder` ⇒ 沙箱把整个项目目录判为越界。连锁影响：这才有「被拦后弃用文件工具改走 py 脚本、44 个脚本污染全局数据目录」。
- **S-153**：截图兜底目录（`~/wishful-claw/image`）不在沙箱允许集里 ⇒ **agent 读不回自己刚截的图**；且该目录名不带点、dev 与 prod 共用一份，破坏「开发只看开发、生产只看生产」⇒ 按方案 B 迁到数据根，按会话作用域分家。

### S-145：Read 读图 / 读视频

- **§一 读图**：`Read` 认图像扩展名，走 base64 image block + 文本说明（与截图工具同形态），**不新增独立工具**；顺带修「Anthropic 下 `tool_result` 里的 image 块被静默丢弃」（不修则新功能在 Anthropic 下无效，且截图工具也瞎）。约束：单图 ≤ 5 MB、单次 ≤ 4 张、非 vision 模型降级为路径文本、DB 侧剥离 base64（只存 `[image: path w×h mediaType]` 占位）。
- **§六 读视频**：**渲染端抽帧、不引三方依赖**（需要嵌入三方则需求搁置）。落地后老大实测踩到断链 —— worker 发反向请求 `vision/extract-video-frames` 没人接：① 主进程 `rendererMethods` 白名单**漏登记**这条（请求落进主进程 handler 表当场回错，渲染端实现成死代码）；② 超时口径不匹配（主进程 30s / 渲染端 120s）⇒ 补白名单 + 新增长任务档 150s。改的是主进程，**重测要重启 dev 实例**。

### S-148：预览器文案 i18n + PDF/HTML 交内置浏览器

根因：`<Document>` 未传 `error` 用了 react-pdf 默认英文；预览器 13 个 viewer 文案整体未 i18n。修法顺带把 PDF / HTML 这类**直接交内置浏览器预览**（不再自绘），去掉 `?v=<hash>` 那类缓存参数。

### S-149 / S-150：渲染降级与滚动回跳

- **S-149**：帧间隔按**池压力自适应**，把主线程让给交互。**根治边界**：部分电脑性能就在那里，做不到 100% 不降级（见 `S-149.md` §七.4）。
- **S-150**：高度回收**加冷却锁**（240ms）—— 回收了不能立即又回收。收尾补 `trackContentBottom`（内容底单调下界），滤掉虚拟化下尾行挂载/卸载造成的「骤降回升」噪声；套件 25 → 38 断言。
- 两项一开始被当成一件报，老大 12:28 明确「**这是两个需求哈，分开登记**」：S-149 是**渲染吞吐**（主线程被占满 ⇒ 假死），S-150 是**滚动跟随**（高度回收 ⇒ 回跳）。

### S-151 → S-155：文件搜索

- **S-151 三次收窄**：① 引导用户自装 Everything（不内置）→ ② 探不到就不支持文件模式 → ③ **09-28 定案「Windows 接管式」**（`spawn -search "<词>"`，结果交给 Everything 自己的窗口）。
- **S-155 推翻 ③**（09-28 16:55）：「查询可以用我们自己来呈现结果，主要是原生 everything 丑」⇒ 走 `es.exe` 取数、**我们自渲染**。原 4 条口径里「es.exe 怎么来」由「引导用户下载」二次拍板改为**内置进安装包**，另加「Everything 没在跑时自动拉起」。
- **关键技术事实**：`es.exe` stdout 走 **GBK**（不可用）⇒ 必须 `-export-json <f> -utf8-bom` 落文件再读；字段真名 `filename`（全路径）/ `size` / `date_modified`（FILETIME）/ `extension`，**`-name -path-column` 不拆 name·path**（JS 里切）；单次 ~143 ms ⇒ 防抖 250ms + 串行队列；参数表**没有**「启动 Everything」的开关 ⇒ 依赖本体在跑；`-date-format 1` 直出 ISO-8601、`-no-result-error` 区分空结果与出错。
- **实测暴露的修正**：拼查询词原本「关键词 + 分类」**恒 0 条**（本机空格＝整文件名匹配）⇒ 改「拆词 + 逐词 `<>` 分组 + 全程无空格」；「搜索文件」不再单独占一行、改成应用砖（**未搜到东西时才排首位**）；目录图标不取系统图（改 lucide `<Folder />`）；视频白名单剔掉 `ts`。
- **独立窗**：文件搜索走独立窗（常规窗，带系统标题栏），原窗只搜应用；开窗时把应用窗已输入的词带过去。

### S-152：微信渠道「正在输入」

- 起因是排查「微信长时间收不到推送」——**那条线当场结掉、不立项**：iLink Bot 协议层无主动推送通道，`context_token` 只能由用户入站消息刷新，提醒本身也要 token（发不出去）。
- 协议定案（对齐生产实现，只取协议知识、实现不参考）：`getconfig` 换 `typing_ticket` → `sendtyping`（**不能直接调**）。微信**没有**流式边界（未实现 `supportsStreaming`）⇒ 改用主进程内两个现成点。**不做续发**（消失就消失）。

### S-154：终端选项卡随进程结束关闭

agent 的 Terminal 工具 `stop` → `pty.kill()` → `terminal:exit`，渲染端此前**只把 tab 标成 `exited`/`error`、不删 tab** ⇒ 死 tab 越堆越多。只收 `local-agent`（用户自开的 `local`、SSH 观察窗 `ssh-agent` 保持现状）；**陷阱**：空停靠栏会自动新建终端 ⇒ 删最后一个 tab 时要连停靠栏一起收。
