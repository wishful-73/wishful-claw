# S-311 · 子 agent 运行期间进度恒为 0 —— 进度数据没有实时通道

> 状态：**✅ 已实施，门禁待补（runtime sln 被运行中的 worker 锁定），待真机验收**
> 登记：2026-11-04 14:53
> 实施：2026-11-04（见文末「§实施记录」）
> 来源：dev 实例 2026-11-04 14:53 的实测报告（老大转达）
> 关联：S-308（子 agent 停止）、S-309（§2.3「看不出在思考还是卡住」，本条是它的具体落点）

## 一、现象

子 agent 正在执行工具，`SubAgentStatus` 报的却是 `Tool calls: 0 / Iterations: 0`。

dev 的取证过程值得记下来，因为它**推翻了自己上一轮的判断**：

- 上一轮 dev 看到两个 background 子 agent 全程 `0 calls`，判断「它们还没真正开始执行，所以停掉的是没启动的实例」；
- 本轮 dev 从系统进程表确认：14:50 那一轮有一个 `Start-Sleep -Seconds 4` 的 shell（PID 25912）**正在运行**，而同一时刻 `SubAgentStatus` 仍然报 0。

⇒ 子 agent 在干活，进度数据是假的。上轮被停掉的两个子 agent 很可能也在实际执行中。

## 二、根因：进度只在整轮跑完之后写一次

`BackgroundSubAgentRegistry.UpdateProgress` 全仓只有一个调用点，`SubAgentExecutor.Background.cs:64`：

```csharp
await AgentLoop.ExecuteLoopAsync(childParameters, childState, context);

// Update progress before completing
BackgroundSubAgentRegistry.UpdateProgress(
    toolCallId, collector.ToolCallCount, collector.Iterations,
    BuildToolCallEntries(collector.ToolCallSummaries));
```

它**在 `await ExecuteLoopAsync` 之后** —— 要等整个循环跑完才执行。紧接着 `Complete()` 又用同样的数据覆盖一遍。所以运行期间恒为 `0/0`，跑完才有真实数字。

**这不是算错了，是这条数据没有实时通道。** 数据本身一直是准的：`SubAgentRunCollector` 通过 `childState.EventObserver` 实时收到每一个事件，`_toolCallCount` / `_iterations` / `_toolCallSummaries` 都在逐条更新 —— 只是没人把这些值往注册表里送。

## 三、为什么渲染层看着是准的

`SubAgentRunCollector.ForwardEvent` 会把 `sub_agent_tool_call` / `sub_agent_iteration` 实时推给渲染层，聊天窗的卡片因此能实时显示步骤。

⇒ **同一个事实走了两条路：UI 那条是实时的，注册表那条是滞后的。** `SubAgentStatus` 工具（给 agent 自己用的）读的是注册表，所以它给不出进度。

## 四、实施

### 4.1 `SubAgentRunCollector`

新增 `Action? ProgressChanged` 回调，在三个低频事件之后各触发一次：

| 事件 | 为什么挂它 |
|---|---|
| `tool_call_start` | 工具开始 → 次数 +1，首个工具出现就该让外界知道 |
| `tool_call_result` | 工具结束 → 状态从 running 变 completed/error |
| `iteration_start` | 轮次推进 → 长时间无工具的轮次也有心跳 |

**不挂 `text_delta` / `thinking_delta`** —— 那是每帧级别的热路径，挂上去等于给每个 token 做一次字典写入。

### 4.2 `SubAgentExecutor.CreateCollector`

`CreateCollector` 是前台 / 后台 / goal 三条线的统一创建点，回调挂在这里，一处覆盖全部：

```csharp
collector.ProgressChanged = () => BackgroundSubAgentRegistry.UpdateProgress(
    toolCallId, collector.ToolCallCount, collector.Iterations,
    BuildToolCallEntries(collector.ToolCallSummaries));
```

`_records` 是 `ConcurrentDictionary`，跨线程写入安全；`ObserveAsync` 与回调同线程，不引入竞态。闭包捕获 collector，生命周期随子 agent 任务一起结束，不泄漏。

### 4.3 保留的原有调用

`Background.cs:64` 那次 `UpdateProgress` 没删 —— 它是「循环已结束、最终值」的一次确认，跟实时通道不冲突（同一份数据，后者不会倒退）。

## 五、验收点

1. 派一个会跑多个工具的后台子 agent，运行期间反复查 `SubAgentStatus` → `Tool calls` 应随工具推进增长，不再是 0；
2. 子 agent 卡住不动时 → 数字停住但保持最后一次的值（不是回到 0）；
3. 结束后 → 最终值与卡片上显示的次数一致；
4. 高频文本流式输出时 → 不因为进度上报产生额外卡顿（没挂 `text_delta`）。
