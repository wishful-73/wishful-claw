## 一、原话 / 来源

老大 2026-10-09 13:52：

> 「38 迭代再登记一个小 bug 或者说叫优化吧，就是我们的子 agent 本身是可以后台执行 也可以主会话等待执行的。后台执行的结束后会主动唤起主会话并输出结果。但是在测试过程中主会话 agent 好像不知道这个规则，然后在自己死等通过命令让自己强制活着等待这些」

## 二、现象（拆三层）

1. **规则真实存在**：子 Agent 有两种模式 —— `background=false`（主会话等待）/ `background=true`（后台执行，结束时**主动唤起主会话**并送达报告）。
2. **主 Agent 不知道**：模型派完后台子 Agent 后，**不结束自己的回合**，而是用长 `timeout` / `sleep` 轮询把自己强制挂住等结果。
3. **纯空转**：后台完成是**新开一轮 run** 送达的（见 §三），主 run 活着期间的等待**没有任何意义**。

### 3.2 `Task` 工具描述（模型**调用之前**唯一必读的规则文本）

C# `src/runtime/WishfulClaw.Agent/Tools/TaskTool.cs`：

```text

56  It runs in its own session, inherits the parent's tools, and only returns its final answer.
...
74  Usage notes:
75  - Delegate complex tasks immediately; do simple 1-3 step tasks yourself.
76  - Sub-agents are stateless and do not see this conversation — write self-contained prompts with all needed context.
77  - Set background=true to run without blocking; check progress with SubAgentStatus/SubAgentDetail.
```

`background` 参数（`:108-112`）：

```text
108  "background": { "type": "boolean", "default": false,
111    "description": "If true, runs in the background and returns a sub-agent ID immediately; check progress with SubAgentStatus. If false (default), waits for completion."
```

⇒ **确认缺失**：`TaskTool.cs` 全段**没有**「后台不要等 / 完成会自动通知」；`:77` 那句只教「用 `SubAgentStatus` 查进度」，**恰好把模型推向轮询**。

> 渲染端镜像 `sub-agents/create-tool.ts:55-87` 描述更短、**连 `background` 参数都没有**，`execute` 只返 `nativeOnlyTaskResult()`（`:49-53`）⇒ 不发给模型，**不是修点**。

### 3.3 「会通知你」唯一出处在**调用之后**

`src/runtime/WishfulClaw.Agent/SubAgentExecutor.Background.cs:204-209`（工具**返回值**占位符）：

```text
208  The sub-agent is running in the background. You can continue working.
209  Use SubAgentStatus to check its progress. When it completes, you will be notified automatically.
```

⇒ 模型**已经用 `background=true` 调完**才看到这句，**治不了「调之前就死等」的根**。

### 3.4 唤醒链路（规则真实存在，且确实会唤醒）

- **C# 侧**（`SubAgentExecutor.Background.cs`）：`:48-56` fire-and-forget `Task.Run` → `:86-92` emit `sub_agent_end` → `:100-101` + `:216-255` 构造 `[Background Sub-Agent Completed]…Report:` 通知 → `:106-115` 先尝试 `parentState.EnqueueMessages(...)` 注入父 run 队列，**失败（父 run 已 finalize）则 `:122-130` 缓冲**进 `BackgroundSubAgentNotifications`。
- **渲染端**：`sub_agent_end`（`stores/chat-store/index.ts:852-861`，仅 `isBackground` 时 emit → 另有 `sub-agent-native-ui.ts:276-281`）→ 事件总线 `sub-agents/background-events.ts:20-35` → `hooks/use-background-subagent-wakeup.ts:156-179` 订阅 → `:44-70` 经 IPC `agent:drain-sub-agent-notifications` 取回缓冲 → `:103-123` `chatStore.sendMessage({role:'user', content})` **重开主 run**。
- 唤醒消息尾注：`sub-agents/background-wake-message.ts:22` `WAKE_TRAILER = '后台子 agent 已完成，请基于上面的报告继续处理…'`；Worker 侧 drain 入口 `AgentRuntimeTools.cs:167-184`。

⇒ **主 Agent 是被「新的一轮 user 消息重新启动 run」唤醒的，不是同 run 内被 push**。所以主 run 活着期间自己 sleep/轮询 = **纯空转**，且拖长回合、占住会话。
