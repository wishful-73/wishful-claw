# S-107 请求上下文上限纳入全局设置，会话默认继承

## 需求（2026-09-20 老大）

> 「请求上下文上限 跟压缩阈值一样 在全局页面有个设置，会话上默认继承」

## 现状（2026-09-20 实读）

| 事实 | 位置 |
|---|---|
| 全局设置页「上下文压缩」节只有两项：启用开关 `contextCompressionEnabled` + 触发比例滑条 `contextCompressionThreshold`（30~90%） | `src/renderer/src/components/settings/RuntimePanel.tsx:274-318` |
| **全局没有「请求上下文上限」这一项**，设置存储里也无对应字段 | 同上；`stores/settings-store.ts` |
| 会话级上限只存在于输入区的 `ContextRing` 弹出面板（滑条 + 「Model max / 具体值」两态） | `components/chat/InputArea/context-ring.tsx:363-401` |
| 落库字段 `Session.contextCapTokens` + `contextCapModelId` | `stores/chat-store/types.ts:84`；`db-helpers.ts:373` |
| 生效口径：**上限只在它被设置时的那个模型上有效**，换模型即作废（返回 0） | `resolveSessionContextCapTokens`（`lib/agent/context-compression-config.ts:139-148`） |
| 运行期盖章：`sendMessage` 把 `contextCapTokens` 写进 `agent/run` run param；Worker `ApplyContextCap` 把 provider 的 `contextLength` 夹到该值 | `stores/chat-store/index.ts:418-423`；`AgentLoop.Helpers.cs:58-88` |

对照「压缩阈值」已具备的范式（`resolveSessionCompressionThreshold`：会话设过用会话的、否则用全局；`0` = 跟随全局 + 面板里带「跟随全局」还原出口），**全局上限这一整套是缺的**。

## 裁定（2026-09-22 老大：「根据你的推荐来」）

| # | 争议点 | 裁定 |
|:--:|---|---|
| 1 | 全局值量纲 | **绝对 token 数**。`0` = 不限制 / 跟随模型窗口（与会话级 `0` 哨兵同构） |
| 2 | 会话默认继承怎么落地 | **沿用 `contextCapTokens` + `0` 哨兵**，不新增字段；解析出口统一走新增的 `resolveEffectiveContextCapTokens(session, global)` |
| 3 | 与 S-84「换模型作废」共存 | 换模型作废**只约束会话级**；**全局值不绑模型** |
| 4 | 是否保留会话级覆盖 | **保留** |

追加约束：`context-ring` 面板的「跟随全局」按钮此前只还原压缩阈值，现在要**同时还原压缩阈值与上下文上限**。

## 实施（`df857315`，12 files，+275/−29，未推送）

- 全局控件落在设置页「上下文压缩」节压缩阈值滑条之后（`RuntimePanel.tsx`）。

## 调档（2026-09-22 老大：档位里不要 0、不要「不限制」）

> 「档位没有 0 没有不限制，我搞不懂你非要弄不限制干嘛」
> 「默认是 1M，如果模型不足 1M 以模型为准，不过这个逻辑跟全局设置这里没关系」

第一版的数字输入框与 `0 = 不限制` 被否：设了「不限制」就没有「省钱」这个初衷（老大要做这个功能的动机就是**上下文越大越贵**），手输入的数字也没法横向比较 —— 上一轮那个「前后端两套分母」的悬案正是从手输的 384000 冒出来的。改成**固定档位滑条**，白名单 `200K / 400K / 800K / 1M`，无 0、无不限制。

## 实施（`466ca6a4`，7 files，+110/−38，未推送）

- `GLOBAL_CONTEXT_CAP_STAGES` 取代量程常量；`DEFAULT_GLOBAL_CONTEXT_CAP_TOKENS` 由 `0` 改 **1M** —— 它顶替的就是原来那个 0 的语义位，对当前所有模型（窗口 ≤ 1M）等价于旧行为。
- `clampGlobalContextCapTokens` 语义从「夹到量程」改成「**吸附到档位**」：档位是白名单不是范围，老配置的手输值（384000）迁到最近的 400K；非正数（含旧的 0 哨兵）与非法值**回落默认档 1M，不是吸附到最低档** —— 吸到 200K 等于把老窗口静默砍一半。
- 新增 `globalContextCapStageIndex`：滑杆吃档位**下标**，token 数与下标的换算只此一个入口，组件里不再算第二遍。
